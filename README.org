#+TITLE: Autolith
#+SUBTITLE: A terminal agent you can inspect and change in Common Lisp
#+STARTUP: content

Autolith, or AL, is a terminal agent inside a live Common Lisp image. It owns
its model loop, tools, conversations, local state, checkpoints, and recovery.
It talks directly to configured model services instead of launching a vendor
agent CLI. Use prose for open-ended work. Start an input with an opening
parenthesis for an exact local Lisp action.

Autolith is not a security sandbox. Code it runs has your user privileges.

* Start

Nix and source checkouts support Linux x86-64 and native macOS arm64. Packaged
binary releases support Linux x86-64.

Nix supplies the complete runtime:

#+BEGIN_SRC sh
nix run github:luciusmagn/autolith
#+END_SRC

The conventional Linux installer is shorter. Inspect the
[[https://sh.lambda-symbolics.com/autolith][installer script]] before piping it into a shell.

#+BEGIN_SRC sh
curl -fsSL https://sh.lambda-symbolics.com/autolith | sh
#+END_SRC

Then authenticate and start:

#+BEGIN_SRC sh
autolith --auth
autolith
#+END_SRC

The [[file:docs/guide.org][guide]] covers source setup, providers, permissions, updates, and the
first machine-local image build.

* See it work

** One prompt, prose and Lisp

Ask in prose when interpretation helps. Enter a form when you need an exact
local action or a computed prompt.

#+BEGIN_SRC lisp
(describe 'application)
(fs.list :path ".")
(prompt (read-file "review-notes.org"))
#+END_SRC

The form runs in the active image without a model rewriting it. Registered
operations still keep their normal authority and approval rules.

** Inspect the machine at the right boundary

#+BEGIN_SRC lisp
(lisp.eval :form "(+ 20 22)" :repl "scratch")
(self.inspect :symbol "APPLICATION")
(self.status)
#+END_SRC

=lisp.*= uses named, heap-isolated SBCL workers. =self.*= inspects or changes
the active Autolith image. Durable live changes have private replay history.
A separate pristine image remains available for recovery.

** Steer a running child

Ask Autolith to delegate work, then keep working while the children run. If one
visible child is named =test-review=, this form adds exact FIFO guidance:

#+BEGIN_SRC lisp
(prompt :to 'test-review
        "Run the focused tests and report only failures.")
#+END_SRC

The child must already be running. Its next useful verbal response returns to
the primary terminal.

** Update the running packaged release

#+BEGIN_SRC lisp
(update)
#+END_SRC

For a selected binary release, this performs a fresh check and requests
an attended, verified launcher update when a newer release exists. Source and
Nix starts only explain their external update path.

* What makes Autolith different

** Lisp-first control

- Prose, callable commands, tools, and explicit Common Lisp share one input
  surface.
- Exact local forms can compute prompts or return results without model
  interpretation.
- Matching SBCL source and live image state are available for inspection.

** Responsive terminal work

- Keep editing and queue more work while a response or tool is running.
- Use multiline input, completion, image attachments, readable transcripts,
  and ordinary scrollback.
- Steer bounded child jobs and collect their results without blocking the
  primary session.

** Durable state and recovery

- Conversations use append-only readable files. Memories and workspace
  agendas remain explicit.
- Accepted input survives active-image crashes in a conversation-scoped vault.
  It is never submitted automatically.
- Checkpoints, private mutation commits, generations, and a pristine recovery
  image keep live work reconstructible.

** Extensions with visible authority

- Search, file, shell, resource, Lisp-worker, and self operations have distinct
  boundaries.
- Native Skills and MCP add request-local instructions and external
  capabilities.
- Command approval modes and =--immutable= startup make authority choices
  explicit.

* Development

Read [[file:AGENTS.md][AGENTS.md]] before editing. The [[file:docs/guide.org][guide]] documents user-visible
behavior, and the [[file:docs/architecture.org][architecture note]] maps source files to runtime
responsibilities.

Nix users can enter the locked development environment without a separate host
SBCL or Quicklisp installation:

#+BEGIN_SRC sh
nix develop
nix flake check
#+END_SRC

The development shell supplies the pinned SBCL, matching source, Lisp systems,
native libraries, and sandbox helper. It does not install private baseline
images. =./script/check= inside the shell still requires the pristine recovery
image previously created by =./script/bootstrap=.

Source development additionally needs Quicklisp, Rust with Cargo, a C compiler,
CMake, =pkg-config=, and a host SBCL when the pinned runtime must be built from
source. Materialize the locked environment and baseline images with
=./script/bootstrap=.
