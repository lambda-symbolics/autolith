#+TITLE: Parent-Agent Protocol
#+STARTUP: content

* Status and scope

This document specifies the private supervisor-agent boundary under development.
The wire schemas are =proto/autolith/common/v1/value.proto= and
=proto/autolith/parent/v1/protocol.proto=. Generated bindings, bounded framing,
defensive decoding, portable value conversion, and startup negotiation are
implemented as standalone libraries. The optional
=autolith-supervisor/protocol= system loads without the agent system.

Ordinary =bin/autolith= launches use =script/parent.lisp --cli= and this
protocol. The trusted parent owns terminal input and rendering, provider
credentials and callbacks, provider transport, approvals, and private storage.
Agent initialization and private mutation replay run in the restricted child.
See [[file:architecture.org][Architecture]] for the current implementation. The sections below also
specify protocol requirements beyond the implemented services.

Use Protobuf for typed messages. Use the common data types in later public
schemas, but define remote control as a separate interface with its own
identity, authentication, authorization, and session access rules. The private
connection is not a public network endpoint. Protobuf does not supply isolation
or authorization. Generated Lisp schema packages are permitted.

Version 1 covers fresh-image session resume, model transport, session records,
memories, papercuts, agendas, access requests, and controlled restart. Exact-heap
transfer and private image publication are outside this version. Do not expose
a host execution, host Lisp evaluation, or arbitrary private-file operation.

* Ownership

The parent owns terminal input and rendering, approvals, provider credentials,
provider transport and stream parsing, private configuration, private storage,
session event ordering, policy, and sandbox lifecycle. It loads focused service
libraries independently of the agent system. It never evaluates agent-supplied
Lisp or loads private agent mutations into its own image.

The agent owns reasoning, context construction, tool schemas and execution,
self-modification, and workers. Tools use approved resources directly inside
the sandbox. Workers and descendants inherit the restrictions. The agent
cannot grant itself access by changing code, registering a tool, or editing
configuration. Parent operations validate authority independently.

The parent reads private files and supplies selected data through this API.
Credentials never cross the connection. A model profile is a parent-owned
identifier, not a credential path, endpoint URL, or arbitrary header set.
Configuration sent at startup contains only approved portable values. Keep
parent configuration separate from Lisp configuration intended for the agent;
agent initialization code executes only inside the restricted agent process.

Once the parent supplies private content, the agent can retain it in its heap,
files, or checkpoints. Storage isolation does not make supplied content secret
from the agent. Revoking access cannot remove data already read.

* Framing and validation

Use a private bidirectional byte connection established by the parent. Use
inherited pipes or an OS adapter for a private local connection. Do not discover
the parent through an unauthenticated public listening socket. Do not inherit
unrelated descriptors or provider credentials. Keep stdout and stderr separate
from protocol traffic; capture them as untrusted diagnostic output.
Sanitize terminal control sequences in agent output. Render approvals in a
parent-owned region with trusted grant details; agent text must not impersonate
that interface. Rate-limit output, storage writes, and model requests, and bound
queued bytes. A blocked consumer must cause backpressure, not unlimited buffering.

Each frame is a four-byte unsigned big-endian length followed by exactly one
serialized =Envelope=. The length excludes the prefix. Reject zero-length
frames. The bootstrap frame limit is 8 MiB. =Welcome.limits= may lower that
limit, never raise it. Limit value depth to 32 and total decoded collection
entries per frame to 65536, or lower negotiated limits. Limit in-flight requests
to 64 per direction by default. Bounds are inclusive and must be positive.

The decoder counts every wire field and packed element against the 65536-entry
work budget, including unknown and overwritten fields. It limits wire nesting
to 128 messages. The separate logical =Value= depth limit excludes envelope,
list, and map wrappers. Unknown length-delimited payloads are opaque bytes.

Check lengths before allocation. Limit all nested Protobuf messages, repeated
fields, decoded bytes, and parser work, not only =Value= trees. Reject malformed
varints, invalid UTF-8, truncated frames, excessive nesting, and oversized
length-delimited fields during decoding. Close the connection on malformed
framing or a violated hard decode limit; terminate the child process tree.
Do not resume parsing at an arbitrary byte offset.

Every envelope has major version 1, the parent-assigned instance ID, and a
positive message ID. Each sender starts its IDs at 1 and increments by one.
=reply_to= identifies the peer's request on this connection. Responses and
stream events must identify an outstanding request. Requests have no
=reply_to=. Empty or unsupported envelope bodies cannot authorize operations.
Reject wrong directions, unknown enum values, missing semantic fields, and
unsupported operations with =Failure= when the connection is still valid.
An instance mismatch or message ID discontinuity closes the connection.

Protobuf accepts some repeated singular fields and multiple =oneof= members by
merging or keeping a later value. Validate the decoded result; do not rely on
field order or duplicate fields as an authorization check. Unknown fields may
be skipped for compatible additions, but never confer authority. Empty
=Value.kind= is invalid. Reject duplicate =ValueMap= keys, non-finite numbers,
and unknown null enum values. Map keys remain strings; never intern them.

* Startup and feature negotiation

The parent assigns a fresh instance ID before launch and supplies it through
the launch adapter. It retains the session ID across restarts.

1. Agent sends =Hello= with supported feature names.
2. Parent sends =Welcome= in reply. Include session ID, effective policy
   revision, active grants, limits, approved configuration, and resume records.
3. Agent sends =Ready= in reply to =Welcome= after initialization.
4. Parent may send =TurnStart= after =Ready=.

The handshake is the sole exception to the request/reply shape: =Welcome=
terminates =Hello= while opening a handshake obligation of its own. =Ready=
terminates that obligation. Each =reply_to= names the immediately preceding
handshake message. A handshake failure terminates startup and stops the child.

The features are =session.v1=, =model.v1=, =records.v1=, =record-scopes-v1=,
=knowledge.v1=, and =access.v1=. =record-scopes-v1= requires =records.v1=.
=session.v1= is mandatory; the others are enabled only when offered by the agent
and selected by the parent. Reject calls to unselected services. Lifecycle,
output, and structured errors are always available. Startup must finish within
a parent-configured deadline, default 30 seconds, or the parent stops the child.
A major-version mismatch fails startup; optional additions use feature names.

* Structured knowledge and scoped memory

The optional =knowledge.v1= service uses the shared knowledge engine in the
parent. The agent sends bounded portable data in =KnowledgeRequest= and receives
=KnowledgeResponse= or a fixed =Failure= code. Neither side reads Lisp forms
from request fields. The service does not accept store paths or executable code.
The parent supplies the store context, workspace, evidence policy, and admission
callback when it creates the service.

=RecordRequest.scope= requires =record-scopes-v1=. Omit it for the original
=records.v1= workspace behavior. Explicit scopes select memory services that the
parent configured. Global memory requires a separate parent grant. Cursors,
record revisions, and collection guards are scope-bound. An operation ID binds
the full request, including its scope. A scope move requires both configured
services to share the same trusted store context. The returned item can then be
edited through its new scope.

=KnowledgeRequest.scope= selects workspace or global knowledge. An unspecified
scope means workspace. The parent must enable global access. Workspace reads
include global facts only with that permission. The parent projects the complete
graph before evaluation, rendering, admission checks, and writes. Another
workspace's facts cannot satisfy a contract or a rule in this scope.

| Operation | Fields and result |
|-----------+-------------------|
| =READ= | =view= names =facts=, =predicates=, =rules=, =methods=, =contracts=, =procedures=, =changes=, or =claim/ID=. Returns text and an exact graph revision. Only =facts= accepts =query= and =limit=. |
| =EDIT= | =view= is =facts=. =fields.operations= contains 1 to 16 public edit maps. Requires an issued =expected_revision= and a stable =operation_id=. Returns text and a new revision. |
| =CHECK= | =fields= contains =tool= and an =arguments= map. Returns =none=true=, a refusal, or an opaque handle with an optional passive-mode refusal. |
| =RECORD= | =fields= contains a parent-issued =handle= and successful tool-result text in =result=. To release a failed or abandoned call, send =outcome="abandoned"= and omit =result=. Requires a stable =operation_id=. Returns claim IDs and mapping errors. |
| =CONTEXT= | Workspace-only fields are =query=, =turn=, and =active=. Returns memory and fact lines, change text, and stale, unverified, and change counts. |
| =EXPAND= | Workspace-only fields are =task= and optional =depth_limit= and =node_limit=. Returns plan steps, status, and details. |
| =READ= with =view= =plan= | Workspace-only =fields.action= selects =prepare=, =render=, =changes=, or =delivered=. The parent checks bounded step requirements and verification patterns against its authorized graph. The agent stores the plan. |

=READ=, =CHECK=, =CONTEXT=, and =EXPAND= use an empty operation ID. Non-view
operations use an empty view and no revision guard. Unknown fields and operations
fail. Public edits cover predicate definitions, fact assertion and retraction,
rule proposals, method definitions, and contract proposals. Recipe resources are
not part of this checkout's interface.

The parent checks the full authorized graph against an issued observation under
the store lock. It stages the complete edit batch and its receipt, then appends
both together. A failed batch publishes neither data nor a receipt. A repeated
session and operation ID with the same canonical request returns the saved
response before checking the guard or handle. This also works after reopening
the service. Reusing that ID for different data fails.

Only parent policy can admit a rule or contract. The callback receives the exact
kind, scope, ID, version, and proposed data. A child request cannot admit its own
proposal. File evidence must pass parent root and quote checks. User evidence
must match parent input history. URL evidence is an observation only when a
trusted parent retrieval callback supplies checked evidence. Other URLs support
proposals.

The production startup configuration supplies =knowledge_mode= as =active=,
=passive=, or =off=. Active mode checks requirements before a tool call and
records successful results. Passive mode records results without refusing the
call. Off mode bypasses knowledge capture. Parent-backed tools never reopen a
local private knowledge store. The parent also checks its own mode before it
includes facts in turn context. A child cannot enable parent-disabled context.

Plan completion receipts are opaque parent-issued tokens. The parent binds each
token to the workspace, global-access grant, step identity and text,
requirements, and verification pattern. The issuer session is audit metadata.
It stores receipt state separately from viewer snapshots and checks the binding after a service reopen. Plan requests do not change the
knowledge graph.

Plan fields include =steps= and =canonical=. For =prepare=, send new steps in
model input form and the prior canonical steps in =previous=. The parent returns
normalized steps, rendered text, and change lines in =fields=, without a graph
revision. For the other actions, send canonical typed terms and opaque receipt
tokens. =changes= supplies active-mode advice; =delivered= records the snapshot
shown by a normal plan tool. The agent caches advice for one conversation turn.
Explicit plan tools check current facts in all three knowledge modes.

A plan has at most 32 steps and each step has at most 32 required patterns.
Plan text is at most 500 characters per step; an explanation is at most 4096
characters. Rendered plan text and each change line are at most 131072 characters.
The parent keeps at most 128 receipt tokens per workspace, with current tokens
first. The private receipt snapshot permits 32 workspaces, 1024 tokens, and 8 MiB
per store. Unknown, expired, changed-step, and cross-workspace tokens fail with
=permission-denied=. A cold service reads the same private receipt snapshot.

Each knowledge request and response is at most 1 MiB and must fit the negotiated
frame limit. Record and knowledge traffic share a limit of 64 requests and 8 MiB
per second. Fact views return at most 50 results. Query text is at most 4096
characters; rendered content and recorded result text are at most 262144
characters. Issued graph observations and outstanding contract handles each have
64 entries and a 4 MiB budget. A committed =RECORD= consumes its handle; its
durable receipt permits retries, including after reopening the service. An
abandoned outcome records no claims or predictions. The agent releases handles
on failed results and nonlocal exits. Retraction requires the exact claim owner
scope, including when the request identifies a support instead of its claim.
Session and operation IDs are at most 256
characters. Context turn numbers range from 0 to 1000000000. Expansion depth is
at most 8, and the node limit ranges from 1 to 1000.

* Messages and completion

| Request | Sender | Reply and terminal outcome |
|---------+--------+----------------------------|
| Hello | Agent | Welcome or Failure |
| Welcome | Parent | Ready or Failure |
| TurnStart | Parent | TurnFinish or Failure |
| TurnCancel | Parent | No direct reply; the original turn terminates |
| SessionRead | Agent | SessionPage or Failure |
| SessionAppend | Agent | SessionAck or Failure |
| ModelStart | Agent | Ordered ModelEvent stream |
| CancelRequest | Agent | CancelAck or Failure |
| RecordRequest | Agent | RecordResponse or Failure |
| AccessRequest | Agent | AccessDecision stream or Failure |
| PrepareStop | Parent | ReadyToStop or deadline termination |
| Output | Agent | No reply; bounded transient display only |

Only one turn may run at a time. Turn IDs are parent-assigned, nonempty, and
unique within the session. =TurnCancel= names the active turn. Repeated
cancellation is harmless; cancelling an inactive turn has no effect. Output
messages are unsolicited; =Output= is not a durable assistant message.

For model and access streams, all events reply to the original request.
=ModelEvent.index= starts at 1 and increments by one. A model stream ends with
exactly one =complete= or =failed= event. A rejected =ModelStart= may instead
receive a direct =Failure= before the stream begins. Complete contains the
assembled message, or ordered output items with =model-items-v1=, plus stop
reason and available usage. Token counts are absent when unknown, not reported
as zero. Delta events are provisional; execute tools only from a validated
complete result.

=CancelRequest.request_id= refers to an outstanding cancellable model or access
request from this agent. =CancelAck= acknowledges cancellation delivery; the
target request still needs a terminal outcome. For an active target, serialize
completion against cancellation: an already committed terminal outcome wins;
otherwise end it with =CANCELLED=. An unknown target is =INVALID_REQUEST=.
Retain terminal request IDs for the connection so repeated cancellation can
return =already_terminal=true=. Agent termination cancels its provider calls.

Access state =PENDING_APPROVAL= is nonterminal. States
=APPROVED_PENDING_RESTART=, =DENIED=, =ACTIVE=, =FAILED=, and =EXPIRED= are
terminal for the request on its current connection. After a restart, the parent
reports the active policy in =Welcome=. Cancellation before policy commit
prevents the grant. After commit, cancellation does not revoke policy. Report
the committed state and restart. The parent records the final disposition even
if the old instance never receives it.

A =Failure= contains a stable code and a redacted explanation. =retryable= is
advice, not permission to repeat an operation with possible external effects.
A storage operation that committed before reply loss stays committed.

* Session durability and restart

The parent persists user input before sending =TurnStart=. =input_sequence=
identifies that record, or the continuation record selected by the parent.
The parent orders records with increasing positive sequence numbers. Sequence
zero in =SessionAppend= means unassigned. =SessionAck= means the record and its
deduplication identity are durable under the storage backend's commit contract.

Agent records require a nonempty session-scoped =event_id= and active turn ID.
Agent appends may use =ASSISTANT_MESSAGE=, =TOOL_STARTED=, =TOOL_FINISHED=, or
=NOTE=; only the parent creates =USER_INPUT= and =TURN_OUTCOME=. An assistant
payload is a map with =text=. A tool-start payload has =call_id=, =name=, and
=arguments=; a tool-finish payload has =call_id=, =result=, and =is_error=.
A note payload has =text=. Call IDs are unique per session; tool finishes must
match an acknowledged start. Reject unexpected fields and invalid field types.
Parent-generated user-input payloads have =text=. Turn outcomes have =outcome=
and may have =reason=. On append, origin must be =ORIGIN_UNSPECIFIED=; reject
agent attempts to set it. The parent sets returned =SessionRecord.origin= to
=PARENT= or =AGENT=. Treat only parent-origin records as parent statements;
text inside a note cannot assert an approval.

Before executing a tool with possible effects, obtain the durable tool-start
acknowledgement. Persist its result before reporting completion. Duplicate
event IDs with identical contents return the original acknowledgement;
conflicting contents fail. Deduplication persists across agent restarts. Check
existing event identity before active-turn validation, which applies only to
new events. Compare the submitted record without parent-assigned metadata.
A start without a finish after termination means interrupted, effects unknown.
Do not retry it automatically. No exactly-once external execution is claimed.

=SessionRead= reads only the attached session, after the supplied sequence,
in ascending order. Limits range from 1 to 256, subject to frame limits; a page
may be shorter to fit. =high_water_sequence= is the snapshot maximum, and
=has_more= describes that snapshot. Continue after the last returned sequence.
If one record cannot fit, return =RESOURCE_LIMIT= rather than an empty loop.
Startup resume uses the same page rules. Fetch further context as needed; the
parent may supply persisted compaction notes instead of the full history.

The parent persists model stream events before forwarding them, separately
from the compact session records. It does not replay unfinished model requests
after restart. Mark them interrupted. Continuation handles are opaque,
parent-issued, scoped to the session and profile, and persisted if required
for resumption. Reject unknown handles. The agent cannot inject raw hidden
provider state through a handle.

For restart, send =PrepareStop= with a grace interval measured by the parent
from send time. Stop accepting new work and effectful requests; permit session
reads, wrap-up notes, and results for acknowledged tool starts. The agent
flushes those records, then sends =ReadyToStop= with its last acknowledged
sequence. A wrap-up event must already be acknowledged. The parent may kill
the process tree at any point after its deadline, without a checkpoint or
cooperative reply. Retain the policy and durable session independently.

Stop and reap the old process tree before launching the new instance. Rebuild
the sandbox from the committed policy, then resume the same session from a
fresh image. A policy application failure is recorded and shown to the user;
never start with weaker enforcement without a separate explicit approval.
On connection loss, stop the agent tree, cancel its provider calls, and mark
unfinished work interrupted. Exact heap continuity is not required.

* Model service

** Projection and authority

Negotiate =model-items-v1= before using the ordered-item model service. With
this feature, =ModelStart.kind= must be =GENERATE= or =NATIVE_COMPACTION=,
=messages= must be empty, and the ordered history consists of =items= followed
by =ephemeral_items=. Without it, use the original message service and reject
the added model fields, including nonempty =ephemeral_items= and nonzero
=purpose=. Do not route a provider that needs opaque replay through the
original message service. The unpublished =model-items-v1= extension includes
both fields; advertising it means support for their validation and projection,
not only the earlier ordered-item fields. No separate feature token is needed.
For the item service, =ModelComplete.message= must be absent, even for an empty
result. The final =output_items= list is authoritative, not the display deltas.

The agent selects durable history =items=, request-local =ephemeral_items=,
the stable instruction prefix, and the request-local suffix. Preserve order
within each list. Map durable items to =wire-request.items= and instruction
texts to =prefix= and =suffix= in =cl-llm-provider-api=. For Anthropic, map
=ephemeral_items= to the typed =:ephemeral-items= library option. Apply the
history cache breakpoint to durable items before appending ephemeral items,
then append suffix text. Do not flatten ephemeral items into text or include
them in the durable cache prefix. For other families, append ephemeral items
to durable items before the existing family projection and suffix placement.
Apply the same transcript validation, size limits, and replay-handle authority
rules to both item lists. Request-local placement does not append items to the
durable session or grant additional handle authority.

The parent selects the actual model from =profile_id=. It applies the
provider's instruction placement and cache breakpoint rules without flattening
the prefix and suffix into history. Anchored context belongs in =items=;
volatile text belongs in =request_suffix=. A native compaction suffix contains
the compaction instructions.

=ModelStart.purpose= is a bounded logical setting, not provider cache control.
Omitted or =PURPOSE_UNSPECIFIED= preserves the existing =GENERATE= behavior;
it does not request a summary. =ORDINARY_SUMMARY= is valid only with
=kind= set to =GENERATE=. It requests tool-free ordinary summary generation,
equivalent to the existing =compaction-p t= projection. The agent supplies the
selected durable history and compaction instructions in the family-appropriate
prefix or suffix. It omits ephemeral context and normal goal/context delivery. Reject
nonempty =ephemeral_items=, =tools=, or =hosted_tools=, enabled =tool_discovery=,
and a requested reasoning summary for this purpose. The parent disables
Anthropic caching for this request, including system, history, and tool cache
markers, and applies the other families' existing ordinary-summary projection.
The agent cannot set arbitrary cache fields. Reject unknown purpose values.

=NATIVE_COMPACTION= is a separate operation and requires =purpose= set to
=PURPOSE_UNSPECIFIED=. Do not substitute ordinary summary generation when a
profile does not support native compaction. The agent can first request a
native checkpoint, then select that checkpoint for a separate portable
=GENERATE= request with =purpose= set to =ORDINARY_SUMMARY=, as in the existing
native-checkpoint-then-portable-summary sequence.

The parent validates the profile, context size, tool schemas, and resource
budgets. Its profile allowlists output limits, temperature, reasoning effort,
reasoning summary, strict schema mode, deferred discovery, and hosted tools.
Omitted options use profile defaults. An explicit false value disables an
optional boolean setting. Unknown or disallowed values fail explicitly. The
parent translates these logical options to library options and may apply its
own fixed provider fields, instruction placement, cache controls, and reasoning
parameter names. The agent cannot supply arbitrary request fields, URLs,
headers, credentials, model routing tokens, or HTTP options. Profile selection
cannot read host files or change provider endpoints.

Message roles describe model context, not trusted user actions or approvals.
New =TranscriptItem= values contain typed messages, calls, results, discovery
results, or a replay handle. Conversation blocks contain text, inline media,
tool calls, tool results, or visible reasoning. Visible reasoning is not a
signed thinking block. Media has a validated MIME type and bytes; there is no
implicit URL or host path retrieval. Reject unsupported roles, media, options,
or item kinds instead of silently discarding them.

** Opaque item replay

For each completed provider item, the parent stores the exact portable provider
item privately, including item IDs, status, signed or redacted thinking,
encrypted reasoning, and native compaction data. It returns an =OutputItem=
with a nonempty replay handle, family, zero-based item index, and one typed
view. The view exposes logical content for reasoning and display, not private
provider replay fields. Empty reasoning text is valid, including signed thinking
with no visible text. Hosted-tool views expose only bounded logical content
and status, not arbitrary provider fields. A compaction view may omit its
summary. Never send signatures, encrypted blobs, Lisp forms, or opaque original
items as agent-controlled input fields.

Handles are unguessable parent-issued identities scoped to the attached
session, profile, and provider family. Before forwarding an item event, durably
store its original item, scope, request and attempt identity, index, and handle.
Persist the public views and handles with the parent model-event log. On
restart, include accepted model results and their ordered views and handles in
resume data or session pages, using parent-origin =NOTE= records with a
=model_result= payload that contains the portable field-name projection of
=ModelComplete= plus the owning turn and request identity. The parent also stores
=request_kind= (=generate= or =native_compaction=) and =request_purpose= (=ordinary=
or =summary=) atomically with acceptance, before publishing the session note.
Resume restores ordinary generation output directly. Summary and native-compaction
output require an explicit agent checkpoint. Old unclassified notes require saved
agent records for all output handles; otherwise resume fails with
=ambiguous-model-result=. These parent notes are distinct from the agent's text
notes. Page and value limits still apply;
return =RESOURCE_LIMIT= if a single result cannot fit. The agent can then select,
omit, or reorder accepted handles without access to the original hidden data.

A =TranscriptItem.replay_handle= means replay that original item unchanged.
It has no accompanying editable view. Reject unknown handles, cross-session,
cross-profile or cross-family handles, and handles from failed or unfinished
attempts. Keep accepted handles valid for the retained session, including after
restart and compaction; do not delete omitted items while retained session
history can refer to them. Normal family projection and validated provider
encoding still apply. Never interpret a handle as a path or serialized code.
The parent must not silently append unselected history. Native compaction uses
the supplied items and returns a handle for the exact checkpoint. The agent
chooses where to use it in later history.

** Tools and argument text

Tool identity is the pair =(namespace, name)=; an empty namespace is the flat
namespace. Reject duplicate identities and inconsistent descriptions for the
same namespace. =input_schema= is the provider-neutral JSON Schema object
accepted by the profile. Preserve namespace descriptions, deferred flags, and
optional strict mode when constructing library tool namespaces. The parent
applies provider-specific name encoding and schema projection. Tool definitions
never register privileged parent operations.

=tool_discovery= enables the profile's client-executed discovery declaration.
Deferred tools require enabled discovery. A returned discovery call has a
=tool_discovery_call= view, not an ordinary executable tool call. The agent
answers it with =ToolDiscoveryResult= containing only tool definitions offered
to that request. The parent validates the call identity and expansion against
the original request, and encodes the library tool-search output. Replay keeps
its tools intact; native compaction uses the library's trimming rules. Discovery
does not grant access or add tools to the agent's allowed set.

A hosted tool declaration contains a parent-configured =capability_id= only.
The profile fixes its provider settings and allowed external capabilities.
An empty =hosted_tools= list disables hosted tools for this request, including
restricted turns. Native compaction requires empty =tools= and =hosted_tools=
and disabled discovery. Unsupported hosted tools fail before provider execution.

=ToolCall= requires exactly one of message-present =arguments= or present
=arguments_json=. A present empty map and an absent map differ. The text form
preserves the exact provider argument string, even when it is empty, malformed,
a JSON scalar, or not a JSON object. Do not replace it with an empty map.
Agent-side argument validation and tool error handling apply before execution.
Tool results must contain values supported by the profile. Deltas carry JSON
fragments for display and incremental parsing; they do not prove a valid call.
A delta uses a stable block index within its attempt. Call ID, namespace, and
name may be absent until supplied, then must be consistent.

** Attempts, results, and compaction

=ModelEvent.index= increases from one across the whole logical request, including
retries. =attempt= is one-based. Emit =attempt_started= before any event for an
attempt; it gives the maximum attempts and the scheduled retry delay in
milliseconds, zero for the first attempt. It resets provisional deltas, items,
metadata, and usage. After a nonterminal =attempt_failed=, emit either another
=attempt_started= or terminal =failed=. Report elapsed seconds, output presence,
retry eligibility, and a redacted structured failure for each failed attempt.
Cancellation never starts another attempt. No events follow terminal =complete=
or =failed=.

Completed-item events preserve provider order. Their indexes start at zero and
are contiguous within an attempt. The final =output_items= must exactly match
the successful attempt's completed-item events, including handles and views.
Emit any remaining completed-item events before =complete=. The receiver may
show provisional output, but must replace or remove it on attempt reset. Do
not execute tools or accept provisional items as durable conversation history
before =complete=. Failed attempts stay in the audit log, not accepted history.
This prevents retry output from duplicating accepted output or tool execution.

Metadata events are accumulated immutable snapshots of observed model, finish
reason, cache writes, and usage presence, including observations before failure.
=progress= is bounded redacted display information; it cannot change authority
or accepted history. =Usage.provider_usage= preserves the provider's complete
portable usage object for accounting and export, subject to value limits.
Typed counters are normalized projections of that object where present; reject
conflicting projections. Preserve cache-write counts as well as cache reads.
Raw usage and metadata are output data, never input request settings.

Map =ModelComplete= to the library's full =provider-result=: ordered items,
response ID, usage, metadata, turn state, and turn completion. Tool calls and
discovery calls are ordered subsets of the item views, not separate authoritative
lists. =reason= describes the request stop cause; =turn_completion= independently
records =ENDED=, =CONTINUED=, or unspecified. Do not infer explicit turn completion
from a stop reason or the absence of tool calls.

The parent replaces a provider per-turn routing token, including Codex
=x-codex-turn-state=, with =turn_state_handle=. It persists the token privately
and validates session, profile, family, and =turn_id= on each use. It expires
when the user turn ends; reject use in a later turn. =continuation_handle= is a
separate parent-issued session/profile/family-scoped provider continuation, not
an item list or a per-turn token. Neither handle accepts agent-supplied hidden
state, and neither implicitly selects history.

For =NATIVE_COMPACTION=, use the library's native compaction endpoint and return
=compaction_outcome= set to =COMPACTED= with the checkpoint item, usage, and metadata.
If the endpoint does not exist or returns 404, 405, or 501, return terminal
=complete= with =UNSUPPORTED=, no output items, and unspecified stop reason and
turn completion. Other errors follow attempt/failure rules. Native compaction
must not emit text-generation deltas, tool calls, or per-turn routing state.
Ordinary generation leaves =compaction_outcome= unspecified. The agent chooses
whether to request a separate ordinary-generation compaction fallback; the
parent never silently substitutes one.

The mapping targets =cl-llm-provider-api= commit

* Private record service

Requests address a collection and parent-issued ID, never a pathname. Scope is
the attached workspace by default. Global memory access requires a separate
parent-configured permission. The collection identifies authority; user text
inside =fields= cannot change scope. Query limits range from 1 to 256. Cursors
are parent-issued and bound to the collection, query, and scope.

| Collection | Allowed operations | Writable fields |
|------------+--------------------+-----------------|
| Memory | QUERY, CREATE, REPLACE, DELETE | title, content, tags |
| Papercut | QUERY, CREATE, ASSESS, CLOSE | See operation rules below |
| Agenda | QUERY, CREATE, REPLACE, DELETE | text, status, memory_ids |

For papercut CREATE, accept =title=, =content=, =diagnostic=, =issue_kind=, and
=tool=. ASSESS accepts =verdict=, =note=, and =diagnostic=. CLOSE accepts
=resolution= and =diagnostic=. Title/content, verdict/note, and resolution are
required for their respective operations. Diagnostic is optional redacted
export data; keep private details in content or note. Parent-owned timestamps,
IDs, revisions, scope, and origin cannot be supplied as writable fields.
Memory title/content and agenda text/status are required on create or replace.
Tags and memory IDs are lists of strings. Agenda status is =todo=, =doing=,
=blocked=, =done=, or =note=. Assessment verdict is =improved=, =worse=,
=unchanged=, or =too-early=. Unknown fields and unsupported operations fail.

QUERY accepts query/cursor/limit and no record ID, revision, or writable fields.
CREATE accepts fields but no record ID or expected revision. REPLACE, DELETE,
ASSESS, and CLOSE require the exact ID and expected revision. They do not
accept query pagination fields. REPLACE replaces writable fields completely.
An empty =RecordResponse= acknowledges a delete; other writes return the
resulting record and revision. Conflicts return =REVISION_CONFLICT=.

QUERY returns =collection_revision= for an exact structural snapshot of the full
parent-authorized collection scope, independent of the query filter. All pages
of one query retain that revision. The parent retains bounded issued observations.
CREATE can supply =expected_collection_revision=. Agenda REPLACE and DELETE can
also supply it, in addition to the item revision. The parent checks the issued
observation against the current exact scope inside the same write transaction,
before any append or receipt. Unknown or stale observations fail with
=REVISION_CONFLICT=. Omission preserves the low-level write contract. The guard
is part of the operation payload identity. An identical committed retry returns
its receipt before checking the guard, including after its observation expires.

All writes require a nonempty =operation_id=. Persist their payload identity
and result atomically with the write, scoped to the session. Identical retries
return the original result; conflicting reuse is invalid. Query operation IDs
must be absent (empty). Bound query results and use a cursor if they do not fit.
Validate linked agenda memories within the same permitted scope.

* Access policy

=AccessRequest= asks for exact resources and operations, with an operation ID
and an untrusted reason. A parent-owned prompt describes the resolved grant.
The parent obtains approval before committing it. Persist operation IDs and
policy outcomes to avoid duplicate prompts or grants on retry. Conflicting
operation ID reuse fails. A batch of grants is approved and applied atomically.

Filesystem targets are absolute paths resolved and bound by the backend,
including link and replacement rules; operations are =read=, =write=, or
=execute=. Directory access covers descendants. Network targets are exact
host:port authorities with operation =connect=; enforcement must account for
name resolution and redirects. Service targets are parent-configured service
IDs with operation =connect=, not arbitrary socket paths. Reject unsupported
combinations and backend guarantees before requesting approval. Access to a
service includes its service authority, not merely permission to open a file.

Instance grants expire when that instance stops. A restart-required instance
grant applies to the replacement instance only, then expires. Session grants
last until session close or explicit user revocation. Approval never grants
access to parent-private roots or the parent control endpoint; supply private
records through services. Do not imply that denying a Docker socket blocks
all Docker access through other granted services or networks.

Access operation IDs are session-scoped. Retrying an old operation reports its
current disposition without a fresh grant or prompt. If its approved lifetime
has ended or it was revoked, return =EXPIRED= with no effective grants, not a
historical =ACTIVE= reply. A new grant requires a new operation ID and approval.
For a partially expired batch, report =EXPIRED=; consult =Welcome= for other
active grants. This does not revoke surviving grants in the batch.

Record approved policy separately from active policy. A pending restart event
names the approved revision; only =Welcome= or an =ACTIVE= decision proves
application. =effective_grants= in =Welcome= and =ACTIVE= is the complete active
set; in other states it is empty. Backend failure does not activate a revision.
Revocation uses the same restart path and does not revoke already-read data.
Persist access outcomes as parent-authored session notes for the replacement.

* Compatibility and verification

Never reuse field numbers or names after removal; reserve both. Make compatible
additions optional. Never change a field's meaning in place. A new mandatory
contract needs feature negotiation or a major version. Keep transport major
version distinct from access-policy revisions and durable session sequences.

Validate both schemas from the repository root with:

#+BEGIN_SRC sh
protoc --proto_path=proto --include_imports --descriptor_set_out=/tmp/autolith-parent.pb proto/autolith/common/v1/value.proto proto/autolith/parent/v1/protocol.proto

The descriptor is a temporary validation output, not a tracked artifact.
Before wiring this API into the runtime, verify the chosen Lisp generator and
runtime against unknown fields, presence, oneof semantics, malformed inputs,
resource limits, and cross-language fixtures. Runtime checks must also cover
restart during a tool effect, duplicate writes, stale revisions, cancellation
races, failed policy application, private-path denial, and descendant cleanup.
