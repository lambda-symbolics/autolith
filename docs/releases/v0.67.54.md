# 0.67.54

## Workspace changes

- Submit `(cwd PATH)` during a response to change workspace in steering order. Relative paths resolve when that input is applied; `(cwd)` returns the current path immediately.
- Send the model a durable workspace-change notice before its next request and publish the committed workspace to connected clients.
- Recover pending workspace changes from their prepared absolute paths, retain their submission identities, and avoid repeating the live change when notification is retried.

## Personal memories

- Read and write agent-personal memories through `memory:personal`, with ownership tied to the agent's durable identity across channel changes and reloads.
- Include personal memories in related recall. Child agents may read shared workspace/global memories and structured knowledge; top-level agents may also modify them.
- Assign a new child's durable identity before its first provider request and tool call.

## Onboarding and terminal

- Stop onboarding authentication with Ctrl-C from either the provider picker or authentication-method picker, including after choosing the wrong provider.
- Choose 0, 1, or 2 blank lines around the normal input prompt with `:prompt-padding` in settings or onboarding. The default is 1.
- Clarify recovery-vault actions: `(vault)` displays contents, `(vault-restore)` resubmits messages, and `(vault-discard)` deletes the queue.

## Context and reliability

- Retain measured conversation usage when prompt headers change, charge inserted header text by UTF-8 bytes, and mark deletion-only header edits as estimates.
- Wait for restart-marker removal before checking checkpoint cleanup in Windows readiness tests.
