# 0.67.36

## Channels and the shared world

- Run ordinary sessions as channels in one background world server instead of starting an agent process per terminal. Each channel has an identifier, working directory and durable conversation history.
- Keep channels open across repositories, visit child agents and return to the original conversation.
- Run `autolith` in a directory to connect, starting the server when needed. Open the workspace's most recently active channel not controlled by another terminal, or create one.
- Open a specific channel with `autolith open ID`. Inside Autolith, use `(switch)` for the picker or `(switch "ID")` to select one; unambiguous identifier fragments work.
- Closing or disconnecting a terminal leaves its channel running. Use `(detach)` or Ctrl-Z to detach deliberately, and `(quit)` to end the channel.
- Inspect the server with `autolith lg status`. Stop all channels and the server with `autolith lg stop`; shutdown waits for confirmed server exit.
- Report failed server startup instead of silently starting a separate agent in the terminal process.
- Unload channels without attached terminals, running work or pending work after the configured idle interval, 30 minutes by default. Reopen one or message its agent to serve it again from durable history.

## Participants and identity

- Distinguish channels, participants and terminals: a channel is a conversation and execution location; a participant is a person or agent with identity and private state; a terminal shows or controls a channel. Switching the terminal view moves nobody.
- Limit each agent to one resident channel and each channel to one resident agent.
- Start the human participant as `user` in their own agentless `inbox`. Give agents workspace-derived names such as `frob` and `frob-2`; children use parent-supplied names.
- Use unique, case-insensitive handles. Rename the current channel's agent with `(rename "reviewer")`, or any participant, including yourself, with `(rename "WHO" "NAME")`.
- Inspect channels through `channel:id/ID`, the current channel and its children through `channel:current`, and other channels through `channel:list`.
- Share identifiers and history between channels and durable conversations. Migrate existing histories onto corresponding channels and participants without recreating identities on each open.

## Messages, mentions and inbox

- Send as yourself with `(tell "ID" "Please review the change")`; destinations accept channel identifier fragments or handles such as `@reviewer`. Use `(tell)` to choose a channel and prepare the message form.
- Complete mentions in the composer. A submitted `@reviewer please check the failure path` reaches that participant's channel before the local agent takes the prompt; `@` inside an email address or path is not a mention.
- Use `channel.send`, `channel.subscribe` and `channel.unsubscribe` for agent messaging. Deliver to destination residents, subscribers and mentioned participants; subscribers also receive ordinary typed messages and agent replies from followed channels.
- Start a turn for an idle agent; steer a busy agent with the sender and source channel labelled. Children send as their own participants under their role's tool policy.
- Address the sender's parent with `@parent`. For a parked parent, deliver to the nearest ancestor agent with a channel, or to the human if none exists.
- Put messages addressed to or mentioning the human in the inbox as notices, not agent prompts. Open it with `(switch "inbox")`; notices stay unread until displayed, then appear in full with a return command for the source channel. Reply with `(tell "ID" "text")`.
- Persist incoming deliveries and outgoing sends. Retry full inboxes and interrupted deliveries with the original message identifier; crash replay does not duplicate them. Report destinations still waiting to the sender.
- Queue messages for agentless channels until an agent resides there.

## Moving and parking agents

- Bring an existing agent into the current channel with `(move "WHO")`, select its destination with `(move "WHO" "ID")`, or open pickers with `(move)`. Park without deleting with `(dismiss "WHO")`; create an agent in an empty channel with `(domestic)`.
- Before moving or parking, stop the current turn at a safe boundary: finish in-flight tool calls, start no new provider request, and drop unstarted prompts with a notice in the old channel. Refuse moves into occupied channels or the human inbox.
- Take the agent's model and existing context to its destination. Include activity from the move onward; earlier channel history is readable but not automatically inserted into context.
- Save private context before residence changes and restore it before the next turn, including after restarts or partially completed moves.
- Move goals and missions with the agent. Pause running missions and cancel their mission jobs; resume with `(mission :resume)`.
- Keep other started jobs running and recording results in their original channel, without waking an agent there.
- Cancel a moving child's active parent assignment and report the outcome to the parent. Its own children continue.
- Retain a parked agent's identity, context and children, but no channel; parking does not park its children. Restore it with `(move "WHO")`; mentions report no delivery destination while parked.
- Retain agentless channels' history and subscribers. Move an agent in or create one with `(domestic)` before submitting prompts. Domestic agents start without inherited private context and can read channel history.

## Durable children and jobs

- Retain child identities, channels, names, roles and histories after assignments finish. Reuse idle children through their channels; `channel:current` lists children and whether each is busy.
- Allow up to 32 children per agent, including children creating their own children within configured depth and role limits.
- Visit child channels to inspect transcripts or work directly under the child's role instructions and tool permissions, not as an unrestricted top-level agent.
- Use the lifecycle operation matching the work:
  - `child.spawn`: create a child and start its assignment.
  - `channel.send`: assign work to an idle child or steer a busy one.
  - `job.get`, `job.wait`, `job.cancel`: inspect, await or cancel an execution. Cancellation does not delete its child.
  - `child.rename`: change the child's name.
  - `child.compact`, `child.reset`: summarize or clear an idle child's history.
  - `child.remove`: explicitly delete an idle child, its channel and descendants. Completion does not automatically prune children.
- Deliver completion results to the conversation that started the work. Nonblocking work detaches by default; `continue` can wake the owning conversation, while `notify` waits for an ordinary turn.
- Validate the complete channel-removal selection before changing the world. Retry storage cleanup durably and prevent removed identities from reappearing through leftover history.
- Check recorded ownership before deleting worktrees; preserve unrelated checkouts when ownership is uncertain. Keep engineering artifacts independent of checkout cleanup.

## Usage and context accounting

- Preserve conversation-lifetime usage across unloading and reopening parent and child channels. Track assignment-job usage and timing separately; label process-wide `(status)` spend as belonging to this process.
- Inspect stored data, logical disk usage and process memory across workspaces with `autolith usage`. Count live channels separately, but each process ID once, including a world server with no open channels.
- Deduplicate disk file identities across overlapping roots. Report memory as RSS observations and identify unavailable or partial measurements.
- Reuse measured provider usage for the context meter and automatic compaction across ordinary usage-metadata updates, rather than discarding it for a larger character estimate.
- Count retained reasoning in the measured post-response input and output total; count new tool evidence and session content separately. Distinguish exact covered measurements from estimates with new content.
- Invalidate obsolete measurements after interrupted response persistence, compaction or context replacement.

## Contract recovery

- Compare vector-valued contract arguments structurally across log replay. Retain earlier authorization when replacing an admitted contract without activating the new proposal.
- Keep string case and scalar types significant; reject invalid admission receipts before appending anything.
- Recover with `(reset-contracts)` or `contracts.reset`, even when damaged metadata blocks ordinary tools:
  - Archive the original log byte-for-byte with private permissions.
  - Atomically remove contracts and saved diagnosis/probe records across all scopes in the store.
  - Preserve facts, evidence, rules, methods, procedures and prose memories; allow new contracts afterward.

## Terminal navigation

- Group the fullscreen sidebar by workspace and nest children under parents, with the human inbox first. Distinguish working, idle and unloaded channels; show attached terminals, unread messages and mentions separately.
- Click channels to switch; press Ctrl-T to toggle the sidebar. On narrow terminals, use Ctrl-T for a keyboard drawer, then arrow keys and Enter.
- Share durable human-inbox unread counts across terminals. Keep ordinary channel unread counts per terminal and show queued-delivery counts for unserved channels.
- Show loading before opening an inactive channel's host, including noticeably long startup.
- Initialize prompt recall on open and reconnect, loading older input lazily. Show executable cancellation forms with quoted string job IDs, such as `(job.cancel :id "exec:1")`.
- Reflow retained Markdown after transcript-width changes, including sidebar changes. Carry terminal presentation preferences across switches and reconnects.
- Explain channel navigation, the inbox, agent residence and separate child/job lifecycles during interactive onboarding.

## Checkpoints, clients and startup

- Checkpoint the shared process: make new turns wait for active turns and jobs to finish, pause all channels, save the image and reconnect attached terminals. Send every channel the outcome and the requesting channel the generation ID.
- On Windows, restart the saved exact heap through the launcher and serve the channels again.
- Use the shared channel runtime for ACP clients, including ownership and lifecycle rules for session creation/loading. Tolerate editor disconnection during streamed delivery; wait for channel idle on synchronous requests.
- Restore caller ASDF settings before executable user initialization while isolating private runtime startup. Use a store-resident interpreter for packaged Nix launchers starting the detached world server.
- Resolve Windows check workers' explicit ColorLisp native-library path before temporary cache isolation, so mapped DLLs do not prevent fixture cleanup.
- Stream retained conversation-fork history within bounded memory and transcript queries in bounded pages. Refuse oversized `resource.read` windows explicitly so callers can request smaller ones.
- Coordinate startup, deletion and checkpoint admission across interrupted delivery, concurrent opens and durable cleanup in the shared-world lifecycle.
