#+TITLE: Autolith Architecture
#+STARTUP: content

Autolith is a terminal agent in a live Common Lisp image. The running
system can be inspected and changed by both the agent, and the user.

Agent definitions live in the =autolith= package and the =autolith-agent= ASDF
system. The trusted parent uses the =autolith-supervisor= package and focused
systems for the interface, providers, private storage, and access policy.
It does not load the agent ASDF system. The =autolith= system is a compatibility
entry point for the agent. Generated Protobuf bindings use their own packages.

- The *stable launcher* checks runtime and source provenance, then starts
  the active image or recovery
- The *trusted parent* owns terminal I/O, approvals, provider requests,
  credentials, private records, and native child isolation. It loads only explicit
  trusted provider extensions. Agent init files and private mutations execute in
  the child.
- The *active image* runs reasoning, commands, tools, and self-modification.
  It sends interface events and bounded service requests to the parent.
- *Workers* handle search and =lisp.*= REPLs in separate Lisp images.
- *Durable records* use parent-private XDG folders. Selected agent code and
  initialization files have exact read-only projections into the child.
- The *recovery image* is a separately built pristine core, which Autolith
  will reboot into in case the current image is FUBAR. Autolith can work
  using the recovery image to either fix figure out the issue with your
  current image, or try to finish your task if that's a priority.

** Trusted parent protocol

The boundary and Protobuf wire schemas are specified in
[[file:parent-agent-protocol.org][Parent-Agent Protocol]]. The default launch path uses this protocol.
The =autolith-supervisor/protocol= system supplies generated bindings, bounded
wire validation, portable values, and startup negotiation. The
=autolith-supervisor/session= system adds durable session storage and the
=session.v1= dispatcher, with bounded requests, output, and shutdown handling.
The =autolith-supervisor/model= system adds trusted model profiles and semantic
request projection through the provider library's wire API, plus a private replay
journal. Request projection checks family capabilities, parameter limits, and
replay-handle authority before request construction.

The replay journal stores provisional provider items and public events before
publication. After final provider validation and cleanup, commit the accepted
completion and its pending session-note projection. Publish that parent-owned
=model_result= note with its stable event identity, then acknowledge publication
in the replay journal. Only then authorize replay handles or send terminal
completion. The two journals are separate. Recovery repeats pending notes with
exact deduplication, including notes for known turns already marked interrupted.
A recovery note does not change the turn outcome. These parent libraries have
standalone tests that run without loading the agent system.

The model event collector maps provider-library events to protocol views through
trusted storage and emission hooks. It retains exact library-normalized originals;
these are not raw provider wire data. A provider completed event is provisional.
Call finish only after the executor returns a validated result. The pinned library
attempts cleanup but suppresses cleanup errors, so its return does not prove that
stream closure succeeded. The acceptance hook must complete replay acceptance and
session-note publication before returning true. The collector retains accepted
completion data if terminal emission fails.

Use =make-model-replay-collector= to connect the collector to the replay and
session journals. Its hooks write each event once and verify the saved identity
before emission. Continuation and turn-state handles are private, kind-specific,
and usable only after acceptance and session publication. Turn-state handles also
require the owning turn. A terminal failure commits its event and final request
state together. Use the request-scoped =make-model-replay-resolver= when projecting
a later model request. The collector checks public event budgets before retaining
items or state, and reserves space for a terminal failure. Reconcile unknown
journal write outcomes before further publication.

Use =make-model-service= to attach an optional ordinary-generation service to
=session-runtime-open=. Select =session.v1=, =model.v1=, and =model-items-v1=
together. Supply a trusted executor, transport-abort callback, clock, and timeout.
The service admits one provider call per connection. One storage-owner thread
serializes journal operations. A separate writer sends ordered frames from bounded
byte queues, including the current write and a separate control reserve. History
updates follow successful write receipts. The reader latches cancellation without
waiting for storage or output. Separate control and deadline threads stop provider
work. Join all tracked workers before reusing the session store.

The owner orders acceptance against cancellation before entering the collector's
finish operation. Cancellation received during an acceptance operation is pending
until its durable outcome is known. This phase is not a terminal outcome. A
committed acceptance wins; a known pre-commit failure permits cancellation.
Reconcile an uncertain write or close the connection. The executor must stop all
callbacks before return. The abort callback must also confirm actual transport
closure, including after normal executor return, before acceptance can begin.
Native compaction is not enabled by this service.

The optional =autolith-protocol-client= system supplies the agent-side client
over explicit private streams. It supports negotiation, session reads and appends,
turn lifecycle, transient output, ordered model events, and correlated cancellation.
Use =agent-context-project= to map logical conversation items, tool schemas, and
request-local context to a typed =ModelStart=. After receiving its validated
terminal completion, use =agent-context-accept= to consume context receipts and
retain detached public output views with replay handles. Later requests send the
handles, not reconstructed provider data from those views. Ordinary summary
requests omit tools and request-local context.

After handshake, start =agent-protocol-driver-start= to give one reader exclusive
receive ownership. The driver routes validated replies into bounded request queues
and dispatches lifecycle messages separately. Use =agent-protocol-driver-request=
for correlated sends. Consume each terminal reply once, then close and join the
driver during shutdown. Queue overflow or disconnect closes the connection; it
never authorizes an effect retry.

The optional =autolith-protocol-client/records= system adds typed record requests
and agenda, memory, and papercut adapters. Use =agent-protocol-record-request=
through the driver, then consume one terminal response. The parent selects the
record scope and checks durable operation identities. The client has no private
store path.

The shared agenda, memory, and papercut systems contain the domain types, record
validation, and stores. Legacy agent adapters use those same implementations.
The parent record services compare revisions and exact snapshots within the
write transaction. They commit operation receipts with each mutation. The
=autolith-supervisor/records= dispatcher reserves session-wide operation IDs
before domain dispatch. Domain receipts are the only stored operation results.

Use =make-agent-protocol-provider= to select an explicit parent profile for the
existing agent provider protocol. The adapter projects logical context and maps
validated public events and accepted results to the agent interface. Public output
items retain parent replay handles through conversation persistence. Later requests
use those handles even if the agent changed the displayed item. Provider credentials
and transport configuration do not enter this adapter.

The =autolith-supervisor/accounts= system contains shared OAuth storage, refresh,
and credential scopes. The =autolith-supervisor/family-accounts= system adds
provider-family settings and authentication. The legacy agent imports these
implementations. Shared ChatGPT HTTP headers and stream opening are in
=autolith-supervisor/provider-http=. Parent executors use trusted
profile-to-account bindings and the provider library's encoder, parser, and retry
engine. They confirm transport closure before model acceptance.

Parent-backed =web.run= and =web_extra.gist= use the fixed =WEB= parent operation.
=src/agent/protocol-web.lisp= sends commands, text history, or a URL. The parent
selects the profile, account, endpoint, credentials, and search mode in
=supervisor/parent-web.lisp=. It returns public text and bounds request lifetime
and response size. Page retrieval uses parent tool authorization for the initial
URL and each redirect. A parent refusal does not select the standalone transport.

The optional =autolith-supervisor/private-process= system provides a private duplex
connection through an inherited descriptor, with separate bounded diagnostics and
explicit child environment. POSIX cleanup covers the child process group. Windows
uses a native job object. POSIX workers that create another process group need
separate launch integration before full descendant cleanup can be claimed.

The optional =autolith-supervisor/access= system stores approved policy and
operation receipts separately from the active instance revision. The session
adapter runs approval outside the session owner, records parent-authored access
outcomes, and requests replacement after approval. An already-active grant does
not require another approval or revision. Cancellation and policy commit share
one control lock.

The native backend has one adapter per supported host. Darwin uses a deny-default
Seatbelt policy and inherited process-control restrictions. Linux uses a minimal
Bubblewrap root, an inherited syscall filter, and a delegated cgroup v2 subtree.
Windows uses the pinned AppContainer helper and native job objects. Each adapter
rejects grant masks it cannot enforce before approval, checks private file
identities against admitted scopes, and requires external descendant cleanup
before replacement. Trusted host writers must not add private aliases after
admission. Missing native prerequisites stop launch; there is no process-only
fallback for the parent application.

Use =agent-protocol-session-start= after handshake to create a parent-backed
conversation and a separate turn worker. Session reads and acknowledged appends
replace legacy private conversation writes. The bridge projects durable input
before calling the existing provider loop. Cancellation stops new effects and
drains any active model request before the stop acknowledgement.

Supply =:lifecycle-callback= to =session-runtime-open= for short parent control
updates after durable turn and stop transitions. The callback receives the event
kind, turn ID, and outcome outside the lifecycle lock. Use the separate terminal
system for bounded trusted input, approval prompts, and escaped agent output.

The default =autolith= entry starts the trusted parent interface through
=autolith-supervisor --cli=. The explicit =script/parent CONFIGURATION.sexp=
entry accepts bounded data-only configuration. Both compose terminal, provider,
session, record, and native policy services. The child enters the standard agent
core with =--parent-agent= before agent initialization or mutations load.
Every launch requires native base isolation; =:access-p= selects the optional
access request feature. The controller closes the old launch before replacement.

The parent owns terminal I/O and approvals, provider credentials and response
streaming, private configuration and records, policy, and child lifecycle.
Parent configuration is separate from agent initialization Lisp. Private agent
mutations and agent-supplied Lisp never execute in the parent image.

The restricted agent owns reasoning, tools, workers, and self-modification. It
accesses approved resources directly and requests selected private records or
new access through the parent protocol. Private storage roots are not mounted
into the agent. Approval changes committed policy; restart applies it to a new
instance. The parent resumes the same durable session without requiring the
old heap or a cooperative shutdown. Stop descendants before relaunch.

The OS sandbox backend enforces grants. Process separation and Protobuf do not
enforce access by themselves. Public remote-control schemas may share data
types, but must use a separate authenticated and authorized interface.

* Configuration layers

Autolith keeps packaged defaults separate from the user's XDG configuration.
An optional absolute site configuration root supplies =init.lisp=, =mcp.sexp=,
=skills/=, and =agents/=. Site definitions have lower precedence than the
corresponding user definitions. Trusted directory configuration follows user
native MCP configuration, while the user XDG =init.lisp= loads last among
filesystem Lisp configuration. Live registrations remain independent runtime
state. The user-owned =directory-scopes.sexp= is never read from the site root.

The site layer is a deployment and composition mechanism, not a security
boundary. Privileged operations must remain behind the supervisor boundary even
when site or user Lisp replaces every guest-side definition.

* ACP service

=src/acp/session.lisp= owns leased headless applications and serializes primary
operations. =observer.lisp= projects native streaming/tool events and editor
permissions. =mcp.lisp= builds session-local client declarations through the native
MCP manager and credential scopes. =runtime.lisp= supplies the agent methods,
chronological replay, bootstrap, and disconnect cleanup.
=extensions.lisp= owns typed dispatch, bounded JSON projection, advisory events,
and session-scoped read/write admission. The =extension-*.lisp= adapters project
native settings, model/operation catalogs, conversations, owned jobs and structured
resource windows. =completions.lisp= owns the condition-variable controller for
receipt-backed automatic turns, sharing prompt admission, observer projection,
cancellation and shutdown with explicit prompts.

The source entry and stable launcher route ACP diagnostics to stderr and avoid
interactive recovery. The serving lifetime holds the secret-use guard while
client credentials are retained. Cancellation targets registered prompt/tool
owners; durable turn finalization defers queued interrupts before lease teardown.

* User state

Autolith stores portable, readable S-expressions (for now, it is possible we migrate
to sqlite or similar in the future).

Use =sexp-store= transactions for locked read/modify/publish operations. Caller
state is published after durable records. Conversation sidecar reconstruction
holds the same file lock as source invalidation and writes.

| State         | Components                                               |
|---------------+----------------------------------------------------------|
| Conversations | headers, messages, provider items, model choices         |
| Memories      | workspace and global facts, sources and premises, tombs  |
| Knowledge     | predicates, evidence, supports, rules, retractions,      |
|               | learned procedures and their runs, diagnoses and cases   |
| Viewers       | the last knowledge snapshot each viewer saw (derived)    |
| Agendas       | versioned workspace plans and memory identifiers         |
| Papercuts     | user-visible defect reports and closure tombstones       |
| Input vault   | queued follow-ups and steering after a crash             |

- The knowledge log is append-only: a batch of records is one =:transaction=
  form, so an interrupted write leaves none of it, and a reader folds only
  what was appended since its cached read. It lives beside the memory log
  rather than in it so older generations still read every memory after a
  rollback; they never read the knowledge log. Derivations, statuses, and
  conflicts are evaluated from the log, the cited files, and the time, and are
  never stored.
- Procedures are learned from tool-call traces read from conversation logs.
  Traces are cached in memory per conversation and extended from where the
  last read stopped; they are never written anywhere, so the transcript stays
  the one record of what a turn did.
- Conversation records are authoritative provider history
- The header records the selected model and effort. Later changes are
  durable configuration records, so resume restores the latest choices
- Identifiers use =idsmall= Base58 IDs, which are not the most secure, but they encode a timestamp and are short enough that
  you can at least remember the prefix.
- =src/conversation/compaction.lisp= captures the provider cutoff and uses a pure
  =clinker-transcript= carry-forward plan. It validates late arrivals and truthful
  repairs before publishing a self-contained checkpoint, then installs the
  replacement projection. =:cutoff-seq= identifies the request snapshot;
  =:through-seq= covers every record before checkpoint publication.
- =src/conversation/input-history.lisp= maintains complete editable input recall in
  =conversation-picker/<id>.inputs.sexp=. Missing or invalid indices rebuild from
  authoritative records once. Each new input appends one indexed sequence;
  compaction flushes the index before retiring the active segment. Checkpoints
  carry the last input sequence, not the input strings.

** Configuration

A =configuration= holds a table of settings and their values. Each setting is
an instance of a =setting= kind (=boolean-setting=, =choice-setting=,
=integer-setting=, =string-setting=, =pathname-setting=, =derived-setting=,
and the Autolith-specific =model-setting= and =reasoning-effort-setting=)
declaring its name, type, documentation, label and group for the settings
page, default, options, scope, and environment variable. =define-setting=
registers a knob once; each configuration snapshots the registry at creation,
so user initialization may add knobs and children may carry different ones.

=config= reads a value and =(setf config)= coerces, validates, stores, and
notifies listeners; =*configuration*= supplies the default instance. Values
are chosen at creation by source precedence: explicit override, environment,
durable file, default. Scopes are =:process= (fixed for the process),
=:durable= (persisted through the preferences store on every session
change), =:session= (forgotten at exit), and =:derived= (computed on read).
=configuration-copy= produces an independent instance for children and
inference frames; listeners stay with the original.

=preferences.lisp= reads and atomically writes version 8 records of durable
settings, preserving unknown keys across rewrites. Unsupported or malformed
records are reported through =preferences-load-warning= during configuration
creation.

* Provider and tools

- =src/provider/client.lisp= integrates product providers with
  =cl-llm-provider-api= wire clients and request execution. Render semantic stream
  events in the terminal and record projected provider history in conversations.
- =src/provider/wire-protocol.lisp= anchors Codex's identical, currently supplied
  goal and remaining developer-context tail before appended assistant/tool
  rounds, after =context-delivery-project-items= has placed opted-in anchored
  contributions. Exact suffix validation uses that assembly's actual tail,
  not the full delivery rendering that also contains anchored blocks.
  Only the current request's objects are moved; durable history is unchanged.
  Weak conversation-keyed state retains two positions and case-sensitive
  SHA-256 digests, not prompt text. Reuse requires the complete preceding
  history to remain an exact prefix and no intervening user, developer, or
  system message. Changed, omitted, partially omitted or unrecognized context,
  rewritten/shortened history, and direct compaction requests reset placement.
  When compaction uses a detached request view, the original conversation
  resets on the changed history at its next ordinary request.
  Compaction wire input itself is unchanged. The placement-state mutex does
  not serialize conversation mutation or network requests: concurrent
  constructors can reset cache continuity, but each uses only its own context.
- Tools have metadata, namespaces, validation, and a result for every
  call, including failed ones
- =src/tools/defaults.lisp= assembles the registry

provider request --> semantic events --> agent --> validated tool calls
                                             |
                                             +--> matching tool results
#+END_SRC

- A provider request sees tokens only in its dynamic scope
- The optional Codex file is a one-time access-token import

* Revisioned resources

=cl-resources= defines authority-neutral identities, resolver registries,
observations, revision guards, operation discovery, typed conditions and staged
change-set lifecycles. Autolith registers product resolvers and retains
conversation-local observation aliases in =src/resource/protocol.lisp=.
Caller authorization and resource-specific storage policies belong to Autolith.
Each resolver documents its own scheme for reading and editing, and the
=resource.read= and =resource.edit= descriptions are composed from the resolvers
of their registry, so a scheme registered only in some sessions appears only
there.

=src/resource/workspace-changes.lisp= adapts staged changes to exact UTF-8 file
snapshots. Cooperating operations share the workspace mutation lock. Publication
is atomic per file; failed batches compensate in reverse order, retaining owned
undo handles when cleanup or safe rollback requires explicit recovery. Staging
ownership transfer defers asynchronous interruption. Restorable host permission
values retain source access state before ordered moves remove their source paths.

* Workspace and workers

- Command execution uses =platform-call-with-command-sandbox= to own policy
  construction and scope cleanup. =cl-exec-sandbox= selects the backend:
  - Bubblewrap on Linux
  - Seatbelt via =sandbox-exec= on macOS
  - AppContainer, a restricted token, scoped ACLs, and a Job Object on Windows
- The default policy provides:
  - no network
  - host read-only on POSIX; explicit tool reads and system application access on Windows
  - workspace and temporary writes
  - protected repository metadata
  - 60 second default timeout
- The Windows adapter serializes scope construction through cleanup and sets
  child-only temporary/cache environment paths. The release launcher selects the
  bundled native helper outside writable scopes. Both Windows authorization
  modes execute commands through native PowerShell.
- Search is one supervised native helper per fff registry.
- =lisp.*= operations run in named persistent SBCL subprocesses. A pristine
  worker, like the private replay probe, boots the installed active core when
  its manifest matches the source and runtime exactly, and loads the system
  from source otherwise; the choice is made again at every start.
- Worker images never participate in active startup or recovery
- =sexp-config= reads skills, MCP configuration, child roles, etc.
- Tasks use =cl-jobpond= for admission, threads, deadlines, cancellation, and
  generic durable completion subscriptions. =src/task/completions.lisp= projects
  bounded outcomes and reconciles mailbox claims with durable conversation receipts.
  =src/application/job-completions.lisp= admits coalesced primary continuations
  through the ordinary input controller. Bounded metadata-only controller work
  frees mailbox capacity occupied by notify-only or inadmissible outcomes.
  Producer callbacks only signal its condition variable; provider requests occur
  on the normal turn path.
- =src/task/unfinished-work.lisp= reads owned durable continuity and exact-owner
  conversation receipts for bounded outstanding-job context. Compaction records
  contain reference snapshots; later request contributions re-read job authority.

** Headless job observation

=src/task/job-boundary.lisp= runs one contracted role through the application
runtime and atomically publishes its terminal result. =src/startup/main.lisp=
accepts the opt-in =run-job --events sexp= flag. The event stdout stream is
captured before redirecting diagnostic streams to stderr and interactive input
to EOF. Bordeaux Threads initial bindings include recursively inherited stream
bindings for nested workers; no scheduler or provider transport is added.
After application cleanup and bounded delivery, the streaming CLI exits directly
with its result status, without flushing or interrupting a blocked stdout writer.

=src/task/job-event-observer.lisp= adapts the existing orchestrator listener and
child observer events. Its scope is one generated root admission name in the
owning conversation, then that root's exact job identifier and descendant
ancestry. It retains only the root identifier. Wire job IDs are execution UUIDs;
provider call IDs are hashed with the run UUID, without a growing call map.
Projection permits registered canonical tool names, approved statuses, and
bounded normalized numeric usage fields. Continuity precedes task start events.
Descendant terminal events follow durable task results or tool terminal metadata;
root terminal events follow publication of the outer result artifact. Listener
registration is removed on every exit.

=src/task/job-events.lisp= owns the version-one closed vocabulary, bounded
=sexp-config= grammar, validation, UTF-8 serialization, finite queue, and single
writer. Producers enqueue bounded owned snapshots without waiting on stdout.
Backpressure evicts progress first and reports lifecycle overflow with a fixed
warning. Final delivery has a reserved slot; shutdown waits only for a bounded
interval. An in-flight blocked writer retains one bounded payload; it is not
killed or used to interrupt task execution.
=:run-finished= is the last delivered event when the consumer remains connected.
The stream has no durable replay authority; consumers reconcile with the output
artifact.

** Native language servers

=src/lsp/configuration.lisp= validates user-owned =lsp.sexp= with the closed
=sexp-config= grammar and selects workspace-bounded project roots.
=cl-lsp= implements binary Content-Length framing, request correlation, ordered
server callbacks, deadlines, process/thread cleanup, initialization, disk
synchronization, UTF-16 positions, and version-aware push/pull diagnostics.
=src/lsp/tools.lisp= registers the query, diagnostics, status, and restart tools,
appends bounded diagnostics after successful workspace resource edits, and
contributes a request-context note naming enabled servers.
=src/lsp/semantic-proposals.lisp= retains bounded conversation-scoped edit plans
and compiles ordered server proposals into resource change sets.
=src/lsp/semantic-tools.lisp= registers semantic request, preview, resolution and
apply operations. Each affected path is authorized and revalidated before
application; annotated confirmations use the command-authorization boundary.

  Each registry owns one lazy manager. Registries create it and its tools only
  when =lsp.sexp= enables at least one server. Operations share its recursive
  lock; notification delivery uses the client state lock. Runtime retirement
  closes the manager once through shared runtime identity. Saver-child detachment
  closes inherited descriptors without signaling the parent's language servers.
  Configured executables run as trusted local processes, separately from the
  shell sandbox. Server-driven workspace edits are declined; file changes use
  revision-gated resources. =cl-lsp= encodes language-server file URIs.

** Emacs and Slynk

=src/slynk/endpoint.lisp= owns one process-wide Slynk server serving the active
image on loopback, loaded by exact path from the person's own sly installation.
ACP serving and the terminal session own its lifetime; checkpoints quiesce it
and serve the same port again. Slynk's global debugger, stream redirection and
log output stay off, so Autolith's threads never report into a sly connection.
=src/emacs/server.lisp= speaks the Emacs server line protocol over the
configured Unix socket, with base64 arguments and JSON results.
=src/emacs/resource.lisp= resolves the =emacs:= scheme: =emacs:current= renders
the visible windows, region and file buffers, and =emacs:buffer/NAME= snapshots a
whole widened buffer as a workspace-style observation. Edits reuse the
original-line operations and observation state of workspace files, but publish
by one Emacs request that compares the buffer with the observed text and calls
=replace-buffer-contents=, so concurrent typing makes the edit stale and never
lost. =src/emacs/tools.lisp= holds the action tools, =emacs.visit= and
=emacs.eval=, and registers them with the scheme only while that socket exists.
=emacs/autolith.el= wires both from Emacs.

* Terminal

Autolith uses the primary screen and leaves finalized output in normal
scrollback by default. An opt-in fullscreen terminal UI owns the transcript
viewport in an alternate screen, keeps application scrollback, and pins the
composer to the bottom. The persistent setting is stored in the global
preferences record; =--fullscreen= overrides it for one launch.

- Reasoning previews enter scrollback only once finalized
- Autolith provides semantic styling, candidate policy, terminal mode, and
  emits OSC 133 prompt blocks
- OSC 133: =A= and =B= precede input, =C= starts execution, =D;STATUS=
  closes execution. This way you can rely on smarter terminals
- OSC 0: the interactive window title is =autolith - PATH=. Autolith writes
  it at UI start, after localgroup attach, and after =(cwd "PATH")=.
- Clinedi owns editor state, input decoding, geometry, and live repainting
- The fullscreen viewport owns transcript wrapping, application scrolling,
  reflow anchors, and bottom-pinned composer geometry
- =PageUp= and =PageDown= page through fullscreen history; =Ctrl-Home= and
  =Ctrl-End= jump to its ends, and mouse-wheel events scroll incrementally
- cl-colorist is used for ANSI capability detection
- Text is sanitized before styles are added
- Ctrl-C on an empty prompt exits.

* Live mutation and generations

The =self.*= tools can inspect the active image and install a complete definition.

#+BEGIN_SRC text
journal proposal
   |
   v
compile and install --> checks --> replay script and manifest
                                              |
                                              v
                                  private mutation-history Git commit
                                              |
                                              v
                                  atomically select normal startup state
                                              |
                                              v
                                      journal durable result
#+END_SRC

- Exploratory changes stop after install and journal publication
- =self.diff= shows effective state. =self.exercise= records focused
  evidence. =self.discard= reverses one effective change
- =self.commit= creates a private snapshot, replay-probes it in a clean
  process (the probe loads the script, then asserts the core surface of
  load-bearing functions and classes survived), commits it
  to the separate mutation-history repository, and atomically selects it
- Replay entries record the tracked source they shadowed. Startup replay
  skips and reports an entry whose tracked definition moved since
  publication, so newer tracked code is never shadowed by a stale override
- Checkpoints use =sbcl-generations=. Before the fork, Autolith quiesces
  work, clears credentials, detaches workers, and checks provenance
- Windows cannot fork. Checkpoints and rollback are withheld there, and a
  worker saves its image by exiting through =save-lisp-and-die= and
  restarting from the saved core instead of forking a saver

* Startup, update, and recovery

#+BEGIN_SRC text
stable launcher
   |
   +--> verify runtime and source provenance --> active image
   |                                               |
   |                                               +--> retained generation
   |
   +--> failure --> recovery --> pristine exact-source checkout
   |
   +--> explicit generation or rollback --> recovery --> retained generation
#+END_SRC

- =active-image.lisp= builds the preloaded image for normal startup and for
  every fresh Autolith process, such as pristine =lisp.*= workers
- =script/bootstrap= finds a supported SBCL, builds the pristine recovery
  core and a separate active image, and boot-probes both
- Updates validate provenance and refresh a readable availability cache.
  Startup reads cached state only. An accepted packaged update runs the
  bundled installer and restarts.
- Recovery reports sanitized crash context. Automatic failure recovery boots
  current committed source without private mutations or user init. Explicit
  generation selection and rollback retain their saved-state path
