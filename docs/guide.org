#+TITLE: New User Guide
#+STARTUP: content

* Intro

Autolith is a terminal agent running in a live Common Lisp image. It works on
Linux x86-64, macOS, and Windows x86-64.

Launch Autolith from your terminal:

#+BEGIN_SRC sh
autolith
#+END_SRC

If you haven't authenticated yet, follow the [[file:../README.org][README]] instructions.

Autolith's prompt window can also evaluate Lisp forms directly:

#+BEGIN_SRC lisp
(help)
(resource.read :uri "workspace:.")
(prompt (read-file "review-notes.org"))
#+END_SRC

You can use the same tools and Lisp machinery as the clanker.

Slash syntax is optional syntactic sugar for command forms, for example
=/status= for =(status)=.

Type =(=, =[=, or ={= in the composer to insert a matching pair with the cursor
between the delimiters. Type the closing delimiter to move past it, or press
Backspace between an empty pair to delete both.

Press =Tab= to complete operation names, finite options, and workspace paths.
Use =Shift-Tab= to step back through the suggestions. With nothing to complete,
press =Tab= to send the input like Enter, or queue it as a follow-up while a turn
runs. If you press =Tab= while typing an unfinished form such as
=(job.continuity :=, nothing happens. Finish the form before submitting it.

The work indicator displays =REPL= with one letter highlighted in sequence.
Use =(settings :transcript-style :repl)= to show messages as a Lisp REPL
exchange, with =>= before yours and =<= before Autolith's. When turn timestamps
are enabled, the time appears on the line above. Set the style to =:labels= to
restore the =❯ you= and =● autolith= headers.

Below the modeline, an activity line names the current work, such as
=pondering=. Hide it with =(settings :activity-line-p nil)= to free that row. The
modeline still shows elapsed time. The activity line is hidden while a response
streams.

* Terminal diagrams

Ask for a fenced =mermaid= block to view a diagram in the terminal. Autolith uses
[[https://github.com/lambda-symbolics/clermaid][Clermaid]] for flowcharts, sequence diagrams, flat state diagrams,
class diagrams, and entity relationships. The library documents the syntax for
each family.
Boxes, connections, arrowheads, and labels use separate theme colors. Graph
layers are centered, with ordered ports and routes that limit crossings. Unicode
diagrams use rounded connection corners and directional end caps.

#+BEGIN_SRC markdown
```mermaid
flowchart LR
  A[Read] --> B[Evaluate]
  B --> C[Print]
```
#+END_SRC

During streaming, view the source in the live tail until the closing fence. Use
the diagram's copy action to copy its original Mermaid source. For syntax outside
the supported subset, or for a diagram too wide for the terminal, read the
ordinary source block instead.

* Command arguments

Pass native Lisp values to commands. Use keyword actions, Boolean switches,
integers, pathnames, and quoted data directly:

#+BEGIN_SRC lisp
(settings :boot-screen-seconds 2)
(settings :onboarding-p nil)
(trace t)
(trace nil)
(mcp :refresh)
(permissions :ask)
(tasks :transcript "ID" :offset 0 :limit 4000)
(tasks :send "ID" :message "Keep the original message intact.")
#+END_SRC

Omit a switch argument to inspect its value. Pass =t= to enable it or =nil= to
disable it. Strings represent text such as objectives, messages, names, and
identifiers. Pass structured arguments as Lisp data, not as source text inside a
string.

* Onboarding

At the opening boot screen, press Space or Enter to start the tour. Press Esc or
begin typing to open the listener instead. Typed and pasted text stays in the
prompt. The lessons are available on the next launch or with =(onboard)=.

On your first interactive launch, try the prompt, =(help)=, background Lisp, and
=(settings)= in the fullscreen tour. Edit the lesson input and press Enter to
check it. Resize your terminal at any point. Use Page Up/Page Down to scroll long
lessons and Shift-Tab to go back. Press Tab to skip one slide, including an
exercise, without changing its settings.

Press Esc to skip the tour. Completed and skipped lesson versions are recorded
in your state directory. Ctrl-C interrupts the tour without acknowledging
unfinished lessons. Later launches show only new or revised lessons. Evaluate
=(onboard)= to replay the whole tour.

Disable automatic tours with =(settings :onboarding-p nil)= or set
=AUTOLITH_ONBOARDING= to =off=. If you disable the boot screen, enter the tour
directly without its opening animation.

* Goals and verified missions

Use =(goal "OBJECTIVE")= for lightweight autonomous work. Inspect it with
=(goal)= or =(goal :status)=. Control it with =(goal :pause)=, =(goal :resume)=,
or =(goal :clear)=. Edit it in place with =(goal :update "NEW-OBJECTIVE")=.
String arguments are literal objectives, including ="pause"=. Unknown keyword
actions signal =application-goal-error= without changing the goal.

Lightweight goals pause after eight automatic continuation turns between user
messages by default. Set =(settings :goal-continuation-limit 16)= to change the
limit, or =(settings :goal-continuation-limit :unlimited)= to remove it. The
setting is durable. A completed lightweight goal permits ordinary session-owned
job-completion wakeups without restarting that goal.

Queued commands and Lisp forms run between goal turns. The goal continues after
that input only when its loop yielded to it. Send a message to continue after
interrupting goal work.

For externally verifiable work, install explicit acceptance policy with
=(mission :start specification)=:

#+BEGIN_SRC lisp
(mission :start
 '(:objective "Deliver the accepted build"
   :turn-limit 40 :token-limit 100000 :wall-seconds 3600
   :criteria ((:id "build" :description "The build passes" :gates ("build"))
              (:id "review" :description "The user accepts the result"))
   :gates ((:id "build" :kind :command :command "make check"
            :inputs ("Makefile" "src/main.lisp") :deterministic-p t
            :attempt-limit 3 :timeout-seconds 300))))
#+END_SRC

Use =(mission :run)= to begin, =(mission :status)= to inspect the complete durable
state, and =(mission :verify)= to request harness verification. The model can also
call =mission.status=, =mission.verify=, =mission.stop=, and
=mission.invalidate=. Only the primary agent may change mission policy through
these model operations. Configure acceptance criteria yourself. The model cannot
weaken them or supply user acceptance.

Each criterion has a unique =:id=, a =:description= and optional ordered gate
IDs in =:gates=. Criteria without gates require your explicit evidence:

#+BEGIN_SRC lisp
(mission :accept "review" "I inspected the artifact and accept the result")
(mission :resume)
(mission :verify)
#+END_SRC

The model's completion marker requests verification. A passing gate proves only
the criteria you linked to it. Verification requires every gate and criterion.
Inspect the acceptance mapping before you begin work.

The turn allowance counts provider inference calls from the primary agent,
children, compaction, and recursive inference. This includes mapped and nested
frames. Reported billable tokens use the provider API's usage normalization and
exclude known prompt-cache reads.

Admissions and settlements are serialized within a mission, but provider requests
run concurrently. Each admission reserves one turn and an output allocation from
the unspent, unreserved tokens. The allocation normally divides those tokens
among the remaining turns; an explicit provider output cap replaces that split.
Reviewer requests reserve from both allowances. Settlement releases the
reservation and charges reported input and output usage. Measured usage can
therefore exhaust the token allowance.

When an admitted child request reports no usage, Autolith charges its full finite
reservation once, if it can identify the exact child and reservation. This covers
length failures, HTTP 429, cancellation, and interrupted dispatch. The child's
failure and UNKNOWN audit are retained.

The =:reservation-charged-tokens= field is included in =:tokens-used=, not added
as separate spend. The =:reservation-charges-by-child= field records request
counts and token charges. Child terminal results retain =:unknown-usage=,
=:reservation-charged-tokens= and =:reservation-charge-requests=; =:usage=
contains only provider-reported usage. This bounded settlement leaves no
unresolved UNKNOWN in the shared mission. Subsequent primary inference, new
children and scheduled continuations use the same mission, with its remaining
budget, deadline and identity checks.

The reservation charge is an accounting rule. It is not measured usage, a limit
on provider billing, or a wire limit. Input tokens and repeated generations can
exceed it. Codex does not enforce a wire output ceiling at the current library
pin. A successful retry uses only its final reported usage and does not reconcile
earlier unreported attempts.

If Autolith cannot establish exact child ownership and a finite reservation,
missing usage stays unresolved. Under the default policy, unresolved child usage
prevents further inference and new child work before dispatch; non-spending
continuation and already-reserved requests may finish. Missing root usage or
uncertain ownership blocks new work. Recovery cannot reconstruct per-request
child bounds from aggregate reservations, and restore or continuation never
reclassifies an existing unresolved UNKNOWN.

To continue despite missing provider usage, explicitly select
=:unknown-usage-policy :record= when starting a mission:

#+BEGIN_SRC lisp
(mission :start
 '(:objective "Run the periodic checks"
   :turn-limit 10000 :token-limit 10000000 :wall-seconds 86400
   :unknown-usage-policy :record
   :criteria ((:id "checks" :description "The user accepts the checks"))))
#+END_SRC

With =:record=, unbounded failed requests and interrupted requests recovered
after restart increase the durable =:unknown-usage= counter without blocking
solely for missing usage. Exact-child finite reservation charges still apply.
Turn and wall-clock limits apply exactly; token accounting includes reported
usage and conservative reservation charges, not all unreported provider tokens.
Independent reviewers still require reported usage. The default =:block= also
applies to older mission records without a policy. Choose the policy once at
mission start; an existing blocked mission is not changed or resumed automatically.
To opt in for existing work, start a new mission with its acceptance criteria and
budgets and add the policy key. Large integer limits are finite, not an
unlimited-mode switch.

The wall-clock deadline includes gate execution, delegated tools, pauses, and time
away. Work runs under cl-jobpond supervision. Use =(goal :pause)= and
=(mission :resume)= without resetting the mission budget. Use
=(mission :cancel "REASON")= to terminate it.

Terminal states are =verified=, =exhausted=, =cancelled=, and =failed=. A =blocked=
mission keeps the evidence needed to resolve its blocker and resume. With the
default =:block= policy, interrupted inference becomes blocked when its usage
cannot be recovered. Gate attempts, fingerprints, and evidence restore with the
conversation and survive compaction independently of model summaries.

Gates run in order and stop at the first failure. Command gates use the ordinary
shell authorization and sandbox boundary. Artifact gates require =:path= and
optionally accept an expected =:sha256=. Lisp gates require a =:predicate=
string and run an assertion in the existing isolated Lisp worker.

Every gate supports =:timeout-seconds= and a separate =:attempt-limit=. The
defaults are 60 seconds and three executions. Each gate keeps bounded evidence.

For deterministic gates, declare all relevant file paths in =:inputs= and set
=:deterministic-p t=. File contents and missing-file states form the fingerprint;
directory paths are rejected. Unchanged passing gates supply current proof, and
unchanged failed gates are withheld while the model works on their relevant
inputs. For remote state, omit deterministic policy or invalidate a particular
gate explicitly:

#+BEGIN_SRC lisp
(mission :invalidate "build" "The remote build configuration changed")
#+END_SRC

Invalidation permits another execution without replenishing its attempt budget.
Before acceptance, every gate fingerprint is checked again under the workspace
mutation lock. Changes from a later gate invalidate earlier passing evidence.
Collect terminal results and outstanding inference usage before verifying.

** Independent review checkpoints

Attach a reviewer to an active mission with =mission-review.configure=, or evaluate:

#+BEGIN_SRC lisp
(application-mission-review-configure
 *active-application*
 '(:id "release-review" :phase :final-acceptance
   :inputs ("src/main.lisp" "tests/main-tests.lisp")
   :context "Review the changed behavior and test coverage. Report concrete findings."
   :turn-limit 4 :token-limit 16000 :run-limit 3))
#+END_SRC

Declare the complete relevant file set. The reviewer receives an independent
snapshot and background, returns contracted findings, and has no tools or spawning
permission. Reviewer call and token allowances are cumulative across changed
snapshots and also count against the mission allowances. =:run-limit= bounds the
number of distinct snapshots reviewed.

Use =mission-review.trigger= with =id= to review a checkpoint and
=mission-review.inspect= to read its durable findings, decisions and usage.
Unchanged snapshots reuse completed, failed or interrupted runs. Resolve or reject
each finding through =mission-review.decide= with =id=, =finding=, =decision=
(=resolve= or =reject=) and an evidence-bearing =reason=. Only the primary agent
or local user may configure, trigger and adjudicate reviews.

Final verification runs configured =final-acceptance= checkpoints. Pending
findings and failed or interrupted reviews block acceptance. For
=before-integration= and =after-edit-set= checkpoints, trigger the named review
explicitly at the chosen boundary. Reviewer findings are advisory; mission gates
and user acceptance supply harness evidence.

** Scheduled mission continuations

Attach explicit wakeups to the current mission with =mission-schedule.add=.
Supply an immutable =id=, continuation =content=, and one time policy. =at= is an
absolute Common Lisp universal time. =interval= is a positive number of seconds.
=event= names an external event instead. For example:

#+BEGIN_SRC lisp
(application-mission-schedule-add
 *active-application* :id "build-followup"
 :content "Check the pending build and continue the mission."
 :at (+ (get-universal-time) 300) :missed-policy :latest)
#+END_SRC

For recurring wakeups, choose =missed-policy= =latest= (the default), =all=, or
=skip=. These select the newest missed occurrence, every missed occurrence, or
only an occurrence due at exactly the current time. Use =mission-schedule.event=
with an event name and stable external event =id=; repeated delivery of that ID
is deduplicated. The local daemon listener hosts time wakeups. Due work enters
the ordinary primary command queue as a persisted =(mission-wakeup ticket)=
command, with a structured ticket, and runs as a mission continuation under the
existing turn, token, and wall-clock budgets.

Only the primary agent may use the =mission-schedule= tools. Each wakeup keeps
its exact mission identity and version. Both are checked at admission and
execution.

While the mission is paused or blocked, the missed policy skips due occurrences
without running them. The interval advances. After a resume, the next due
occurrence arrives without recreating the schedule. Skipped occurrences are not
replayed, including one-shot wakeups and deduplicated events. With the default
=:block= policy, unknown usage prevents mission resume. =:record= does not prevent
an independent pause or blocker from resuming.

Replacement, a version change, or a terminal mission (verified, exhausted,
cancelled, failed or legacy complete) cancels the schedule. Skips and automatic
cancellations produce persisted user notices. Use =mission-schedule.inspect= to
read schedules, occurrence IDs, claim tokens and outcomes: skipped occurrences
have =state= =cancelled= with =result= =(:skipped <mission-status>)=; obsolete
mission work has =result= =:stale-mission= and a cancelled schedule. Use
=mission-schedule.cancel= with the schedule =id= to cancel future and pending work.

Interrupted admissions and executions restore as uncertain outcomes. Inspect the
external effects before calling =mission-schedule.resolve= with the readable
=occurrence= ID, current =token= and =action= =completed=, =failed= or =retry=.
Retry is an explicit decision and is refused while the occurrence is executing.
Cancellation retains claim and duplicate history.

* Editor sessions over ACP

Configure your ACP-compatible editor to launch:

#+BEGIN_SRC sh
autolith acp
#+END_SRC
Authenticate the selected provider with =autolith auth= before starting the
editor session. ACP uses UTF-8 JSON-RPC on stdin/stdout; diagnostics go to stderr.
A normal launch loads durable mutations and user initialization. For AUI, use
=autolith --permissions auto acp=. Use =--pristine= when recovering from a
damaged mutable image.

New sessions use the editor's absolute working directory and a durable Autolith
conversation ID. Load that ID to replay messages, visible reasoning, tool calls,
and results. Text prompts, resource links, and embedded text resources are
supported. File and process operations use the native Autolith tools.

The default =ask= mode requests command and external-tool approval in the editor.
An approval covers the exact command and working directory, or the external tool
identity and arguments. Select =auto=, =sandboxed=, or =full-access= through ACP
session modes; use =--permissions auto|sandbox|full= on the command line. Changing
modes clears session approvals.

Client-supplied stdio and HTTP MCP servers are merged with native registrations
for that session. Literal environment values and headers are ephemeral and
redacted from server output.

Cancel a prompt to stop its provider, tools, and owned jobs. Close the session or
disconnect to release its resources and lease.

Each ACP process runs one primary prompt, setting mutation, tool invocation, or
session setup at a time. Catalog reads and owned-job controls can run alongside it.
Ctrl-C ends an ACP process with status 130 after releasing its sessions.
** Remote clients

=autolith acp --http= serves remote clients at =/acp= over the transports in the
ACP proposal "Streamable HTTP & WebSocket Transport": Streamable HTTP over
HTTP/1.1 or cleartext HTTP/2, and WebSocket. =autolith acp --websocket= serves
WebSocket alone. Both listen on =127.0.0.1:8737= by default. Give a port, or a host
and port, to change that:

#+BEGIN_SRC sh
autolith acp --websocket 9000
autolith acp --http 0.0.0.0:8737 --token "$ACP_TOKEN"
autolith acp --http [::1]:8737
#+END_SRC

Autolith prints the endpoint URL on stderr and serves until Ctrl-C. Each client
gets its own sessions. All clients share one primary operation in the process, so
one client's running prompt makes another client's prompt return busy.

With =--token=, a client must send =Authorization: Bearer TOKEN= or add
=?token=TOKEN= to the URL. Other users of the machine can read a token on the
command line. Requests from web pages, which carry an =Origin= header, are refused.

Any host other than loopback makes the agent reachable from other machines.
Autolith warns that the endpoint is not secure. Traffic, including the token, is
unencrypted. Put a TLS reverse proxy in front of it and use a token.

** Typed client extensions

Request =_autolith/capabilities= to discover installed methods and schema version.
Include =sessionId= in every other extension request. Responses contain =outcome=
(=ok=, =condition=, =busy=, =unsupported=, or =cancelled=), with =value= on success
and a bounded =report= on failure. Unknown measurements are JSON null.

| Method suffix | Value or action |
|---------------+-----------------|
| =state= | Session, turn, model, permission, usage, plan and health snapshot |
| =settings=, =models=, =operations= | Typed catalog =items= |
| =set-setting= | Set =name= to =value=; return the updated setting row |
| =invoke= | Invoke =operation= with JSON =arguments=; return presented =text= |
| =steer=, =queue= | Durably admit primary =text=; return =accepted= and =delivery= |
| =conversations= | Page durable conversations using =limit= and =cursor=; optionally filter =cwd= |
| =jobs=, =job= | Page owned jobs or inspect one =jobId= |
| =job-transcript= | Read =jobId= with =offset=, =limit= and =output= (=text= or =structured=) |
| =job-send=, =job-cancel= | Send =text= to or cancel an owned =jobId= |
| =resource= | Read bounded =workspace:= lines or =shell-log:= bytes from =uri= |

Prefix these suffixes with =_autolith/=. Catalog operations expose admission and
availability; tools use their native decoders and ACP approval callbacks.
Terminal-only operations return an explicit unsupported outcome. Workspace resource
windows use =startLine= and =lineCount= and include the observed revision. Shell-log
windows use =byteOffset= and =byteCount= and require session ownership.

Invoke ordinary commands with =arguments: {"input": "..."}=, using slash-command
text without the command name. =text= is an alias for =input=. Commands such
as =skills=, =hurry-up= and =papercuts= return their presented text. Operations with
=terminalWithoutArguments= require an argument to avoid a terminal picker. During
an active turn, native inspection and execution policies apply; boundary-applied
commands return =delivery: "scheduled"= and present their results as ACP updates.

=steer= delivers text at the next safe boundary, including submissions made while
an approval is pending. Late steering is promoted ahead of ordinary queued
follow-ups. =queue= appends a follow-up for the next available primary turn.
Both accept up to 262144 characters and return =delivery: "steering"= or ="queued"=.
Display accepted input separately until its durable =user_message_chunk= arrives.
Cancellation pauses pending input; a new submission resumes it. Accepted input
survives session close and reload. ACP has no per-item withdrawal operation.

For structured child transcripts, =value.updates= contains ordinary ACP
SessionUpdate bodies, with messages, reasoning, tool calls and result content.
Offsets count updates from zero; the default limit is 100 and the maximum is 200.
The typed response envelope is bounded to 262144 UTF-8 bytes. A single update over
that bound returns a condition instead of advancing the cursor. =nextOffset= is
JSON null when =complete= is true, meaning the current snapshot is exhausted.
For a running child, poll again from =total= to read later updates. Text output
uses character offsets and retains its existing numeric end cursor.

Treat =_autolith/event= state and catalog notifications as invalidation hints.
Refetch the affected snapshot after a sequence gap. Events with kind =turn= are
ordered lifecycle boundaries: =data= contains =state= (=running= or =idle=), an
integer =epoch=, =source= (=prompt=, =queue=, =completion=, or =invoke=), and a terminal
=outcome= (=end-turn=, =cancelled=, or =condition=; null while running). Match the
epoch when handling approvals, cancellation and transcript boundaries.

Automatic job continuations stream through ordinary ACP updates. Cancellation or
an inference failure pauses continuation; submit an explicit prompt to resume.

* Emacs and sly

Autolith's image can be your Common Lisp development image. =emacs/autolith.el=
in the source tree sets up one frame with three windows: your code, a sly REPL
connected to Autolith's own image, and an agent-shell conversation with the same
Autolith. What you define in the REPL lives beside the agent, which can inspect
it and advise.

The sly REPL spans the bottom quarter of the whole frame. Above it, edit code
on the left and converse in the right third.

Install sly and agent-shell, load the file, and run =M-x autolith-ide= from the
buffer you are editing:

#+BEGIN_SRC emacs-lisp
(load "/path/to/autolith/emacs/autolith.el")
#+END_SRC

Optional Sly contribs need their Lisp dependencies in Autolith's image. For
=sly-stepper=, install =agnostic-lizard= in a persistent ASDF source registry
visible to the Autolith process before Slynk starts.

=autolith-ide= starts the Emacs server if needed and launches =autolith acp=
through agent-shell with three environment variables:

- =AUTOLITH_SLYNK_DIRECTORY= is your sly's own =slynk/= directory, so the server
  speaks exactly your client's protocol. Autolith loads that =slynk.asd= by path
  and compiles it into the ASDF cache on first use.
- =AUTOLITH_SLYNK_PORT_FILE= receives the loopback port once Slynk listens, or
  =error: REASON= when it cannot start. =autolith-ide= waits for it, up to
  =autolith-slynk-timeout= seconds, and connects sly.
- =AUTOLITH_EMACS_SERVER= is this Emacs's server socket and enables the
  =emacs:= resources and =emacs.*= tools.

=M-x autolith-agent-shell= starts only the conversation, with Emacs access and
without Slynk. The same variables, or the =:slynk-directory=,
=:slynk-port-file= and =:emacs-server-socket= settings, work outside Emacs. In
the terminal, =(slynk)= starts Slynk and shows the port for =M-x sly-connect=,
and =(slynk :stop)= closes it.

The agent reaches your definitions with =lisp.describe=, =lisp.source= and
=lisp.apropos= using target =self=, or with =self.eval=. While Slynk serves, a
context note tells it so. Your Emacs appears to the agent only while the
configured server socket exists:

- =emacs:current=, read with =resource.read=, lists authorized visible windows
  with point, the active region and open file buffers, each by its
  =emacs:buffer/NAME= URI. Outside-root files and non-file buffers require
  full-access approval; denied buffers are omitted from this snapshot.
- =emacs:buffer/NAME= is a live buffer's text, unsaved edits included, with the
  buffer name percent-encoded. =resource.edit= applies line operations to the
  buffer itself: the change stays unsaved and undoable, and is refused as stale
  when you edited the buffer since the agent read it. A buffer visiting a file
  outside the workspace and source roots asks the same permission as that path.
- =emacs.visit= shows a file position in a file window of the selected frame.
- =emacs.eval= evaluates Emacs Lisp. It asks command authorization for
  =emacs.eval -- FORM= and runs only with full access.
Slynk listens on =127.0.0.1= only. Like ordinary sly, it has no authentication
beyond the optional =~/.sly-secret=. Anyone who can reach loopback on this machine
can evaluate in the image. Your code shares the agent's heap: a fatal error or
=(sb-ext:exit)= ends the session, which recovers like any crash.

Slynk's debugger and output hooks stay off for Autolith's own threads, so your
REPL sees only your evaluations. A checkpoint stops Slynk and closes sly
connections, then serves the same port again. Reconnect with
=M-x autolith-ide-reconnect=. A checkpoint waits for in-flight sly evaluations
and fails if they exceed the shutdown timeout.

* Fullscreen terminal

Autolith uses the ordinary inline terminal presentation by default. Opt into the
application-owned fullscreen viewport for a session with:

#+BEGIN_SRC sh
autolith --fullscreen
#+END_SRC

Save the preference for future launches at the Autolith prompt:

#+BEGIN_SRC lisp
(preferences-set-fullscreen (application-configuration *active-application*) t)
#+END_SRC
In fullscreen mode, scroll the transcript above the bottom-pinned composer,
modeline, command, RLM, and task activity rows. Use =PageUp= and =PageDown= for
page movement. Use =Ctrl-PageUp= and =Ctrl-PageDown= to jump between user and
assistant messages while skipping reasoning and tool activity. Use =Ctrl-Home= and
=Ctrl-End= for the oldest and newest transcript positions, and the mouse wheel
for incremental scrolling. In a terminal attached to a hosted channel,
=Ctrl-T= hides and shows the channel sidebar; see Local sessions. A message
jump places the end of the message on the row above the composer. If the
message is taller than the window, its header appears at the top instead. The
=--fullscreen= option enables fullscreen for one
launch without changing the saved preference.
Pass =nil= to =preferences-set-fullscreen= to return future launches to inline
mode. Because the viewport owns the mouse, hold =Shift= while dragging to select
text with the terminal emulator. Fullscreen history lives in the application,
not the terminal emulator's native scrollback. The viewport keeps about four
million characters of recent output in memory. At the oldest retained row, the
legend shows =(history)=. Run =(history)= to load a page of older output.

For input with matching saved memories, a dim =@ N relevant memories exist= line
appears below your message. Its count is the number offered to the model for that
request, followed by how many of them are stale or unverified (see the Memories section).
Each input gets one notice across tool calls and provider retries.

Input recall includes every user message, command, and Lisp submission in the
conversation. Automatic messages and assistant output are excluded. On first use,
the complete input-only sidecar is built from the conversation records; later
submissions are appended to it. Resuming reads this sidecar instead of replaying
archived transcript chunks. If cache storage is unavailable, recall streams the
conversation records directly. The editor keeps the newest 500 inputs, up to a
million characters, in memory. Moving past the oldest of them loads the
next older page, and leaving history recall releases it again.

Clicking a web address in the fullscreen transcript opens it in the default
browser, and every fenced code block ends with a =⧉ copy= label that copies the
block's source. Copies go to the host clipboard through wl-clipboard, xclip or
xsel, pbcopy, or the Windows clipboard, and the terminal also receives an OSC 52
request, so a terminal reached over SSH or a localgroup relay copies on your own
machine. Web addresses in every mode are emitted as OSC 8 hyperlinks, which
terminals open with their usual modifier-click.

Clicking a tool call's header in the fullscreen transcript inserts its Lisp
invocation, such as =(resource.read :uri "file:///tmp/notes.org")=, into the
composer at the cursor. Submitting it alone repeats the call with the same
arguments; editing it first runs a similar call; writing around it asks the
model about that exact call. Arrays are spelled as =(vector ...)= and objects
as =(dict ...)=, and argument names with uppercase letters keep their case as
=:|filePath|= or a string key.

In fullscreen mode, a pending tool call starts with =▸=. When it finishes, the
same header shows a green =✓= for success or a red =!= for failure. Errors
appear beneath the original invocation and arguments. Background handoffs keep
=▸= until completion. Thanks to @rgbcube for suggesting these outcome markers.

Interactive sessions report their root status with the
[[https://www.superlogical.com/rex/docs/build/program-status][OSC 7501 Program Status Protocol]], with =app=autolith=. Reports use =idle=
at startup, =working= during foreground input and resumed model turns, =done=
after success, and =error= after failure. Cancellation returns to =idle=.
Completion status persists until the next input or model turn starts.
Input selectors report =blocked= with =kind=question=;
command and tool approvals use =kind=permission=, and provider authentication
uses =kind=auth=. These reports contain no prompt text or credentials. Reports
use the interactive terminal transport in inline and fullscreen mode.

Root reports include the current conversation title. Child agents and background
tool jobs use independent =jobs/<execution UUID without hyphens>= records for
the same conversation. Queued and running jobs report =working=; completed,
failed, and cancelled jobs report =done=, =error=, and =idle=. Titles use job
names or tool descriptions, with control characters removed and a 192-byte
UTF-8 limit. Reports contain no assignments or result text and no estimated
progress percentages.

Autolith retains at most 63 job records and reserves capacity for active jobs
before completed history. It sends changed records and clears removed records.
After an OSC 133 prompt-start marker, it replays active records only.
Disconnecting the job observer clears its records. Terminal presentation depends
on the terminal.

Fullscreen startup presents a brief Lisp-machine boot screen with a centered tip
and a rock mascot that adapts to short viewports, then the session banner and
transcript above the composer. Mouse wheel scrolling also works through a
controlling local-session attachment.

The boot screen then waits for =Space= or =Enter= before opening the listener,
rotating the startup tip every ten seconds while it waits. =Ctrl-C= on the
waiting boot screen halts the session. Turn the wait off for future launches
with =(setf (config :boot-screen-linger-p) nil)= or for one launch with
=AUTOLITH_BOOT_LINGER=off=, and change the rotation with
=(setf (config :boot-screen-tip-seconds) 30)= or =AUTOLITH_BOOT_TIP_SECONDS=.
The animation takes =(config :boot-screen-seconds)= in total, 3.5 by default
and also set by =AUTOLITH_BOOT_DURATION=, shared evenly by its phases. Skip the
boot screen entirely with =(setf (config :boot-screen-p) nil)= or
=AUTOLITH_BOOT_SCREEN=off=; =(settings)= lists all four.

* Install, update, and uninstall

** Nix

Nix is the simplest way to install Autolith:

#+BEGIN_SRC sh
nix run github:lambda-symbolics/autolith
#+END_SRC

The first launch builds the Lisp images needed for startup under
=${XDG_DATA_HOME:-~/.local/share}/autolith/nix/images/=.

** Linux binary release

Install the Linux x86-64 binary release with the shell installer:

#+BEGIN_SRC sh
curl -fsSL https://sh.lambda-symbolics.com/autolith | sh
#+END_SRC

The installer verifies the release archive's SHA-256 before extraction. The
checksum must identify that exact archive; malformed or missing checksums abort
installation. The initial shell script is fetched over HTTPS.

Read [[https://sh.lambda-symbolics.com/autolith][the installer]] before piping it to a shell, or use Nix if that
tradeoff is unwelcome. Linux binary releases require OpenSSL and Bubblewrap.
Bubblewrap provides the filesystem and network isolation used for sandboxed
command execution. The installer names the missing dependency instead of
installing a release that cannot offer sandboxed or safe automatic execution.
The launcher uses the installation layout, rather than an environment marker
alone, to distinguish binary, Nix, and source starts.

Autolith automatically checks for updates at most once every 20 hours.
To install the latest binary release and exit without starting a session:

#+BEGIN_SRC sh
autolith update
#+END_SRC

The command exits successfully when updated or already current, and returns a
nonzero status if checking or installing fails. =autolith --update= is an
equivalent update-and-exit alias. Run =autolith= afterward to start the new
release. Both spellings accept =--help= or =-h=; extra arguments exit with status
64 before checking for updates. Use your flake or Nix profile to update Nix
installations; update the checkout and run =./script/bootstrap= for source
installations. These installations explain their update mechanism without
building or starting Lisp images.

To update from a session and restart it with its original command arguments:

#+BEGIN_SRC lisp
(update)
#+END_SRC

Release archives are built and checked by the installer host. GitHub publishes
release metadata after the host checksum is available. See
[[file:release-service.org][Release service]].

** Source checkout

For a fresh macOS machine:

#+BEGIN_SRC sh
brew install sbcl rust cmake pkg-config openssl@3
curl -o /tmp/quicklisp.lisp https://beta.quicklisp.org/quicklisp.lisp
sbcl --no-sysinit --no-userinit --load /tmp/quicklisp.lisp \
  --eval '(quicklisp-quickstart:install)' --quit
#+END_SRC

On Linux, also install Bubblewrap with your distribution's package manager.
Autolith uses its =bwrap= executable to isolate the host filesystem and network
for sandboxed commands and the sandboxed decisions made by automatic permission
mode. Nix installations include it. Bubblewrap is not a macOS or BSD dependency.
Without platform sandbox support, the =sandbox= choice is unavailable; explicit
=once=, =always=, and =full= approvals run with the user's full privileges.

With Quicklisp in =~/quicklisp=, bootstrap and check the checkout:

#+BEGIN_SRC sh
./script/bootstrap
./script/check
#+END_SRC

The check runs FiveAM tests in isolated SBCL processes, defaulting to the available
logical CPU count (one worker if detection fails), and verifies the pristine
recovery image. Each run first saves an active image of the checked source.
Tests that launch another Autolith process boot that core instead of loading the
system from scratch. List or select test suites and individual cases with:

#+BEGIN_SRC sh
./script/check --list
./script/check --suite workspace-resource --suite fixtures
./script/check --test test-workspace-file-resources --jobs 1
./script/check --jobs 8 --timeout 900
#+END_SRC

Selected runs skip recovery probes. Selectors are exact, case-insensitive names
and can be repeated; unknown names fail. =--jobs= controls process concurrency,
and =--timeout= sets the deadline per worker in seconds (default 600). Results
include per-case timings and the slowest cases. =AGENTS.md= documents test
registration, reusable fixtures, and interactive Lisp entry points.

To put a checkout into =PATH=:

#+BEGIN_SRC sh
mkdir -p ~/.local/bin
ln -sfn "$PWD/bin/autolith" ~/.local/bin/autolith
#+END_SRC

Make sure =~/.local/bin/= is in your =PATH=.

** Windows

For the Windows x86-64 development artifact, extract the archive into a writable
folder and run =.\bin\autolith.cmd= from PowerShell. Use Windows 10 version 1903
or newer. The bundled SBCL executable has a UTF-8 process manifest for Unicode
paths; system-wide locale changes and 8.3 filenames are unnecessary. The first
launch builds per-user cores under =.autolith-images= beside the release.

To build the source checkout, install Git for Windows, Rust with the MSVC toolchain
and Cargo, and Quicklisp under =%USERPROFILE%\quicklisp=. Put =clang= on
=PATH= for the ColorLisp syntax library. An SBCL 2.6.6 or newer on =PATH= is
used when present; otherwise the bootstrap downloads the official SBCL Windows
binary pinned in =sbcl-windows-releases.sha256=, verifies its SHA-256, and
unpacks it below the data root without registering it with Windows. OpenSSL 3
comes from Git for Windows, from =AUTOLITH_OPENSSL_DIRECTORY=, or from a
=native\openssl= directory beside the sources.

From PowerShell, bootstrap and check the checkout:

#+BEGIN_SRC powershell
script\bootstrap.ps1
script\check.ps1
#+END_SRC

=script\check.ps1= takes the same selectors as =./script/check=. Checks that
need FIFOs, forked children, pseudo-terminals, POSIX file modes, or the POSIX
shell are recorded as skipped. To package a Windows archive, install the Windows
SDK (including =mt.exe=) and run =script\package-windows-release.ps1 -Tag VERSION=.
The POSIX release-server scripts are not built on Windows.

Start a session with =bin\autolith.cmd= or =bin\autolith.ps1=; both take the
arguments =bin/autolith= takes. Windows Terminal is the primary console;
legacy consoles without virtual-terminal input are refused with a message.

Windows sandboxed commands use the bundled AppContainer helper. They can write
in the workspace and a private temporary directory, read system applications
and explicit tool directories, and have no network access. Repository metadata
is protected. Bootstrap installs the helper, both compatibility DLLs, and the
Detours license into a content-addressed generation under the private data
root's =native/sandbox/= directory. After validating every file, it atomically
replaces the =selected= record. Older generations are retained. Release archives
contain exactly the selected generation and its relative selector.

Set =CL_EXEC_SANDBOX_WINDOWS_HELPER= to a nonempty executable path to override
the launcher default. Otherwise, the launcher validates the selected bundle and
exports its generation-specific executable path. After source bootstrap, only
launcher-generated defaults are refreshed. Re-run =script\bootstrap.ps1= to
install the bundle when upgrading from a single-helper installation.

Windows supports supervised detached sessions, client-first starts, and exact-heap
restart checkpoints. It withholds fork-based checkpoint saving and the =unix=
management REPL transport.

** Uninstall

To remove Autolith and keep your data:

#+BEGIN_SRC sh
autolith uninstall
#+END_SRC

The launcher lists what it will remove, asks for confirmation, and exits without
starting a session; =--yes= skips the prompt, which is required when no terminal
is attached. It removes the packaged installation and its command link, managed
SBCL runtimes, the active and recovery images, retained generation cores, saved
worker images, Nix image trees, release markers, crash capsules, launcher
pointers, session sockets and leases, provider caches, and the cache root.

User data stays in place: conversations, inference traces, memories, papercuts,
agendas, plans, pending input, private image commits, the mutation journal and
mutation history, permissions, preferences, credentials, and the configuration
root. Stop running sessions first. A source checkout stays as well; delete it
yourself. Nix installations also need the package removed from the flake or
profile. On Windows the launcher prints the folders to delete, because the
runtime in use lives inside them.

* Talk to Autolith

** Prose, Lisp, and commands

Ordinary text is a prompt to the primary agent. It is equivalent to:

#+BEGIN_SRC lisp
(prompt :to 'autolith "Review this change")
#+END_SRC

=autolith= is reserved, case-insensitively, for the primary agent.

Omit =:to= to address the primary agent:

#+BEGIN_SRC lisp
(prompt "Shut yourself down homie")
#+END_SRC

=prompt= can also compute text or attach local images:

#+BEGIN_SRC lisp
(prompt (read-file "request.org"))
(prompt :images "/tmp/diagram.png" "Review this diagram")
(prompt :to 'test-review "Run focused tests and report failures.")
#+END_SRC

If you message a child agent, it can respond to you in the main conversation
thread if it wants to.

Start a message with =(= to evaluate it as Common Lisp in the active image:

#+BEGIN_SRC lisp
(help)
(resource.read :uri "workspace:.")
(eval-now (setf *print-pretty* nil))
#+END_SRC

Use =(help)= for a short overview. Choose a topic or look up one command:

#+BEGIN_SRC lisp
(help :conversations)
(help :workspace)
(help 'resume)
(help "lisp.eval")
#+END_SRC

Keyword topics open sections. Quoted symbols and strings open command or tool
help, including usage and parameter descriptions. Browse tools by namespace with
=(help :lisp)=, list all commands with =(help :commands)=, or request the full
reference with =(help :all)=. Help uses the terminal Markdown renderer and Lisp
syntax highlighting.

Press =Tab= after =(help = to browse topics and registered operations. Command
options also appear after a command name and a space, for example =(ste =.

Type =@= in prose or inside a Lisp string to fuzzy-search workspace files
through fff. Accepting a match inserts the path and drops the =@=.
Directories keep a trailing slash so you can keep completing. A completed
file stays in the draft.

The clanker receives your Lisp source and its evaluated result. The form also
has its usual effects in the active image.

Local Lisp results use syntax highlighting and width-aware pretty printing.
Small values fit on one line; longer property lists use aligned keyword/value
rows. Each returned value has its own =⇒= marker. Captured output appears in a
separate section. Large or circular values use bounded previews.

Direct tool results use report text without string-literal wrapping. Native
S-expression reports from task, job, and mission tools use the Lisp formatter,
with parentheses, tagged roots, and fields intact. Ordinary strings use Lisp
string notation. Tool calls return their usual values, so
=(list (task.agents))= produces a list containing the report string. Copied or
modified report strings also use string notation. Synchronous and asynchronous
evaluation retain the same display text for replay.

Provider tool calls show parenthesized names, such as =(shell.run)=, with Lisp
keyword labels, such as =:directory= and =:timeout-seconds=. Short argument tables
fit inside the parentheses on one line; wider calls use aligned rows below the
name. Shell commands and Lisp source appear in highlighted rails directly below
the arguments, without a blank row between them.
Consecutive single-line tool success messages share a block without blank rows.
Consecutive single-line calls to the same tool also share a block without blank rows.
Unified diffs in captured output use the ordinary output rail, with their
original change prefixes and indentation.

Start input with =?= followed by whitespace to evaluate one form asynchronously
in the active image. Use this for a blocking operation or a bare variable:

#+BEGIN_SRC lisp
? *package*
? (progn (sleep 10) (values :finished 42))
#+END_SRC

The editor displays =?= in place of the normal prompt. Submit with Enter, then
continue using the session while the form runs. =??= and =?text= are chat;
spaces, tabs, and line breaks after =?= select asynchronous Lisp. Continue an
incomplete form on another line as with ordinary Lisp input.

Inspect or cancel the returned =exec:N= job with =job.get=, =job.wait=, or
=job.cancel=. The bare number works too, as in =(job.cancel :id 1)=, while
exactly one visible job ends in =:1=; otherwise the error lists the candidates.
Standard output, error output, and Lisp diagnostic streams are
captured with bounded retention and rate-limited, sanitized terminal display.
On completion, receive all returned values or the error, together with captured
output. Asynchronous evaluation uses noninteractive error handling and EOF input
rather than a restart picker.

The submitted form and its eventual result are retained in the originating
session, including across a session switch. The model receives these messages
at a safe request boundary; submitting a form does not start a model turn.

When local Lisp or an interactive command signals a serious condition, the
restart debugger keeps the signaling stack and its live restarts available. Use
=Ask Autolith why this failed= to run an independent diagnosis while the failed
operation remains suspended. Diagnosis can offer up to three explicitly selected
recoveries that invoke a live restart, run repair source first, retry the whole
operation, return replacement values when supported, or abort the operation.
Retry does not roll back effects completed before the failure.

The debugger shows the condition type and report, followed by available details
such as the offending value, expected type, operation, filename, and reader
location. These fields come from the condition itself and are also included in
model diagnosis.

Escape during diagnosis cancels only the diagnosis and returns to the live
restarts. Escape at the ordinary restart picker aborts the failed operation.
During an active provider turn, Escape cancels the turn and continues queued
steering in submission order, oldest first. Ctrl-C cancels and pauses queued
work until you submit input; a second interrupt within the force-exit window
exits the application.

** Parking and editing queued input

Run =(vault-store)= to move queued work and unconsumed steering into the recovery
input vault immediately, including during an active turn. Active work continues.
Use =(vault-contents)= to read the parked entries in restoration order and =setf=
to replace the whole list or one zero-based entry:

#+BEGIN_SRC lisp
(vault-store)
(vault-contents)
(setf (vault-contents 0) '(:message "Revised task"))
(setf (vault-contents) '((:message "First task") (:lisp "(+ 1 2)")))
(vault-restore)
#+END_SRC

Entries are =(:message INPUT)=, =(:command TEXT)=, =(:lisp SOURCE)=, or
=(:native-lisp SOURCE)= for noninteractive scheduled wakeups.
Pending snapshots store scheduled wakeups in a separate section ignored by
releases before 0.67.9; after a downgrade, only those wakeups are omitted.
Direct vault reads and top-level =setf= forms containing only =vault-contents=
places execute during an active turn. Returned lists are detached snapshots;
publish edits with =setf=. Use =(setf (vault-contents) nil)= to clear parked input.
Run =(vault)= for a summary or =(vault-restore)= to prepend parked work to the
live queue.

** Managed resources

=resource.read= observes durable state and returns an opaque revision.
=resource.edit= applies a resource-specific operation only against that exact
observation.

For multi-file semantic changes, Autolith prepares a =cl-resources= change set
against retained file revisions and validates every member before publication.
Each file is published atomically. On a later failure, Autolith restores earlier
members; conflicting external updates require explicit recovery rather than
replacement. File moves preserve source permissions captured during staging.

Papercuts report concrete defects or repeated friction in the running Autolith
harness or its tools. Record project source bugs and test, build, or CI failures
in the task plan or agenda, even when developing Autolith itself; use a project
tracker only when authorized. A project failure alone is not evidence of a
harness defect. Papercuts are not progress reports or records of ordinary
uncertainty.

Papercuts use current-workspace resource URIs:

- =papercut:current= lists active reports and accepts =papercut-report=.
- =papercut:id/<percent-encoded-stable-id>= reads one active report and accepts
  =papercut-close= with a complete resolution.

The existing =papercut.report= tool and =(papercuts)=, =(papercut "ID")=, and
=(papercut-close "ID")= commands remain convenient direct interfaces.

Each model papercut report is acknowledged durably in the conversation. Repeated
reports return the existing workspace papercut instead of creating another one.
Reports match by an identical title, or by substantial overlap in the title and
body with a report from the last day. A conversation re-filing its own report
within an hour uses a looser match to catch rewritten repeats.

Conversation history uses read-only resource URIs:

- =conversation:current= is the current conversation's complete durable
  history, including the records compaction removed from the model context.
  A plain read returns the newest records; =start-sequence= and
  =record-count= (default 20, maximum 200) page by durable record sequence.
  A window holds at most 7,000 characters and shortens long records, so read
  a record alone to see all of it.
- With =query=, the read lists the newest records containing every
  whitespace-separated term, each with its sequence and an excerpt. ASCII
  letters match in either case and other characters match exactly.
  =max-results= defaults to 20 and is capped at 50. Messages, assistant
  replies, reasoning summaries, tool call arguments and outputs, web searches,
  and compaction summaries are searched.
- =conversation:id/<id>= reads or searches another conversation by its
  identifier. Searches never span several conversations.

Channels use read-only resource URIs with the same history arguments:

- =channel:current= describes the current channel, its residents,
  subscribers, workspace and owner, then reads its history like
  =conversation:current=.
- =channel:id/<id>= describes and reads another channel.
- =channel:list= surveys every channel with its residents and subscribers.
  Reading a channel never subscribes the reader.

** Memories

Autolith remembers durable facts, preferences, and decisions per workspace or
globally, and offers the related ones with each request. A memory can record
where it came from:

- a quoted passage of a file, or the whole file;
- your own words in the conversation;
- a web page;
- other memories it was derived from, its premises.

If a cited file no longer contains its quoted passage, or a premise changes or is
forgotten, the memory becomes /stale/. Every memory derived from it becomes stale
too. Restoring the passage makes them current again. Quotes are compared while
ignoring whitespace, so reformatting a file does not stale its memories.

Your words and web pages are provenance: they are never refetched. Once a memory
cites files, those files decide whether it is current. A memory whose only cited
files cannot be read is /unverified/. Status is worked out from the current files
when the memory is listed or recalled. Checking makes no model requests.

#+BEGIN_SRC lisp
(memories)            ; relevant memories, stale ones first
(memories "deploy")   ; only those matching a query
(memory "3afbfa1a")   ; one memory, its evidence, and what relies on it
(forget "3afbfa1a")   ; stop recalling it
#+END_SRC
In fullscreen, open the memory manager with =(memories)=. Browse notes and facts
beside their evidence. On a narrow terminal, press Enter to read the selected
item. Use =/= to search titles, bodies, tags, IDs, and evidence. Use Tab to choose
All/Notes/Facts, and Shift-Tab to choose a scope. Scroll an open explanation with
the arrow keys or Page Up/Down. Press Esc to return to the list, then Esc again
to close.

Press =n= to create a note, =e= to edit one, =d= to forget a note or retract an
asserted fact, and =r= to reload. Confirm deletion with =y=. In the note form, use
Tab to move between title, tags, scope, and content. Use Space to choose a scope,
Shift-Enter for a content newline, and Enter to save. A changed or deleted note
must be reloaded before editing. Editing prose preserves its evidence and premise
versions. Inspect derived facts to find their premises and rules.
=(memory "ID")= opens the corresponding explanation directly.

In inline or noninteractive sessions, these commands print textual listings and
explanations.

Any unique prefix of a memory ID selects it. =(forget)= names the memories
that relied on the forgotten one, which are now stale. Recall flags stale
memories for the model to recheck, replace or forget before use. The recall
notice counts them: =@ 3 relevant memories exist · 1 stale=.

The model records evidence through the =memory:= resources. =memory-remember=
and =memory-replace= accept =sources=, objects naming one =file=, =url=, or
=user= with an optional =quote=, and =premises=, memory IDs. A file quote must
occur in the file and a =user= quote in your messages in this conversation
when the memory is written. Replacing a memory without =sources= or =premises=
keeps the recorded versions, so restating or retagging a stale memory leaves it
stale; supplying them again rebinds it to the evidence as it is now. Workspace
memories record files inside the workspace relatively, so they survive moving
or importing the workspace, and a workspace export includes the global memories
its memories rely on.

*** Facts and rules

Besides prose memories, Autolith keeps structured facts: predicates applied to
typed values, such as =event.start review 2026-10-22T13:00:00Z=. Each fact cites
its evidence and says why it is believed: an /observation/ of a file, page, tool,
or mission; a /user assertion/; an /assumption/; or the model's own /proposal/.
The source decides the basis, not the model's label. A file Autolith read is an
observation. Your words are a user assertion. A web page becomes an observation
when =web_extra.gist= retrieves it with the quoted text.

The retrieval receipt identifies the retrieved content, bounded tool preview, and
observation time. Quotations can cite the complete retained overflow object. If
that storage is unavailable, only text in the retrieved prefix counts. The
omission notice is presentation, not source evidence. A fact stated by two
sources has two supports and holds while either does. Web pages expire after a
week and tool output after a day. Fetch the source again to renew its evidence.
Your statements and recorded runs do not expire.

A structured fact's file evidence applies only to the exact observed content,
even when its quotation survives an edit elsewhere in the file. Review the new
revision and observe it again before using it as current evidence. The original
quotation and digest are kept for historical inspection.

Rules derive facts from facts, with dates, durations, numbers, and quantities
in units:

#+BEGIN_SRC lisp
;; departure = start - (travel + buffer)
(:premises (("event.start" "?event" "?start")
            ("event.travel" "?event" "?travel")
            ("event.buffer" "?event" "?buffer"))
 :bindings (("?leave" ("-" "?start" ("+" "?travel" "?buffer"))))
 :conclusion ("event.departure" "?event" "?leave"))
#+END_SRC
When a premise changes, Autolith recomputes the conclusion locally, without a
model request. Move the meeting and the departure moves with it. A derived fact
keeps the basis of its premises, so a conclusion derived from an assumption is
never an observation.

A negated premise matches only a fact explicitly stated not to hold. A missing
fact does not satisfy it. Two facts that disagree about one keyed value, or a fact
and its negation, are /conflicted/. Both are kept and shown; nothing picks a
winner. Rules cannot depend on their own conclusions. An evaluation that reaches
its work limit reports the remaining conclusions as unknown, not false.

A rule the model proposes derives nothing until it is admitted. Admission
uses the ordinary command approval: with full access it is admitted at once,
otherwise you are asked to allow =rule.admit -- departure v1: ...=.

#+BEGIN_SRC lisp
(memories)            ; memories, then facts: conflicted and no longer holding first
(why "c4dfffae")      ; why a fact holds: its sources, rule, and premises
(what-changed)        ; facts that changed since you last asked, with the cause
(rules)               ; rules, their versions, and whether they are admitted
(admit-rule "departure")
(retire-rule "departure")
(forget "c4dfffae")   ; retract a fact; derived facts that relied on it go too
#+END_SRC

=(why "ID")= is an alias for =(memory "ID")= and accepts a memory or a fact.
Recall includes complete current facts related to your message, so the model
can use them without rereading. The notice counts them:
=@ 2 relevant memories exist · 3 facts=. When a fact given to the model earlier
in the conversation changes, the next turn includes an explanation once, and
=@ 1 fact given earlier changed= appears. A memory can name a fact as a premise
and goes stale when the fact stops holding; a fact can cite a memory as evidence.

Autolith keeps every current fact, its sources, and the 1,024 most recently
retracted sources in memory. Older retractions stay in the knowledge log, so
=(why "ID")= still explains a long-retracted fact, reading its history from the
log.

The model reads =memory:facts=, =memory:claim/ID=, =memory:predicates=,
=memory:rules=, =memory:procedures=, and =memory:changes=, and edits =memory:facts= with
=predicate-define=, =fact-assert=, =fact-retract=, and =rule-propose=, up to 16
per edit. Mission status and gate results are recorded as =autolith.mission.*=
facts.

Starter recipes give common work a ready vocabulary. =memory:recipes= lists
them: =appointments= derives when to leave from an event's start, travel, and
buffer, and =service-dependencies= marks a service at risk while something it
depends on is down. A =recipe-use= operation on =memory:facts= defines a
recipe's predicates and proposes its rules, which are admitted like any other.

The =knowledge-mode= setting is =active= by default. =passive= keeps recording
observations such as mission results but offers nothing to the model, and =off=
records nothing; in both, model requests are exactly as without structured
knowledge. Change it in =(settings)= or with =AUTOLITH_KNOWLEDGE=.

Knowledge is evaluated locally when it is listed or recalled, and evaluated
again only after a cited file, the knowledge, or a validity period changes.
Each request where knowledge took part records its share, so its cost can be
measured:

#+BEGIN_SRC lisp
(knowledge-usage-report (application-conversation *active-application*))
#+END_SRC

Facts, rules, and predicates travel with memories in data exports; a relocated
workspace keeps its facts.

*** Plans, methods, gates, and contracts

A plan step can name the facts it requires. Its text takes their values, so
=Leave at {?leave}= requiring =event.departure review ?leave= reads =Leave at
12:20= and follows the departure when the meeting moves, without replanning.
A step with unsatisfied requirements is shown /blocked/ with the missing pattern.
Marking a step done records the facts used to complete it. If those facts later
stop holding, the plan flags the change without repeating the step. Changes
between turns are reported to the model once at its next turn, and
=@ 1 plan step changed with its facts= appears.

A /method/ describes how to do a task when its conditions hold, with subtasks
and plain steps in order. =plan.expand= turns a task such as =prepare review=
into a plan locally, trying methods in order and expanding subtasks within a
depth of 8 and 1,000 tasks. If no method describes a task, no method's conditions
hold, or the search runs out of budget, it reports the reason and leaves the
plan unchanged. Reports of unsatisfied conditions name the methods involved.

A mission gate of kind =:fact= passes when a fact matching its pattern holds
on accepted evidence. By default, it accepts observations and your statements:

#+BEGIN_SRC lisp
(:id "departure-known" :kind :fact :pattern ("event.departure" "review" "?t"))
#+END_SRC

A model's predictions never satisfy it, nor does a fact that another accepted
fact disputes, and a derived fact counts only if everything it rests on,
negated premises included, is accepted. A negated pattern such as
=(:not ("item.blocked" "a"))= passes on an accepted explicit negation. A gate
passed on facts that stop holding before acceptance is checked again.

An action /contract/ describes a tool call: the argument values it applies to,
facts it requires, expected effects, and facts to read from its arguments and
JSON result, such as =$arg.to= and =$result.id=.

A call whose requirements do not hold is refused before execution, with the
reason. As with a gate, requirements need undisputed observations or your
statements unless =accepts= also names =model-proposal=. In that case, predicted
effects from an earlier call can satisfy them. A successful call records its
expected effects as predictions and its observed values as observations. This
also works with MCP results.

Name tools in contracts and diagnostic probes by display name, such as
=service.ping=, or canonical dispatch name. Canonical names take precedence;
a display alias must identify one registered tool.

The model defines methods with =method-define= and proposes contracts with
=contract-define= on =memory:facts=. For each new contract version, approve the
=contract.admit= request containing its complete definition, including
observation mappings and =accepts=. Declining leaves that version inactive and
any previously admitted version active. Any edit requires fresh admission;
proposing the same admitted content again does not. Read proposed and active
versions from =memory:contracts=, and methods from =memory:methods=.

Contract admissions are persisted for the exact definition and version. Older
contract records without admission provenance are inactive. Exports retain
admission metadata for provenance; imported contracts require local admission.
Trusted Lisp callers of =knowledge-define-contract= admit their definitions by
default; pass =:admit nil= to propose one for separate authorization.

Requirements may bind variables used by effects and observations. A call needs
one distinct binding environment; ambiguous bindings or an incomplete search
refuse it before execution. Evidence records retain the supporting claim IDs.
If a successful call's observation mapping fails, its plain result reports
=externalSuccess: true=, a bounded =externalResult= excerpt, and structured
=contractErrors= with =contractRecording: "failed"=. Rich results include a
bounded diagnostic after their ordered content. Durable details retain the
recording diagnostic and subtype metadata; clipped MCP sections include their
original metadata as provenance.

*** Learned procedures

When three turns in a workspace make the same tool calls in the same order,
Autolith learns a /procedure/ after the turn, locally and without a model request.
Arguments that never change stay as they were. A value taken from an earlier
call's JSON result is taken from it again. Values that vary become parameters,
matched with the words that varied in your requests.

A procedure is kept only if each turn is reproduced by the procedure learned
from the other two. If another recent request with the same wording did something
else, the wording is not enough to show when the procedure applies. The procedure
is not offered, though it can still be run. A new procedure shows
=@ learned procedure make-sales-report from 3 turns · (procedures)=.
When a later request fits, such as =Make the sales report for q5.=, the model is
offered one =procedure.run= call. It makes the same calls with =q5=, and
=@ learned procedure make-sales-report fits this request= appears. The first run
asks to admit the procedure (=procedure.admit -- make-sales-report v1:
sales.load, sales.report, notify.send=). Full access admits it at once.

Automatic execution requires completed, successful model turns that ran the exact
admitted procedure version and content. Complete usage measurements must show
fewer model requests and fewer tokens than the learning baseline. A request that
matches the wording exactly, apart from its parameters, then runs the procedure
before the model's first request. The =procedure.run= call is shown, and the
model answers from its results in one request.

If a learned wording pattern has a variable word such as =Please= or =Kindly=,
any word matches in that position. Such a match is only offered to the model,
which may decline it. Different wording, such as =Make the sales forecast for
q9.=, may match no pattern. If it shares at least two words with a procedure,
Autolith lists up to three possible fits with their parameters to fill in and
shows =@ learned procedure make-sales-report may fit this request=. The model
decides whether to use one; none runs automatically on that match.

Procedures are learned only from turns the model finished: every call succeeded,
the model answered, and the turn was not cancelled.

Every call still asks its own approval and passes its contracts. A run whose
contract requirements do not hold for the request's values is refused before
any call and is not offered; a call needing something an earlier call builds
is checked when it is made. If a call fails, the run stops and the model
continues the work with ordinary calls; two failed runs in a row suspend the
procedure until you admit it again.

#+BEGIN_SRC lisp
(procedures)          ; procedures, their calls, status, and what they saved
(run-procedure "make-sales-report" :file "q5")   ; without the model
(admit-procedure "make-sales-report")             ; allow it, or lift a suspension
(retire-procedure "make-sales-report")            ; never run or learn it again
#+END_SRC

=(procedures)= compares the turns a procedure was learned from with recent
turns that ran it, in model requests and tokens. The model reads
=memory:procedures=. Procedures are kept in the knowledge log, with every run,
and are learned and offered only while =knowledge-mode= is =active=.

*** Diagnosis

Diagnostic probes are enabled by default. Turn them off in =(settings)= or with
=AUTOLITH_DIAGNOSIS=0=. With probes enabled and structured knowledge active, the
model can use =diagnosis.run= to distinguish possible causes before trying a
repair.

Supply up to four hypotheses, each with predicted facts, and probes: tool calls
whose contracts observe facts from their results. Autolith checks known facts
first, then ranks probes by prediction differences per unit cost. For each
hypothesis pair, the ranking weight is 1 for two different predictions and 1/4
for a prediction from only one hypothesis. It runs at most three probes without
a model request between them.

A hypothesis is ruled out only by an undisputed observation or statement that
contradicts one of its predictions. Cases the probes cannot settle are reported
as open. Save a diagnosis by name to run it again with new values.

#+BEGIN_SRC text
Diagnosis remote-service: stale-endpoint. Repair: Update its endpoint.
probe 1: service.ping {"service":"billing"} ok → service.reachable(billing, true)
probe 2: service.config {"service":"billing"} ok → endpoint.current(billing, false)
ruled out unavailable: service.reachable(billing, true)
ruled out credentials: endpoint.current(billing, false)
#+END_SRC

=(diagnoses)= lists saved diagnoses and recent cases: the cause found, its
repair, and the facts that ruled out the others.

** Exporting and importing data

Use the same portable archive from the command line or an active session:

#+BEGIN_SRC sh
autolith data export all.sexp --all
autolith data export project.sexp --workspace /home/al/code/project
autolith data import project.sexp --workspace /home/al/src/project
#+END_SRC

#+BEGIN_SRC lisp
(data.export #P"all.sexp" :all t)
(data.export "project.sexp" :workspace "/home/al/code/project")
(data.import "project.sexp" :workspace "/home/al/src/project")
#+END_SRC
Export defaults to all workspaces and global data. A workspace export contains
its conversations, memories, agendas, plans, papercuts, and related session
assets. The archive contains Autolith data, not repository files. Clone or copy
the repository separately. Credentials, configuration, executable image state,
and caches are excluded.

Import preserves stable identifiers and merges into local data. Identical data is
skipped. A conflicting identity aborts the import before publication. For a
single-workspace archive, =--workspace DIRECTORY= or =:workspace "DIRECTORY"=
sets its new home directory. Without that option, workspace locations are
preserved. Relative paths are resolved against the current working directory.

Export creates a new private archive and refuses to overwrite an existing file.
The CLI exits without starting a session: success is 0, invalid arguments are 64,
and transfer failures are 1. Both command groups provide =--help=.

** Session titles and resume

A session gets an immediate local title from its first prompt or image. After the
third actual user turn, Autolith may ask the active model for one concise
replacement and save it with the conversation. The local title does not depend on
provider generation.

Provider-generated refreshes are enabled by default. Use =(titles)=, =(titles t)=,
or =(titles nil)= to inspect or change the durable global preference.

=(resume)= displays titles in its picker. An explicit =(resume "ID")= accepts the
stable conversation identifier or a part that identifies one conversation.
Several matches are listed instead. The terminal status bar and local session
status show the title when one is available; otherwise they show the conversation
ID.

If no process serves the conversation, it resumes in a fresh one. Background
jobs, asynchronous shell runs, and Lisp worker state from before the restart no
longer exist. The first user turn after such a resume carries a request-local
notice telling the model about the restart. Only durable child task results stay
readable through =job.get=.

If a world server still serves the conversation as a channel, resume attaches to
that live channel with its jobs intact. See Local sessions.

Inspect a saved conversation without resuming or locking it with:

#+BEGIN_SRC sh
autolith replay ID
autolith replay ID turn 12
autolith replay ID date 2026-08-28
autolith replay ID time 2026-08-28T10:30:00
autolith replay ID sequence 1200
#+END_SRC

On an interactive terminal, replay behaves like a small debugger over durable
conversation events. =next= and =previous= step records; =turn=, =date=, =time=,
and =sequence= jump to a location; =raw= shows the selected replay form; and
=quit= exits. Replay reads complete persisted forms without acquiring the
conversation lease or repairing, appending, or resuming the conversation.

List the tool calls that failed recently, with the arguments the model sent,
grouped by tool and error:

#+BEGIN_SRC sh
autolith tool-failures
autolith tool-failures --days 3 --examples 5
autolith tool-failures ID
#+END_SRC

Without IDs it reads every conversation and child task conversation, but only
the segments written in the last =--days= days, seven by default. Groups ignore
the numbers and quoted values in error text, so the same mistake with different
arguments counts once per call in one group. Use it to find where a tool
description or argument rule makes models fail.

** Local sessions

*** Starting and switching channels

One background server hosts your channels. Run =autolith= in a directory to
connect to it, starting the server if needed. The client opens the channel
in that workspace whose conversation file changed last and that no other
terminal controls, or creates a channel if none qualifies. Use =autolith resume ID= to open a
specific channel.

Closing the terminal, detaching, or losing the connection leaves the channel
running. Use =(quit)= to end it. Use =(switch "ID")= to attach to another
channel; the server opens it if needed and leaves the previous one running.
In a directly run session, use the same command to resume that conversation
in place.

The server runs until you stop it, even with no open channel or attached
terminal:

#+BEGIN_SRC sh
autolith lg server
autolith lg stop
#+END_SRC

Use =server= to inspect the server process and its hosted channels, and
=stop= to end all channels and the server. Updating or rolling back from any
channel also stops the server because the image is shared.

*** Checkpoints and launch options

A checkpoint saves the whole process and records the requesting channel as
the rollback target. It first waits, however long it takes, until no channel
runs a turn and no job is running. Work already under way finishes, with the
jobs it starts; no channel starts a new turn meanwhile. Then the server
pauses all channels, and each terminal reconnects automatically. Every
channel receives the outcome; the requesting channel also receives the
generation ID. The turns held during the wait then start. A terminal started
during the pause waits for the server instead of starting another one.

On Windows, run a channel directly to checkpoint it. The world server
refuses exact-heap checkpoints because they require a process restart.

Use =--detached= for a standalone session outside the server. Set
=AUTOLITH_SESSION_STYLE=direct= to run a single session in the terminal's
own process.

For a new channel, specify =--model=, =--permissions=, =--immutable=,
=--fullscreen=, or =--almighty= at startup. Supply =--provider= only together
with =--model=, as on a direct start. An existing channel accepts an explicit
=--permissions= override only when no terminal controls it. Other launch
options are rejected, with the option named in the error. When opening a
workspace, those other options create a new channel instead of reusing a
running one.

*** Channel sidebar

In fullscreen mode, an attached terminal can show the world's channels in a
sidebar on the left. Your inbox comes first, with the number of messages
waiting there unread; that count is kept on disk, so every terminal shows
the same one. The other channels are grouped by workspace, with the current
workspace first. Within a workspace, the channel whose conversation changed
last comes first, and child channels are nested under their parents.

| Marker | Meaning |
|--------+---------|
| =▸= | This terminal's current channel |
| Cyan =●= | A terminal is attached |
| Green =●= | The agent is working |
| =○= | Hosted but not working |
| =·= | No running session |

A yellow number counts messages received since this terminal last viewed
the channel; =@= counts mentions of you. Each terminal tracks its own unread
counts. A channel first seen by that terminal starts at zero. The =✉= count
shows deliveries waiting for a channel that no process serves.

Press =Ctrl-T= to hide or show the sidebar. That preference is kept when the
same terminal switches channels or reconnects. Below 100 columns, the
sidebar is hidden automatically.

*** Session endpoints

Every channel the server hosts, like every directly running session,
publishes a private authenticated local endpoint. Its session ID is the
active conversation ID, shared with =resume= and stable across detach,
restart and checkpoint quiescence. Selecting another conversation with
=new=, =resume= or =fork= moves the endpoint to that conversation ID while
attached terminals continue using the same connection. Inspect endpoints
with:

#+BEGIN_SRC sh
autolith localgroup status
autolith lg status --sexp
#+END_SRC

=idle= means that the process is at input with no active work of any kind.

Start an unattended session, or resume one by conversation ID or a part of it:

#+BEGIN_SRC sh
autolith --detached
autolith resume b-6 --detached
autolith resume b-6
autolith resume
#+END_SRC

With =--detached=, Autolith prints the full conversation ID and session PID,
then exits without attaching. This works with closed stdin and with
=AUTOLITH_SESSION_STYLE=direct=. Detached resume requires an ID. Without
=--detached=, omit the ID to open the conversation picker. An exact canonical
or displayed ID wins; otherwise any part of an ID selects the one conversation
containing it, without regard to case, and a part matching several reports
every matching ID with its available title, workspace, time, and preview
instead of selecting one. Running conversations,
including empty new sessions, are selectable. Resuming a running conversation
attaches to it; detached resume prints its existing PID without disturbing its
clients. Launch-only overrides such as =--model= and =--permissions= are
rejected when resuming a running conversation; change its mode inside it with
=(permissions ...)=. =--image= and =--simulate-crash= cannot be combined with
=--detached=.

Control a session with the following commands:

#+BEGIN_SRC sh
autolith lg tell   "message"
autolith lg tell   SESSION-ID "message"
autolith lg pause  [SESSION-ID]
autolith lg attach [SESSION-ID]
autolith lg attach [SESSION-ID] --read-only
autolith lg attach [SESSION-ID] --take-over
autolith lg detach [SESSION-ID]
autolith lg kill   [SESSION-ID]
#+END_SRC

=lg= is an alias for =localgroup=. When exactly one endpoint is reachable,
these commands select it when =SESSION-ID= is omitted. With multiple sessions,
provide a full ID or any part of one that matches a single session. Parts are
matched without regard to case and with the display hyphen dropped, for
example =b=, =b-6=, =uouh= or =6UOU= for =b-6uouHJ=. A full ID in either form
takes priority. If a part matches more than one session, the error lists the
matching IDs and nothing happens; give a longer part.

Use =tell= to send input to a session and resume it if paused.
=pause= cancels active work and holds queued primary work.
=kill= requests graceful shutdown.

On POSIX hosts, detaching hands a session to a supervised process group that
outlives the terminal. On Windows, the supervisor uses a Job Object for the
session process tree. Both support unattended starts and later attachment.

Autolith stores configuration, durable data, process state, and replaceable
caches below =${XDG_CONFIG_HOME:-~/.config}/autolith/=,
=${XDG_DATA_HOME:-~/.local/share}/autolith/=,
=${XDG_STATE_HOME:-~/.local/state}/autolith/=, and
=${XDG_CACHE_HOME:-~/.cache}/autolith/=. XDG base-directory values must be
nonempty absolute paths; invalid values use these defaults. Newly created
Autolith roots have mode =0700=.

POSIX XDG directory values are native filesystem names, including literal
brackets, asterisks, and backslashes.

Until 0.68.0, Autolith moves a populated root to the native path once if an
older release stripped backslashes from the path it used to write the root.
Runtime and launcher migration use the same lock.

The move can replace an absent native root or one containing only directories.
Precreated directory trees are preserved in a hidden sibling backup. If both
roots contain files, choose one explicitly rather than merging installations.

If the move fails, Autolith warns and uses the legacy root. Autolith retries
the move with a fresh configuration. Warnings and conflicts name both paths.
Autolith skips this compatibility lookup for explicitly set roots.

Provider discovery metadata uses =CACHE/provider-models.sexp=. On upgrade, the old
state-directory cache moves there once. Publication is atomic; the old file is
removed only after the target exists. Existing target metadata wins. Failed
publication warns and loads the old metadata offline; interrupted source removal
is retried without reimporting it. Remove this compatibility lookup in 0.68.0.

Generated conversation picker, search, and input-history indexes use
=CACHE/conversation-picker/<source-directory-hash>/=. Missing indexes rebuild from
authoritative conversation records, including retired segments. Context anchors,
source locks, and source-invalidation revisions use their original data-directory
paths. Old generated sidecars are retained for older releases; no whole-directory
migration is performed. Nix ASDF output uses =CACHE/nix/asdf-cache/<identity>/=;
durable images use the data directory. After upgrading, you may remove old
=DATA/nix/asdf-cache/= compilation output.

On Windows the same four roots are, unless an absolute XDG variable overrides
one, =%APPDATA%\autolith\=, =%LOCALAPPDATA%\autolith\data\=,
=%LOCALAPPDATA%\autolith\state\=, and =%LOCALAPPDATA%\autolith\cache\=.
Private files and directories carry an access control list granting only the
owner and SYSTEM, which is what mode =0600= and =0700= mean there; a file
Autolith publishes read-only withholds write access through that list and
keeps the read-only attribute clear, so it can still be replaced and deleted.

** Channels

Autolith is moving from one session per process to one shared world of
channels and participants. A channel is an addressable conversation and
execution location with its own working directory and history. A participant
is a person or an agent with private state; each resides in one channel and
may subscribe to others. You reside in your inbox, a channel of your own
named =inbox= where no agent ever lives; viewing or controlling another
channel moves nobody. Every durable conversation is kept in step with a
channel of the same identifier and an agent participant residing there, all
owned by the one human participant, so =conversation:id/X= and =channel:id/X=
name the same history. A conversation newer than its channel is migrated
again onto the same identities, and a deleted conversation retires its channel
and agent. The world lives in =world/= below the data root. One world server
process hosts the open channels, each with its own endpoint for terminals;
see Local sessions.

=(channels)= lists every channel with its residents and subscribers, newest
change first, and then the parked agents. Agents are all one kind of
participant: an agent has a parent and may have children, and any agent,
a child too, may create child agents. A child agent resides in a channel
nested under its parent's channel and belongs to its parent agent, so
=channel:id/<execution id>= reads a child's transcript and a message to that
channel steers it. How deep the tree grows is capped:
=AUTOLITH_TASK_MAX_DEPTH=, default 2, counts the levels of child agents below
a top-level agent, and the limits on running and queued jobs cap how many
run at once.

Every participant has a unique name, its handle, so =@name= reaches exactly
one of them. A session's agent is named after its workspace directory, =frob=
for an agent working in =~/work/frob=, and a second agent there is =frob-2=;
a child agent takes the name its parent gave it, as in
=(prompt :to 'test-review ...)=, or =agent= when it has none; you are =user=.
Names are letters, digits, hyphens and underscores, matched without regard to
case. =(rename "NAME")= renames this channel's agent and
=(rename "WHO" "NAME")= renames the participant =WHO= names by handle,
identifier or a part of it, yourself included. A name another participant
has is refused, and so is =parent=, which always means the sender's parent.

A channel has one resident agent. =(move "WHO")= moves the agent =WHO=
names, by handle, identifier or a part of it, into this channel, and
=(move "WHO" "ID")= into channel =ID=. The move stops the agent where it is
the way a steer does: the tool call in flight finishes, no new request
starts, and the prompts it had not started are dropped with a notice in
the channel it leaves; nothing moves until the turn has stopped. In its new
channel the agent keeps the context it had, followed by what is said there
from the move onward, and its own model; the channel's earlier history stays
readable at =channel:id/ID= but is not part of the agent's context. The
context is kept on disk, so a restart, or a channel opened only later, finds
it. The agent then waits: it works again when you write there or someone
mentions it from another channel. A move into a
channel that already has an agent is refused, and so is a move into the
inbox or of yourself: you stay in the inbox while a terminal shows you any
channel. =(dismiss "WHO")= parks an agent instead,
after it stops the same way: a parked agent resides in no channel and keeps
its identity, its children and its context, and =(move "WHO")= brings it into
a channel again. Parking never affects its children. A mention of a parked
agent reaches nobody, and the send says the agent is parked. A channel
without an agent, because its agent moved or was parked, keeps its history
and its subscribers, and refuses typed prompts until =(move "WHO")=
brings an agent or =(domestic)= creates a new one for it, named after the
workspace and using this session's model and starting with no context but the channel's
history to read. Messages sent to such a channel
wait in its inbox until an agent is there to read them.

Typing =@= in the composer completes participant handles the way it completes
workspace paths; a token with a slash stays a path. A message you type that
mentions a participant residing in another channel is delivered to that
channel as a mention from you when you submit it, before your own agent
takes the message, so =@frob have a look= reaches frob wherever you are. A
mention starts a word: an =@= inside an address or a path, as in
=alice@frob.example=, mentions nobody. A plain message you type, and your
agent's reply to it, reach every subscriber of your channel residing
elsewhere the same way, as copies labeled by the subscription; a replayed
turn after a restart sends no second copy. The transcript highlights
mentions: your own name in the user color, other participants' names in the
accent color.

Messages travel between channels through the same path for people and agents.
=(tell "ID" "text")= sends a message to channel =ID= as yourself, where =ID=
may be any part of the identifier that names one channel, as in
=channel:id/ID= and =(switch "ID")=; the agent
tools =channel.send=, =channel.subscribe= and =channel.unsubscribe= do the same
for an agent, a child agent included: it is the resident of its nested
channel and messages as that participant under its role's ordinary tool
policy. A message reaches the channel's residents, every subscriber of
the channel and every participant it mentions as =@name= or =@id=, wherever
they reside. =@parent= names the sender's parent; when that parent is parked,
the message goes to the nearest ancestor agent that is not, and to you when
none is left. An idle agent wakes with the message; a working one receives it
as a steer labeled with the sender and the channel. The transcript shows the
sender's name and the channel. A message for you, one that mentions you or
reaches you through =@parent=, is a notice: it goes to your inbox and no
agent takes it as a turn. Once a terminal shows the inbox, the notice is
recorded in the inbox's history and shown in full; until then it waits,
unread, and the sidebar counts it. Each notice ends with the form that goes
where it was said, such as =(switch "b-6uouHJ")=; in fullscreen, clicking it
runs it as if you had typed it. =(switch "inbox")= opens the inbox, which
=(resume)= and the conversation picker never offer. Typing in the inbox
reaches no agent; =(tell "ID" "text")= writes to a channel from there.
Messages you write elsewhere name the channel you wrote them in as their
source. Messages wait in the channel's inbox under
=world/inbox/= until a process serves the channel, and a crash between
delivery and the durable record repeats nothing. A send is recorded under
=world/outbox/= before its copies go out, so a copy an inbox refuses because
it is full, or one a crash skipped, is delivered later under the same
identifier, once, and the sender hears which channels still wait.

Conversation leases, Localgroup endpoint records, and recovery state live under
=${XDG_STATE_HOME:-~/.local/state}/autolith/= rather than =XDG_RUNTIME_DIR=.
They must survive logout so detached sessions, handoffs, and crash recovery can
continue across login sessions. Autolith uses authenticated loopback TCP rather
than filesystem sockets for its inference and Localgroup protocols, and cleans
stale Localgroup records itself.
The management REPL socket also defaults to the state directory, at
=management/repl.sock=.

* Configure Autolith

Autolith loads the optional user file
=${XDG_CONFIG_HOME:-~/.config}/autolith/init.lisp= after tracked code, a
selected private image commit, and any site or trusted directory
configuration. This order also applies to =autolith models= and =autolith auth=.
Use =--pristine= to skip private replay and executable initialization.
The user file reloads on retained generation reconnect.

The file is ordinary Common Lisp in package =AUTOLITH=, with your full
privileges. It is not copied into private replay or the pristine recovery
image.

Packagers may supply one separate, read-only configuration tree with
=--site-config-root DIRECTORY= or =AUTOLITH_SITE_CONFIG_ROOT=. The directory
must already exist and be absolute. It may contain =init.lisp=, =mcp.sexp=,
=skills/=, and =agents/=. Site configuration loads before user configuration,
so it provides defaults without replacing the user's normal XDG tree. A site
=init.lisp= has the same full privileges as user initialization and is not a
security boundary.
Site lookup uses this explicit root rather than =XDG_CONFIG_DIRS=.

Executable initialization loads in this order:

1. site =init.lisp=
2. trusted directory =.autolith/init.lisp= files, outermost to nearest
3. the user XDG =init.lisp=

Missing files are skipped. A file that exists but cannot be read or evaluated
fails startup or reload, with its exact pathname in the error. The
=directory-scopes.sexp= file is user-owned.

** Settings

Every knob Autolith exposes is a named setting with a type, a description, a
default, and, where the choices are finite, its options. =(settings)= opens the
settings page: a picker listing each setting with its current value and where
that value came from. Choosing an adjustable setting opens its options;
choosing a read-only one explains why it cannot change in a running session.
The page returns to the list after every change until you cancel.

The same operations work without the page. =(settings :boot-screen-seconds)=
describes one setting, and =(settings :boot-screen-seconds 2)= changes it.
Use native values: =t= and =nil= for switches, integers for counts, and strings
or pathnames for paths. Omit the value to inspect a setting; an explicit =nil=
sets its value. A change to a durable setting is saved at once for future
sessions. In a script, =(settings)= prints every setting grouped by area.

Settings have four scopes.

Durable settings persist in =preferences.sexp= under the config directory.
These include the model, reasoning effort, Fast mode, reasoning traces, compact
view, timestamps, transcript style, activity line, cache miss notices, Simple
Technical English, generated titles, fullscreen, and saved permission mode.

Session settings, such as hurry-up mode, last until exit.

Process settings, such as the immutable flag, management endpoint, and roots,
come from the command line, environment, or startup defaults and are fixed for
the process.

Derived settings, such as the context window and provider endpoint, follow the
model. For the context window, Autolith first uses a declared model value. If
none is available, it uses the catalog value, or the default if neither value
is available.

On upgrade, Autolith moves the state-directory =preferences.sexp= into the config
directory once, preserving unknown keys. Existing config preferences take
precedence. The old file is removed under both writer locks after atomic
publication. Failed publication warns and continues reading and saving the old
file until migration succeeds. Interrupted source removal is retried using the
config file, without importing stale values again. Session records and pending
inputs use the state directory. Remove this compatibility path in 0.68.0.

Enable the session's private context-pressure reminder with =(relax t)=, or
=(settings :relax-p t)=. Use =(relax nil)= to disable it and =(relax)= to inspect
its state.

The private reminder warns that the agent's session, context and token
estimates are unreliable and often too small. Automatic compaction is
available; perceived length is no reason to shrink scope, skip verification,
rush, or end early. It travels with the session state behind the conversation
history, so turning it on or off keeps the cached prompt prefix. Inference
frames carry it in their own system prompt. It is rebuilt after compaction,
outside conversation turns. The setting lasts until exit and defaults to =nil=.

A durable value is chosen at startup from the first source that supplies it:
an explicit command-line choice, the setting's environment variable, then the
saved file. A saved model or effort that no registered provider serves is
dropped rather than applied. An unavailable saved provider or incompatible saved
model/provider pair falls back to a registered selection after user initialization.
Startup displays a recovery notice once per session. Recovery does not rewrite
saved preferences; re-registering the provider restores the saved selection at the
next startup. Invalid explicit command-line and environment choices report an
error, including a provider that cannot serve the fallback model. Choose a model
registered for that provider with =--model= or =AUTOLITH_MODEL=.

From Lisp, user initialization and replay scripts read a setting with
=(config :model)=, which uses the current configuration, or
=(config :model configuration)= for an explicit one, and change it with
=(setf (config :reasoning-traces-p) t)=. Unknown setting names signal a
configuration error. Create an independent configuration with
=configuration-copy=.

The preferences file uses version 8: one flat record of setting names and
values that keeps unknown keys. Before upgrading a preferences file from
versions 1 through 7 to 0.54 or later, run a 0.53 release once to write version 8.

** Language servers

Install your language server, then configure it in =lsp.sexp= under Autolith's
user configuration directory, alongside =init.lisp=. For example:

#+BEGIN_SRC lisp
(:version 1
 :servers ((:name "clangd"
            :command "clangd"
            :arguments ("--background-index")
            :extensions (".c" ".h")
            :language-id "c"
            :root-markers ("compile_commands.json" ".git")
            :timeout-seconds 30)))
#+END_SRC

Configuration is declarative. Supply a unique =:name=, executable =:command=,
nonempty =:extensions= list, and =:language-id= for each entry. Arguments are
literal strings. Optional =:initialization-options= and =:settings= are JSON
object strings; =:disabled-p t= disables an entry. The request timeout is an
integer from 1 through 120 seconds, defaulting to 30.

  Only configure commands you trust: language servers run with your privileges
  and inherited environment, outside the shell approval sandbox. Keep credentials
  out of this file. Executables must already be installed; commands are resolved
  on =PATH=. Repository-local LSP configuration is not loaded.

  Autolith exposes the =lsp= tools only when =lsp.sexp= defines at least one
  enabled server; without it the registry omits them. A malformed =lsp.sexp=
  keeps the tools registered so the configuration error surfaces when a tool
  runs. When at least one server is enabled, each provider request includes a
  context note naming those servers.

Ask Autolith to use these tools:

- =lsp.status=: inspect configuration and running project/server pairs.
- =lsp.query=: request =definition=, =references=, =hover=, =implementation=,
  =type-definition=, =document-symbols=, or =workspace-symbols= for a workspace
  file. Position queries require one-based =line= and =character= coordinates,
  with columns measured in UTF-16 code units. For workspace symbols, supply
  =query=; the file selects the project and server.
- =lsp.diagnostics=: synchronize a file and retrieve diagnostics.
- =lsp.restart=: stop servers and reload the configuration after changing it.

Use =lsp.semantic= for revisioned transformations:

- =prepare-rename=: inspect the symbol at =path=, =line= and =character=.
- =rename=: propose a symbol rename with those coordinates and =new-name=.
- =code-actions=: discover choices for a range, using =line=, =character=,
  =end-line= and =end-character=. Optionally filter =only= action kinds or
  supply =diagnostics=.
- =resolve=: retrieve a complete action using its returned =choice= ID.
- =propose=: retain an action's edit as an applicable proposal using =choice=.
- =move=: propose server preparatory edits followed by moving =path= to
  =new-path=. Both paths must identify regular files or a missing destination.
- =inspect=: review a retained =proposal= ID.
- =apply=: apply a retained =proposal=. Obtain explicit approval for annotations
  with =needsConfirmation=, then include their IDs in =approved-annotations=.
  Confirm each synthetic =lsp.semantic-confirmation= request through the ordinary
  command-permission prompt. Without a permission callback, confirmation is denied.

Proposals preserve the order of text, create, move and delete effects. Every
affected file passes the ordinary resource authority checks before observation
and again before application. Resource revisions cover file kind and content;
synchronized document versions must also match. Request a fresh proposal after
a conflicting edit or server restart.

Moves preserve the source permissions captured during staging, including
edited multi-hop moves. Publication is atomic per file, with rollback of the
change set on failure.

Proposals and action choices are conversation-local and retain their exact
snapshots. The limits are 32 choices, 240,000 encoded characters per choice,
128 resources per choice, and 512 resources or 16 MiB of UTF-8 snapshots per
conversation. Older choices expire when those budgets fill.

Server commands are presented as data for separate explicit execution.
Use local =file:///= URIs; directories, service resources and URI authorities
are unsupported.

Servers start lazily on file requests, including diagnostic requests after a
successful =resource.edit= workspace edit. All enabled entries with matching
filename suffixes are queried. The project root is the nearest ancestor with a
configured root marker, bounded by the workspace; otherwise it is the workspace.
Open files are refreshed from disk before queries, including shell edits.

Results contain native file URIs and zero-based UTF-16 ranges. Push and pull
reports are retained independently and combined, removing duplicate items.
Diagnostic state =received= identifies versioned reports, =unversioned= means a
report's snapshot cannot be confirmed, and =pending= means no report arrived.
The =sources= field gives push and pull freshness separately.

For explicit diagnostics, Autolith allows two seconds for push reports and
uses the configured request timeout for pull requests.

Edit follow-ups share a single one-second blocking deadline across lock
acquisition, startup, synchronization, and all matching servers. This includes
at most half a second for push settling. If startup fails, Autolith reaps the
server process. If automatic diagnostics time out, use =lsp.diagnostics= for
the full server timeout.

Reports retain at most 200 diagnostics per file and mark truncation. Files are
limited to 2 MiB, with 64 open documents per server and 16 live project/server
pairs per registry. Use =lsp.restart= to release them. Server shutdown occurs
when the tool runtime is retired.

** Active-image management endpoint

The management REPL is a separate opt-in subsystem for trusted programs that
must evaluate Common Lisp in the running =AUTOLITH= image. It is image-daemon's
evaluation endpoint, whose =eval-connect= and =eval-call= form a complete Lisp
client, and does not use the localgroup protocol, Swank, or Slynk. It is
disabled unless =AUTOLITH_MANAGEMENT_REPL= is set to =on=.

Every connection authenticates with a fresh random nonce and HMAC-SHA-256. The
client never sends the reusable token. Put a nonempty token in a regular file
owned by the current uid with mode =0600=. Autolith opens that file without
following symbolic links only while checking a proof, wipes the token octets,
and retains only the token-file pathname.

The following environment variables configure newly created applications:

| Variable | Default | Meaning |
|-
| =AUTOLITH_MANAGEMENT_REPL= | =off= | Enable the endpoint. |
| =AUTOLITH_MANAGEMENT_REPL_TRANSPORT= | =unix=, or =tcp= on Windows | =unix= or =tcp=. |
| =AUTOLITH_MANAGEMENT_REPL_UNIX_SOCKET= | =${XDG_STATE_HOME:-~/.local/state}/autolith/management/repl.sock= | Unix socket pathname. |
| =AUTOLITH_MANAGEMENT_REPL_TCP_ADDRESS= | =127.0.0.1= | IPv4 loopback listener address. |
| =AUTOLITH_MANAGEMENT_REPL_TCP_PORT= | =4141= | TCP listener port. |
| =AUTOLITH_MANAGEMENT_REPL_TOKEN_FILE= | =${XDG_CONFIG_HOME:-~/.config}/autolith/management-repl.token= | Mode-0600 token file. |
| =AUTOLITH_MANAGEMENT_REPL_TIMEOUT= | =10= | Evaluation deadline in seconds. |
| =AUTOLITH_MANAGEMENT_REPL_MAX_FRAME= | =1048576= | Maximum wire-frame octets. |
| =AUTOLITH_MANAGEMENT_REPL_MAX_SOURCE= | =262144= | Maximum UTF-8 source octets. |
| =AUTOLITH_MANAGEMENT_REPL_MAX_OUTPUT= | =262144= | Maximum captured output and value text. |
| =AUTOLITH_MANAGEMENT_REPL_QUEUE_CAPACITY= | =8= | Maximum queued evaluations. |
| =AUTOLITH_MANAGEMENT_REPL_MAX_CLIENTS= | =8= | Maximum accepted clients, including authentication. |
| =AUTOLITH_MANAGEMENT_REPL_AUTH_TIMEOUT= | =10= | Absolute authentication deadline in seconds. |

TCP accepts IPv4 loopback addresses only. This endpoint does not provide server
TLS, and arbitrary Lisp results may contain secrets. Challenge-response prevents
bearer-token replay, but an unauthenticated local process can relay a challenge
and proof between trusted local clients. Treat loopback TCP clients as locally
trusted.

With Unix transport, Autolith creates a mode-0700 private directory and a
mode-0600 socket. At startup, Autolith refuses an active socket and any alien or
non-socket path. It removes a socket only after proving that it is a stale
current-user endpoint.

Windows has no filesystem sockets. Autolith refuses =unix= there with a message
and uses =tcp= by default.

*** Wire protocol

Each message is a four-octet unsigned big-endian length followed by exactly that
many UTF-8 octets containing one readable S-expression. Length zero, oversized
or truncated frames, invalid UTF-8, malformed syntax, and trailing forms are
rejected. Readers use standard I/O syntax, a fresh standard readtable, and
=*read-eval*= =nil=.

The server starts each connection with:

#+BEGIN_SRC lisp
(:challenge :version 1 :algorithm :hmac-sha-256 :nonce HEX)
#+END_SRC

=HEX= encodes 32 random nonce octets as 64 lowercase hexadecimal characters.
The client reads its token file, computes =HMAC-SHA-256(token, nonce)=, and
replies:

#+BEGIN_SRC lisp
(:authenticate :proof HEX)
#+END_SRC

A valid proof receives =(:authenticated :version 1)=. A proof is valid only for
that connection's nonce. Authentication failure closes the connection without
a reusable credential or detailed oracle response.

After authentication, send one request at a time:

#+BEGIN_SRC lisp
(:evaluate :source "(values (+ 20 22) *package*)")
#+END_SRC

The source string must contain exactly one form. A dedicated serial evaluator
thread reads it in package =AUTOLITH=, applies the configured deadline, prevents
interactive debugger entry, and captures standard, error, trace, query, debug,
and terminal output in a bounded Gray stream. Successful responses have this
shape:

#+BEGIN_SRC lisp
(:evaluation-result
 :status :ok
 :values ("42" "#<PACKAGE \"AUTOLITH\">")
 :values-truncated-p nil
 :output ""
 :output-truncated-p nil)
#+END_SRC

=:values= contains one bounded readable string for every multiple value.
Conditions return =:status :condition=, a bounded =:condition-type= and
=:report=, captured output, and truncation flags. Deadline expiry returns
=:status :timeout=. The client may submit further requests on the authenticated
connection.

Evaluation deadlines use in-process interrupts and are best effort for trusted
forms. A form that suppresses interrupts may outlive its deadline.

Before saving the image during checkpointing, Autolith stops the listener,
clients, evaluator, and queue. It restarts the endpoint after saving. If an
evaluator cannot quiesce within the documented two-second shutdown bound,
checkpointing aborts with a =management-repl-error= whose operation is
=:quiesce= rather than saving live management threads.

Normal shutdown is idempotent and removes only the exact Unix socket created by
that runtime.

** Context

Use *ephemeral notes* to add temporary information to provider requests without
adding conversation messages. For example, register advice for release requests:

#+BEGIN_SRC lisp
(define-context-contributor release-advice (request)
  "Add advice for release requests."
  (when (search "release" (or (request-context-latest-user-text request) "")
                :test #'char-equal)
    (make-context-contribution
     :identifier  "release-check"
     :instruction "Verify release artifacts before publishing."
     :lifetime    ':turn
     :priority    40)))
#+END_SRC

- A contributor receives a read-only request snapshot.
- It can return zero, one, or many contributions.
- Notes stack unless they deduplicate, supersede, or conflict.
- Priority matters only when the advice budget is full.

Inspect contributions with =(context)=. They apply only to provider requests;
they do not count as conversation turns or attach to your messages.

Register selective project or user advice as a declarative rule:

#+BEGIN_SRC lisp
(register-context-rule
 '(:id "lisp-edits"
   :when (:paths ("src/") :languages ("common-lisp")
          :events ("tool-success"))
   :instruction "Check the changed declarations before committing."
   :priority 30 :lifetime :while-relevant))
#+END_SRC

Use =:paths=, =:languages=, =:tools=, =:namespaces=, =:roles=,
=:diagnostics=, =:events= and =:output-contains= in =:when=. Fields are
conjunctive; values within a field are alternatives. Paths match prefixes;
=:output-contains= matches literal case-insensitive substrings of recent
completed assistant text and generated tool arguments. Other values match
exactly. Add an absolute =:workspace= directory for project scope. Authorized
tool operations and structured LSP severities supply bounded current-turn
metadata. Asynchronous completions use their originating turn identity.
Rules share the ordinary advice budget, priority, lifetime and deduplication
policy. Inspect delivery with =context-status=; remove a registered rule with
=unregister-context-rule= and its original ID.

To turn a complaint into a persistent correction, use:

#+BEGIN_SRC lisp
(complain "Your explanations are too long. Give the result first.")
(wtf "Use the existing library instead of reimplementing it.")
#+END_SRC

Both names open the same interactive review. Inspect the generated instruction
and literal trigger, amend the candidate, then choose workspace or global scope
to save it. Saving an unmatched trigger and replacing an existing rule each
require separate confirmation. Cancel to discard the candidate. Omit the text
to enter a complaint in the editor.

Generation uses bounded recent assistant output and tool arguments as evidence.
On later provider requests, matching corrections enter the ordinary request-local
advice budget. Inspect them with =(context)=. Global corrections are stored in
=data-root/context-rules.sexp=; workspace collections live under
=data-root/context-rules/=, keyed by the canonical workspace directory. A
same-ID workspace correction overrides the global one in that workspace.
Saves take effect on the next request, including in other sessions using the
same data root. Edit or remove the data files to change saved collections.

The status line keeps a context meter visible while idle. It shows used tokens
and the full model window. =|= marks the automatic compaction point. The
ChatGPT subscription catalog currently reports a 272K-token window for the
GPT-6.1, GPT-6, and GPT-5.6 models, which compact at about 218K tokens by default:

#+BEGIN_EXAMPLE
ctx [==========|..] 218K / 272K used
#+END_EXAMPLE

Before provider usage is available, =~= marks an estimate from the known system
prompt, session state, retained conversation, and tool schemas. The estimate uses
four characters per token. After compaction, the meter estimates the replacement
context until the next provider report. Compaction request usage is recorded
separately as work spent on the checkpoint and summary.

At narrow widths, the meter keeps the used and window counts and drops the bar.

Use =(compact)= to compact the current conversation immediately,
regardless of the meter. Immediate and automatic compaction use the same
provider-native checkpoint and portable summary path. During an active turn,
compaction waits in the idle queue. An empty conversation needs no provider
request. Compaction adds a durable checkpoint without adding a user message
or starting a model turn.

The native checkpoint and its portable handoff normally require two provider
requests. Completed requests are recorded with their usage before output
validation, including rejected summaries and native responses that require
portable fallback. A native checkpoint includes the full returned item window,
in provider order.

A summary must complete normally and contain bounded, nonempty progress,
decisions, context, constraints, next-steps and reference sections before
checkpoint publication. Markdown heading marks may decorate the labels. If a
finished summary lacks this structure, Autolith names the problem and asks
again, up to four summary requests in all.

The last request publishes any finished text answer, so a loosely shaped handoff
never stops the agent. An empty or refused summary fails at once.

Before either request, Autolith captures a fixed history cutoff. The checkpoint
includes unresolved calls with correlated actual or interrupted/unknown outputs,
plus results and steering received during summarization. Running jobs and
undelivered outcomes are recorded separately from the model-written summary.
Ordinary requests include bounded authoritative job references and an omitted
count; inspect =job.continuity=, =job.*= and their resources for full details.
Provider-family changes use the portable handoff and exclude foreign private
context.

Portable compaction summarizes older history and retains a verbatim recent tail,
normally at most two user turns and 32,768 characters. The latest actual user
request and protocol-required tool/reasoning groups can exceed that bound. Current
mission policy and the authoritative active plan are rebuilt from their stores
for each ordinary request, independently of the summary.

Automatic compaction compares freshly projected input with the soft threshold.
Before transport, admission checks the encoded request, including current tools
and temporary context, with output headroom. Set
=(settings :context-output-reserve 8192)= to reserve at least 8,192 tokens, or use
=AUTOLITH_CONTEXT_OUTPUT_RESERVE=. A larger explicit generation cap takes precedence.
The local count is an estimate, with separate image allowances, rather than a
provider tokenizer or paid usage. Candidate checkpoints are admitted with arrivals
before publication; a rejected candidate leaves the previous projection intact.

Set =ANALYTICS_EVENTS_FILE= to export completed streaming calls as UTF-8 JSONL
usage events. =ANALYTICS_ACTOR= overrides the operating-system username. Each
schema-v1 =llm-usage= event contains the UTC timestamp, actor, model, request
count, elapsed seconds, and known input, output, and cached token counts.
Unknown token counts are omitted. Export is disabled without a destination.
Appends are synchronous and serialized across processes; export errors do not
abort a completed provider call.

Mechanical precompaction bounds oversized old tool output before a request,
but only after an explicitly declared cache lifetime expires or the
provider/model changes. A retention estimate alone never permits rewriting
served history.

Excerpts include the head and tail, failure status, uncertainty about external
effects, and a retrievable conversation/call reference. Calls, reasoning, and
failed attempts are retained. Full outputs are available in the durable
transcript; the latest user turn is untouched. Each precompaction is recorded
and replayed on resume.

A same-provider/model resume preserves its prefix unless a known lifetime has
elapsed. If a conversation has no recorded response identity, it is prepared
once on resume. Manual, context-threshold, and scheduled idle compaction can
still replace history with a summary, including when its cache lifetime is unknown.

Idle cache compaction is enabled by default. After a completed request with at
least 32,768 prompt tokens and 131,072 characters of summarizable history, an
idle session can compact two minutes before its estimated cache expiry. The
timer starts when the request starts, not when its response finishes. User
input, drafts, active work and shutdown take priority. Each opportunity is used
once, including after failure. Resumed sessions need a new completed request
before scheduling one.

Use =(settings :idle-compaction-p nil)= to disable it. The ChatGPT subscription
route uses a conservative five-minute inactivity estimate. For Anthropic and
OpenRouter Claude, the requested cache lifetime supplies the estimate. Other
providers need an explicit estimate for idle compaction, for example
=(settings :prompt-cache-retention-seconds 1800)= for thirty minutes. A positive
value also declares a lifetime for precompaction; this is a user declaration,
not evidence from the provider. Set it to zero to use the provider policy.
Both settings persist across restarts. The ChatGPT estimate alone never
permits idle precompaction; that route has no declared lifetime by default.

=(settings :prompt-cache-ttl "1h")= asks the Anthropic API and OpenRouter
Claude models to keep cache entries for one hour instead of five minutes. A
one-hour cache write costs twice the base input price, against 1.25 times for
five minutes. The longer lifetime can avoid rewrites after pauses of five
minutes to an hour; whether it saves money depends on reuse. Other routes
ignore the setting. The requested lifetime supplies both the declared lifetime
for precompaction and the estimate for idle compaction. An explicit
=:prompt-cache-retention-seconds= setting takes precedence for both local
policies. OpenRouter requests carry the conversation's cache key as their
session identifier for upstream routing affinity from the first request.

Use =(status)= to inspect this process's model-request costs. A request is priced
by the charge its provider reports, as OpenRouter does, else by a price
snapshot for its model: the built-in Anthropic API list prices, or
=(settings :model-prices "{\"model\": {\"input\": 2, \"cache_read\": 0.2, \"output\": 10}}")=
in US dollars per million tokens, keyed by the model name from =(model)=. A
missing cache_write rate charges cache writes as input. Requests without a
price, such as subscription routes, are counted as unpriced, not free.
=(settings :cost-limit 5)= refuses new model requests, compaction and
inference frames included, once reported and estimated spending reaches five
dollars; zero disables the limit. Unpriced requests do not count toward it.

Cache retention depends on the provider, model, routing and account policy.
The [[https://developers.openai.com/api/docs/guides/prompt-caching][OpenAI API cache documentation]] describes a thirty-minute default for
GPT-5.6 and later; it does not establish a retention contract for the ChatGPT
subscription route. Idle compaction uses the ordinary paid checkpoint and
summary path. It can reduce the context sent after a long pause, but neither a
cache hit nor a net saving is guaranteed.

Use =(cache-misses t)= to enable notices when cached reads fall by at least
128 tokens, including accumulated smaller losses. Notices also appear when
cached reads remain flat while shared request history grows by at least
16,384 characters and at least one sixteenth of its reference size. Temporary
context and newly offered history are excluded from shared growth.

A cache miss reports measured lost reads. A stall reports shared-history growth
in characters because its token count is unknown. Both show cached and total
input tokens and start with a red =!=. Model changes, idle intervals and
smaller prompts are local observations, not proof of eviction or routing failure.

Each notice also identifies changes in the request as sent, compared with the
previous request: top-level fields such as =tools= or =system=, the first item
in the previous request's reusable prefix that the new request changes or
omits, and moved cache markers.

The reusable prefix stops before temporary context and one-response exchanges,
so appended history does not count as a change. If a request repeats the whole
prefix, the notice reads =prefix intact=: the provider did not extend its
cache. These comparisons use digests of the final request, not provider
counters, and retain no prompt text.

The first request after resuming or compacting establishes a fresh baseline.
Without comparable read counters or prefix measurements, no loss is inferred
from total input. The setting is off by default and persists across restarts.

In Responses requests, skill catalogs and selected skill instructions keep their
first surviving history position instead of moving after each new message.
Autolith reads the current skill contents and checks activation on every request.
Selected instructions expire with the logical turn; only the small selection
call and result enter durable history. Mutable session state and other ordinary
request context follow history. After compaction or removed history boundaries,
Autolith places active skill context after the new history. Use =(context)= to
inspect contribution sizes. Provider cache hits and savings depend on the
provider and are not guaranteed.

** Providers

Register an OpenAI-compatible provider:

#+BEGIN_SRC lisp
(register-openai-compatible-provider
 :name            "my-provider"
 :description     "My OpenAI-compatible provider"
 :endpoint        "https://api.example.com/v1/chat/completions"
 :models-endpoint "https://api.example.com/v1/models")
#+END_SRC

List every model ID known to Autolith without authenticating or starting a session:

#+BEGIN_SRC sh
autolith models | grep gpt
#+END_SRC

The command prints one sorted, deduplicated model ID per line from built-in and
locally configured catalogs.

Inside a session, use =(auth)= to pick a provider interactively or
=(auth "my-provider")= to select one explicitly. From the command line, use
=autolith auth my-provider=.

After a key is saved, static metadata or the last good cache keeps models
available. =(models)= triggers discovery. You can also pass non-secret
=:headers= and static =:models= for descriptions, windows, efforts, or
providers that have no model-list endpoint.

Select a model with =(model "glm-5.3-flash" :provider "neuralwatt")= or
=(model "neuralwatt/glm-5.3-flash")=. Use =(models :provider "neuralwatt")=
to refresh and list one provider, or =(model nil :provider "neuralwatt")=
to filter the interactive picker. The picker and listings show the provider
with each model, including identical IDs offered by different providers.

Bare model IDs use the existing registration precedence. Only a registered
provider name introduces a provider prefix; catalog IDs containing slashes,
such as =hf:zai-org/GLM-5.3-Flash=, are matched intact. If a catalog ID also
looks like another provider's full ID, specify =:provider= to select its exact
catalog ID. An explicit provider and a conflicting qualified prefix signal a
selection error. The selected provider is saved with the model in preferences
and conversation history, so reopening a session uses the same registration.

Select a model for one launch with =--model MODEL=. Use a provider-qualified
ID, or pass =--provider PROVIDER= together with =--model= for an exact catalog
ID. These options work before or after =run-job= and =resume=:

#+begin_src sh
autolith --model my-provider/my-model
autolith --provider my-provider --model hf:custom/model
autolith resume --model my-provider/my-model
autolith run-job --model my-provider/my-model --input job.sexp --output result.sexp
#+end_src

The launch selection takes precedence over environment variables, saved
preferences, and a resumed conversation's model. It does not save a new default;
use =(model ...)= to save a selection. Autolith loads executable initialization
and the local provider catalog before validating the requested model, so providers
registered in =init.lisp= are available. Startup does not fetch a remote catalog;
use =autolith models= to list locally known IDs and =(models)= to refresh them.

The built-in model picker uses =https://models.dev/api.json= for ChatGPT,
Gemini, Grok, Anthropic, Fireworks, OpenCode, OpenRouter, and Mistral metadata.
When you explicitly refresh with =(models)=, Autolith downloads the public
catalog once without provider credentials, selects tool-capable text models,
and updates descriptions, context windows, and reasoning efforts.

Startup reads the last-good local cache without a network request. Failed
refreshes retain cached models, and built-in seed metadata supports a first
offline start. Custom provider registrations and overridden discovery endpoints
retain their own discovery.

Copilot retains its account-specific catalog because that catalog also supplies
authorized protocol routes. Nous retains its account catalog because models.dev
has no corresponding source. ChatGPT, Gemini, and Grok subscription adapters
update metadata only for the model IDs their transports support. Public API
availability alone does not establish subscription access.

** Commands

Use =(btw)= or =(side)= to inspect the running session without interrupting a
turn. Select one field with =(btw :focus)=, =(btw :elapsed)=, =(btw :tasks)=,
=(btw :queue)=, =(btw :step)=, or =(btw :eta)=.

The colored =◆ status= entry shows the current objective or latest user input,
elapsed and accumulated working time, queued/running task counts, pending input,
and the current activity. Completion time is unknown. Status inspection uses
live memory without tools or a model request. Ctrl-PgUp and Ctrl-PgDn include
these entries among message jump points.

Status output is durable display-only history. Resume and replay include it;
rebuilt model input, compaction summaries, and recent-operation context exclude
it. A status query advances the durable record sequence without adding a user
turn.

Put user commands in =${XDG_CONFIG_HOME:-~/.config}/autolith/init.lisp=, or load
a user-owned Lisp file from there. Autolith loads those definitions after the
tracked system on each startup, including after a source update or an installed
upgrade. Use the existing =define-application-command= form; Lisp names, slash
aliases, completion, and busy/terminal policy share its registration.

#+BEGIN_SRC lisp
(define-application-command my-version-command
    (:name              "/my-version"
     :aliases           ("/local-version")
     :argument          "[LABEL]"
     :description       "show a labeled local integration version"
     :tip               "shows the version supplied by init.lisp."
     :busy-behavior     :execute
     :terminal-behavior :shared
     :callable          t)
    (application &optional (label "integration"))
  (application-present application (format nil "~A 3" label))
  :continue)
#+END_SRC

- Callable handlers accept ordinary Lisp lambda lists, including =&key= and
  supplied-p parameters. Lisp argument values reach the handler directly.
- Use =:slash-parser function-name= for commands with structured or action
  arguments. Define the function before the command. It receives the complete
  slash remainder and returns a list of native handler arguments. Parser and
  handler functions are captured when you register the command.
- Missing interactive arguments open the restart debugger. =supply-arguments=
  takes one Lisp form of replacement arguments. Excess slash arguments are
  rejected before dispatch. Programmatic calls keep ordinary Common Lisp arity
  rules.
- Busy behavior is =:inspect=, =:execute=, =:apply=, =:hold=, or =:cancel=.
  During active work, =:execute= runs immediately, =:apply= applies its
  change at the turn's next safe provider boundary, and =:hold= waits for
  the idle queue. Argument-free =:inspect= and =:apply= invocations only
  display state, so they run immediately. An unknown command reports its
  error immediately instead of being scheduled.
- Terminal behavior is =:shared=, =:exclusive=, or
  =:exclusive-without-arguments=. It declares which invocations open a modal
  picker so active work keeps them off the immediate reader path. A modal
  picker requires exclusive terminal input when open. The responsive reader
  continues animating until then.
- =:static-options= replaces =:argument= for one finite positional parameter.
  Supply native strings, keywords, or booleans to derive the help hint and
  completions. Use =(t nil)= for boolean controls. Define a slash parser to
  translate text choices to native values.

** Live definitions

Use =self.redefine= to install loaded Lisp definitions, new or replacing,
including functions and methods outside the Autolith package. =self.define=
names the same tool. Qualify the target symbol in the source,
or supply the =package= argument to select its reader package. Use qualified
symbols with =self.set= for foreign global bindings.

Installation, discard and replay temporarily unlock the reader and target
packages, then restore their locks. New definition records include the target's
owning package separately from the reader package. Replay skips stale definitions
whose ownership moved to another library. Reapply an old skipped definition to
record an intentional replacement under its current owner.

Tracked source takes precedence over private replay. Each published definition
records the tracked source it shadowed, or records that it introduced a new name.
Startup replay skips a definition if its tracked definition changed, was removed,
or appeared since publication. One startup notice lists every skip, grouped by
reason. Skipped definitions are left out of the next =self.commit=.

For commits published before this record was introduced, tracked overrides replay
only while the image runs the source revision the lineage was published against.

To restore a skipped definition, reapply it against the current source. Or use
=(fix-skipped-definitions)= to give the model every skipped definition, along
with its persisted source, the tracked source it was written against, and the
current tracked source. Supply an optional comment to say which overrides to
retain or drop:

#+BEGIN_SRC lisp
(fix-skipped-definitions "Drop all of these. They were temporary development experiments.")
#+END_SRC

The comment takes precedence over the default repair policy. By default, the
model rebuilds each override on the current source with =self.redefine= and
drops any the tracked source already covers. It publishes the result with
=self.commit=, including when all skipped overrides are dropped. During an
active turn, the command waits in the idle queue.

** Refinement

Use =self.refine= to record trajectory evidence, choose the smallest useful target
or =none=, and exercise existing memory, context, skill, role, RLM or mutation
operations. Every transition names the proposal ID and its observed revision.
Evaluation records actual task observations separately from owner compile/replay
checks. Inspect proposals with =(refine)= and supply a local assessment before
promotion:

#+BEGIN_SRC lisp
(refine :assess "PROPOSAL-ID" :revision 3 :verdict :passed
        :evidence "Evidence from a separate task")
#+END_SRC

Promotion proceeds from session to project to global scope, with renewed evaluation
at each scope and an owner-state guard against intervening changes. Recover an
interrupted operation explicitly using recorded evidence; replay never repeats its
effects automatically.

** Executable Skills

Use =skill.load= with an exact catalog name to select prose instructions for the
logical turn. To publish executable behavior, put a bounded data-only
=EXECUTABLE.sexp= beside =SKILL.md= or =SKILL.sexp=. Declare the Skill and ASDF
system versions, entrypoint, input/output contracts, capabilities and exact host
tool names. An executable manifest has this shape:

#+BEGIN_SRC lisp
(:skill-executable :format-version 1 :skill-version "1.0.0"
 :system "my-workflow" :system-version "1.0.0"
 :entrypoint ("MY-WORKFLOW" "RUN")
 :self-test ("MY-WORKFLOW" "SELF-TEST")
 :verify ("MY-WORKFLOW" "VERIFY")
 :capabilities ("workspace-read") :tools ("resource.read")
 :input (:type :object) :output (:type :object))
#+END_SRC

The invocation function accepts =input &key context=; self-test and verification
functions accept =&key context=. Input and output use the native portable JSON
representation, such as =(:object ("status" "ready"))=. Install the declared
ASDF system in the worker environment, or supply its authorized =asd= pathname.
Call =skill.invoke= with =name= and contract-valid =input=:

#+BEGIN_SRC json
{"name":"my-workflow","input":{},
 "asd":".autolith/skills/my-workflow/my-workflow.asd","async":true}
#+END_SRC

Use =skill.verify= with =name= to run the self-test; set =entrypoint= to =verify=
for the verification function. Each operation requires ordinary explicit
full-access code authorization and runs in a fresh disposable worker. Capabilities
are declarations for admission; only declared exact host tools allowed by the
originating agent policy enter the callback bridge. Source and sidecar identity
and the complete manifest are rechecked before loading executable code; declared
ASDF versions are checked during authorized system resolution.

Invocation output is contract-validated and retained with its executable identity
as native execution evidence. Result publication is bounded to 1 MiB and read as
one data-only form after stopping the worker. Use =async: true= for managed jobs;
completion policy applies as described below. Inspect full results with =job.get=
or deliberately await them with =job.wait=. Mission accounting and ordinary
execution supervision apply to workflows and their callbacks.

** Worker tool calls

Supply =host-tools=, an array of exact tool names, to =lisp.eval= or
=lisp.scratchpad-run= for an explicitly authorized workflow request. Inside that
request, call:

#+BEGIN_SRC lisp
(autolith:worker-tool-call "resource.read" "{\"uri\":\"workspace:src/main.lisp\"}")
(autolith:worker-tool-context)
#+END_SRC

Read =:success-p=, =:content=, =:code= and =:details= from the returned result.
The host dispatch retains the originating conversation, callbacks, capability
policy, mission context and job lineage. Requests and results are bounded and
correlated in the conversation audit. Sequential callbacks are supported; choose
a different REPL for nested worker operations. Omit =host-tools= for ordinary
worker execution.

For a Lisp-controlled workflow, branch on returned native results and make the
next authorized call from the same evaluation. For example, pass these arguments
to =lisp.eval=:

#+BEGIN_SRC json
{"host-tools":["resource.read"],
 "forms":["(let ((result (autolith:worker-tool-call \"resource.read\" \"{\\\"uri\\\":\\\"workspace:README.org\\\"}\"))) (if (getf result :success-p) (getf result :content) (getf result :code)))"]}

Host calls pass through ordinary registry authorization with the captured
mission admission, including its absence. An interrupted callback is recorded as
=unknown-outcome= in the audit. Inspect effects before repeating a mutating call.

** Child roles

Roles load from these directories. First match wins:

- =.autolith/agents/=
- =${XDG_CONFIG_HOME:-~/.config}/autolith/agents/=
- =<site-config-root>/agents/=
- bundled roles

A higher-precedence malformed role is reported, not silently replaced.

A role is one bounded UTF-8 =*.sexp= property list:

- required: =:name=, =:description=, =:instructions=
- optional: =:tools=, =:spawns=, =:models=, =:reasoning-effort=, =:output=,
  =:blocking-p=

Roles cannot grant =self.*=, =task.*=, or =yield.*=. Grant =job.*= when a role
needs to inspect, await, or cancel asynchronous work. Children can access only
their own jobs and descendant jobs, not parent or sibling jobs. This is
independent of permission to spawn another child.

- =:tools= may be =nil=, =:all=, or canonical tool names and namespace
  patterns.
- =:spawns= may be =nil=, =:all=, or role names. Task depth still applies.
- =:reasoning-effort= names a supported effort. Omitting it or writing
  =:auto= selects =medium=, so routine delegated work does not inherit the
  parent's effort. Children never inherit Codex Fast mode.
- =:output= is the native schema DSL. There, =nil= is JSON false and
  =:null= is JSON null.

Example:

#+BEGIN_SRC lisp
(:name             "reviewer"
 :description      "Review a change for regressions."
 :instructions     "Report concrete, evidence-backed findings."
 :tools            ("resource.read" "search.*")
 :spawns           nil
 :models           ("@parent")
 :reasoning-effort :high
 :blocking-p t)
#+END_SRC

=task.agents= shows effective roles. =task.run= starts one task or an
independent batch. Nonblocking work detaches by default. =blocking: true=
waits. A role with =:blocking-p t= always waits. Each child must finish
with one =yield.submit= of =success=, =failed=, or =aborted=.
Persisted child results must contain one data-only form with valid terminal
status and field types. The default reading limits are 16 MiB, 128 nesting
levels, and 262,144 tree nodes.

** Completion-driven turns

Set =completion-policy= to =continue= (the default) or =notify= on asynchronous
tools and =task.run=. A batch inherits its outer policy unless an item overrides
it. The policy also applies after the synchronous grace period hands work off.

In a primary terminal session, continue independent work while jobs run. When
only job results are pending, yield the current turn.

Results arrive in the exact conversation that owns the work, with a bounded
summary, the actual outcome and an artifact reference. When the session is idle,
completions within a one-second window share one automatic turn through the
ordinary controller. During a busy turn, results arrive at the next safe request
boundary. With =notify=, they arrive on the next ordinary turn instead.

An empty final reply while eligible jobs run appears as an Autolith yield notice
with the number of unfinished jobs that can wake this conversation. Replayed
notices retain the count at the time of yielding; completed jobs and notify-only
work do not contribute to a new notice.

Automatic continuations for an active goal or mission wait while a job that
will wake the conversation is queued, running or awaiting result delivery.
The goal stays active. When the wakeup arrives, the transcript shows
=∙ continuing with job results=. The goal's continuations resume after that
turn.

Delivery receipts survive restart and conversation compaction. Notifications are
reconstructed from terminal artifacts without repeating job effects. Cancellation,
paused or terminal missions, spent budgets, and conversation ownership constrain
automatic turns. Inspect retained results with =job.get=, =job.continuity= or =(tasks)=.

Outside a child's exact conversation, its outcomes are available only for
inspection. Completing a child does not reopen it or redirect descendant results
into the primary context.

ACP sessions also own a completion controller and stream automatic turns to the
connected client. Interfaces without an input controller deliver results on
subsequent ordinary turns. Use =job.wait= when deliberate waiting is appropriate.

** Task inspection and continuity

Use =(tasks)= for a compact nonmodal inventory of owned live and durable work,
including lineage, timing, reported usage, recent activity and artifact paths:

#+BEGIN_SRC lisp
(tasks :list :offset 32 :limit 32)
(tasks :get "JOB-ID")
(tasks :transcript "JOB-ID" :offset 0 :limit 4000)
(tasks :send "JOB-ID" :message "Inspect the failing check before continuing.")
(tasks :cancel "JOB-ID")
#+END_SRC

Lists show 32 tasks per page, with live work first. Use =:offset= and =:limit=
(up to 64) to navigate.

Transcript bounds are character counts, defaulting to 0 and 4000. Use the
shown next offset for another window. The =:get=, =:send= and =:cancel= actions
use the ordinary owned job operations and authorization.

Use =job.continuity= with =action= =list= or =get= to classify retained work as
live detached, completed, reconstructible from a checkpoint, safe to restart,
abandoned or needing a decision. List pages contain whole records with
=:total=, =:next-offset= and =:more-p=; =offset= defaults to 0 and =limit= to 20
(maximum 100). Supply a visible job or durable execution =id= for other actions.

The primary owner may declare =allow-restart= with a =safety= rationale and
=authorize: true=, or declare =checkpoint= with a compatible saved worker
=image=, target =repl= and the same explicit authority. A safety rationale is
an assertion about repeating external effects. Revival reattaches live work,
starts the named REPL from its saved image, or dispatches a new child from a safe
retained shared-workspace task specification:

#+BEGIN_SRC lisp
(tasks :revive "JOB-ID" :authorize t)
(tasks :abandon "EXECUTION-ID" :authorize t)
#+END_SRC

For equivalent =job.continuity= calls, use =revive= or =abandon= with =id= and
=authorize: true=. The recovery decision is durably recorded before dispatch
and links the old execution to the new execution.

A failed or interrupted revival consumes its claim and records an uncertain
outcome for explicit inspection. When you resume a conversation, you see this
inventory for a decision. Resuming does not replay the work.

** Granted peer messages

The primary owner establishes directional communication with =peer.grant=.
Supply an immutable grant =id=, =sender= and =receiver= as primary-visible job
IDs or =primary=. For example, these arguments grant one child permission to send
coordination data to the primary:

#+BEGIN_SRC json
{"id":"build-report","sender":"CHILD-JOB-ID","receiver":"primary","context":true}
#+END_SRC

Each participating actor uses =peer.discover= to inspect its current grants and
exact endpoint identities. Call =peer.send= with a stable message =id=, the
receiver's endpoint ID from discovery, and =text= of 1 to 8192 characters.
The sender is the actual executing actor. =peer.receive= claims incoming work
and returns a delivery token; use =peer.ack= with =id= and =token= after handling
it. =peer.wait= waits for incoming work or a named message acknowledgment, with
=timeout= bounded to five seconds. =peer.inspect= returns scoped metadata pages
or the payload and recovery token for an exact message =id=.

With =context: true= on the grant, receive coordination data at the existing
safe steering boundary. Acknowledgment follows durable persistence of that
input. Peer text is coordination data, not additional tool or execution authority.
Children need their ordinary role permission for each =peer= tool; grants do
not expose parent or sibling job-control operations.

Cross-session communication requires paired explicit grants on both sessions.
Set =remote-session= and =direction= (=outgoing= or =incoming=); name a remote
child with both =remote-job= and =remote-execution=, or omit both for its primary.
Transport uses authenticated local daemon discovery. =peer.revoke= durably
revokes a grant. Endpoints include exact execution identity, so a replacement
child does not inherit its predecessor's grant.

Grants and messages restore with the session; interrupted deliveries become
uncertain. Keep the same stable message ID when transport completion is unknown.
Only the primary may call =peer.resolve= with =id=, current =token= and =action=
=acknowledge=, =retry= or =cancel=; retry requires a current grant. Final session
finish closes its mailbox, while transient daemon handoff preserves delivery
state.

** Engineering task artifacts

Select the bundled =engineering= role or give a native role =:output :engineering=.
The version-1 contract requires =schemaVersion=, =baseline= (=kind=, =workspace=,
=revision=), =change= (=kind=, =reference=), =paths=, =checks=, =evidence=, =issues=
and =integrationNotes=. =symbols= is optional.

For each check, include the command, status (=passed=, =failed=, =skipped= or
=not-run=) and summary. Evidence references are optional. Use baseline kind
=unknown= when no revision is available and change kind =none= when no change
was produced.

Extend the common contract in a native role:

#+BEGIN_SRC lisp
:output (:type :engineering
         :properties (("review" (:type :string)))
         :required ("review"))
#+END_SRC

Common properties cannot be overridden. The usual structured =yield.submit= and
durable result transport validate and retain these values. Checks and evidence
are child-reported observations; mission gates establish harness acceptance.
A failed or aborted child follows the ordinary error-only terminal contract.

** Isolated modifying tasks

Supply an =isolation= object in a flat =task.run= call or in each selected batch
item. Omit it for the ordinary shared workspace. The object accepts =baseline=
(a commit-resolving revision, default =HEAD=), =dirtyPolicy= (=reject= by default,
or explicit =ignore=), and =artifactKind= (=patch= by default, or =commit-range=).
With =ignore=, use only the committed baseline; staged, unstaged and untracked
source edits are excluded. Git isolation is unavailable for non-Git workspaces.

Sandboxed commands in an isolated child may write its owned checkout and the
repository's Git administrative directories, including a linked worktree's common
Git directory. Integration requires authorization for the target workspace.

The child edits and tests in its detached checkout. Before it starts, persist the
source repository, exact resolved baseline, isolated path and conversation-qualified
owner. Stage new files before yielding.

A patch includes committed and uncommitted tracked changes. A commit range
requires a clean checkout and an ancestor baseline.

Terminal results identify the secured engineering artifact, including when a
task is aborted. If extraction fails, the checkout is retained and the result
reports =:worktree-error=. A successful child without a complete artifact is
reported as failed.

Use =task.worktree= with an explicit =action=:

- =inspect= returns provenance, touched paths and the durable artifact pathname;
  =extract= explicitly retries extraction after repairing an incomplete checkout.
  Supply a visible terminal job =id= or its durable execution ID.
- =check= verifies patch applicability without mutation. =apply= applies the patch
  to the clean target's index and working tree; =commits= cherry-picks the recorded
  commit range. Supply =id= and an explicit =target= repository.
- =conflicts= inspects unmerged paths; =abort= explicitly aborts an interrupted
  cherry-pick. Supply the target repository.
- =cleanup= removes only the task's owned checkout. Dirty cleanup requires
  =discardDirty: true=. Secured artifacts are independent of checkout removal.
- =discover= lists this conversation's active and absent owned records. Supply
  =source= to recover interrupted registry publication from Git markers.
  =cleanup-orphan= uses a discovery worktree =id= and explicit =source=, including
  after task-result publication failed. Unrelated worktrees are excluded.

Git lifecycle and integration commands use ordinary command authorization and
execution policy. Target paths use ordinary tool-path authorization. Isolation
is an accidental-overlap boundary, not hostile-code confinement. The parent
chooses integration order and resolves conflicts deliberately.

Primary shell and Lisp executions and child agents appear as live rows with
spinners and elapsed time. The command and agent strips share a viewport bound,
and provider activity remains visible below them. You can supply a short
=:description= in a =shell.run= call to set its row label. Otherwise, the label
is derived from the command.

Use POSIX shell syntax for commands on POSIX hosts and PowerShell syntax on
Windows. Both Windows authorization modes use native PowerShell. MSYS/Git Bash
requires a shared object namespace that AppContainer does not permit.

On Windows, sandboxed commands execute serially while temporary filesystem
ACLs are installed. Their writable temporary directory is removed after
completion or cancellation. For tools installed outside system application
directories, add existing read-only tool directories through
=*win32-sandbox-read-roots*=.

Windows scopes must be local directories with no reparse points or hard-linked
files. If a scope is unsupported or the helper is unavailable, execution fails
rather than proceeding without isolation.

The default pool admits eight concurrent children.
=AUTOLITH_TASK_MAX_CONCURRENCY= raises that up to 32. =AUTOLITH_TASK_MAX_DEPTH=,
default 2, is how many levels of child agents may sit below a top-level
agent; a child at the last level cannot create children. Child jobs have no
deadline unless =AUTOLITH_TASK_MAX_RUNTIME_MS= is set positive.

** Retained command output

Use =shell.run= for synchronous commands, detached commands and command mission
gates. Each authorized invocation receives private execution-owned raw captures
before launch. Results include exit, timeout and cancellation status, retained and
observed byte counts, capture completeness, and stable =shell-log:= references.
The inline preview samples the beginning and end, with most space reserved for
trailing diagnostics. Set =separate-output: true= to capture stdout and stderr
independently; the preview allocates more space to stderr.

Read a reference with =resource.read= using zero-based =byte-offset= and
=byte-count= (default and maximum 4096 bytes). Use =query= for a literal UTF-8
search, optionally =max-results= and =byte-offset=. Continue with the returned
next offset. Each search scans at most 1 MiB and returns at most 20 excerpts.
Text rendering replaces invalid UTF-8; the retained files contain the original
bytes. Access follows the owning conversation and ordinary task-descendant
inspection authority.

References are included in job inspection, durable tool-result metadata and
completion notices. Reopen them after restart or compaction without executing
the command again. Missing, interrupted and pruned captures return diagnostics.

The defaults are 64 MiB per stream, 1 GiB of reserved capture capacity and 256
retained artifacts. Eligible completed captures can be pruned at the next
allocation, either after seven days or under capacity pressure. Active captures
and undelivered completion evidence are protected.

If delivery is observed before child artifact retention, the observation is
recorded on each capture. This allows normal pruning after the owner's
conversation storage is removed.

Adjust =*shell-log-capture-byte-limit*=, =*shell-log-retention-byte-limit*=,
=*shell-log-retention-count-limit*= and =*shell-log-retention-age*= in trusted
configuration. Captures that exceed their limit are explicitly marked incomplete.

Session export collects task metadata independently of local log storage.

* Non-interactive jobs

=run-job= executes one caller-supplied child role without an interactive
terminal. It uses normal project, user, and bundled task-agent discovery,
provider and MCP configuration, role tool and spawn policy, task traces, usage
accounting, and native structured-output contracts.

#+BEGIN_SRC sh
autolith --permissions auto run-job \
  --input /path/to/job.sexp \
  --output /path/to/result.sexp
#+END_SRC

The input is exactly one bounded data-only S-expression:

#+BEGIN_SRC lisp
(:autolith-job
 :version 1
 :id "job-identifier"
 :role "project-role"
 :prompt "Perform the assigned work."
 :input (:caller-owned "opaque data")
 :output-contract (:type :object
                   :properties (("answer" (:type :string)))
                   :required ("answer")
                   :additional-properties nil)
 :timeout-seconds 900)
#+END_SRC

The supplied output contract applies only to that run and does not alter the
role definition.

The terminal artifact is atomically installed at =--output= as
=(:autolith-job-result :version 1 ...)=. Structured objects and arrays use
=:OBJECT= and =:ARRAY= tags, so false, null, and empty arrays remain distinct.

Failures use stable categories and statuses =:failed=, =:cancelled=, or
=:timed-out=. Successful jobs use =:succeeded= and include the contracted
result. Trace and usage fields are included when available.

Headless execution never opens an approval picker. =auto= classifies shell
commands and denies decisions that would require approval. =sandbox= permits
only sandboxed commands. =full= permits full command execution. External tool
calls whose configured policy requires approval are denied unless full access
was selected. The role allowlist remains the child capability boundary.

** Live S-expression events

Add =--events sexp= to observe a run on stdout. Capture diagnostics separately on
stderr and read the authoritative terminal result from =--output=:

#+BEGIN_SRC sh
autolith --permissions auto run-job \
  --input /path/to/job.sexp --output /path/to/result.sexp \
  --events sexp >events.sexp 2>diagnostics.log
#+END_SRC

Read consecutive top-level data forms, rather than splitting physical lines.
Strings may contain newlines. Each version-one record has this shape:

#+BEGIN_SRC lisp
(:autolith-event :version 1
 :run-id "a-generated-run-uuid" :seq 1 :time "2026-10-08T09:00:00Z"
 :kind :run-started :data nil)
#+END_SRC

The event kinds are =:run-started=, =:job-started=, =:tool-started=, =:progress=,
=:tool-finished=, =:job-finished=, =:usage=, =:warning=, =:progress-omitted=, and
=:run-finished=. Ignore unknown versioned kinds.

Sequence numbers increase strictly within one run. Job and execution
identifiers are opaque execution UUIDs; provider call identifiers are
pseudonymous within that run. Tool names come from the registered tool catalog.

Observe only the requested root and its owned descendants, excluding other
roots in the same conversation. Event data contains allowlisted statuses and
numeric counters, not prompts, tool arguments, tool output, or provider
payloads.
Interactive input is EOF, and diagnostic/query streams go to stderr in the
initiating thread and its workers.

Use =run-job-event-read-stream= to read one validated record at a time, returning
NIL at EOF. It uses the bounded =sexp-config= data grammar with =*read-eval*= NIL.
Only approved keywords, strings, NIL/T, bounded nonnegative integers, and finite
proper lists are accepted. The maximum record size is 16 KiB of UTF-8; character
streams supplied to the library must already use UTF-8. Binary streams receive
UTF-8 octets.

Root =:job-finished= and final =:run-finished= records follow atomic result
publication. Published terminal job events include a =:result-uri= resource
reference; descendant references identify execution-qualified artifacts. The
final data includes =:status= and =:published-p=; successful publication also
includes =:output-path=. An output write failure reports
=:failed=, =:published-p nil=, and =:category :result-publication-failed=, with a
nonzero exit status. Inspect the result artifact for contracted data and full
failure details.

Delivery is best effort through one bounded queue and a single writer. Progress
may be omitted under backpressure, with =:progress-omitted= reporting its count.
Lifecycle overflow is reported with =:warning= and =:code :queue-full=; final
delivery has a reserved slot. A slow or disconnected consumer may miss the
terminal record; execution and result publication continue. There is no replay
or reconnect cursor. For a new invocation, expect a new run UUID and sequence
beginning at one.

From Lisp, call =run-job-run= with =:events :sexp= and =:event-output STREAM=.
Without the events option, use the existing artifact-only interface.

* Generations and recovery

=(checkpoint)= requires a clean Git worktree and a passing =./script/check=.
On POSIX it saves a retained image without stopping the active session. On
Windows it saves the exact live heap, restarts through the stable launcher, and
resumes the active conversation after the saved image passes its probe.

- =(generations)= lists retained images.
- =(rollback ID)= selects a compatible image and exits through recovery.

Inspect or boot retained generations from the CLI:

#+BEGIN_SRC sh
autolith --recovery --list
autolith --recovery --generation GENERATION-ID
#+END_SRC

Recovery starts the separately built pristine core, not the damaged active
core. If that image is missing or invalid, it falls back to source.

Automatic recovery boots a private clean checkout of current committed source
with =--pristine=. It does not load retained generations or private mutation
replay. An intentional =(rollback ID)= still boots the selected generation.
Explicit generation selection may use an older revision.

To start a rescue session directly, use:

#+BEGIN_SRC sh
autolith resume --pristine --permissions full
#+END_SRC

With =--pristine=, the process uses tracked source instead of a saved active
core. It skips the selected private image commit, mutation journal
reconstruction, and executable user initialization.

The process also runs with =--immutable=, so ordinary self-mutation tools
cannot replace the selected private commit. Mutation and conversation data
are not erased.

A fatal active failure publishes a private crash capsule and restores the
terminal. Recovery restores the conversation without duplicating scrollback.
With a valid capsule, it queues one read-only diagnosis turn before ordinary
input.

That turn can inspect:

- bounded crash context
- workspace and tracked source
- indexed source
- active state

It has no shell, MCP, hosted provider, image, write, mutation, checkpoint,
or rollback tools. It asks before any repair. A manually started recovery
image does not queue diagnosis.

Saved cores require their recorded SBCL version, OS build, and architecture.
Source remains authoritative. To reconstruct without a core, check out the
manifest revision, run =./script/bootstrap=, load =autolith=, then load the
manifest's ordered =reconstruct.lisp= in package =AUTOLITH=:

#+BEGIN_SRC lisp
(asdf:load-asd (truename "autolith.asd"))
(asdf:load-system :autolith)
(load #P"/path/from/generation/manifest/reconstruct.lisp")
#+END_SRC
