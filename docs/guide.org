#+TITLE: New User Guide
#+STARTUP: content

* Install, update, and uninstall

** Nix

To launch Autolith without installing a command, run:

#+BEGIN_SRC sh
nix run github:lambda-symbolics/autolith
#+END_SRC

You can pass Autolith arguments after =--=. To get a command on your =PATH=,
use =nix profile install github:lambda-symbolics/autolith=.

Nix supports x86-64 and ARM64 Linux and Apple silicon macOS. On first launch,
the images are built under =${XDG_DATA_HOME:-~/.local/share}/autolith/nix/images/=.

** Linux, macOS, and BSD
:PROPERTIES:
:CUSTOM_ID: linux-binary-release
:END:

Inspect the [[https://sh.lambda-symbolics.com/autolith][shell installer]] before you run it:

#+BEGIN_SRC sh
curl -fsSL https://sh.lambda-symbolics.com/autolith | sh
#+END_SRC

The shell installer selects a package for your operating system and CPU:

- Linux: x86-64 and ARM64, for glibc and musl
- macOS: Intel and Apple silicon
- FreeBSD, NetBSD, and OpenBSD: x86-64

On Apple silicon, use the native arm64 release even when installing from a
Rosetta shell. You can also start that release from a translated application,
such as AUI's =Try again= after stopping the server in Terminal.

Make sure that =~/.local/bin= is on your =PATH= if you use the default command
location. Install OpenSSL before running the script. On Linux, also install
Bubblewrap (=bwrap=) for filesystem and network isolation.

** Windows

On Windows x86-64, inspect the [[https://sh.lambda-symbolics.com/autolith.ps1][PowerShell installer]] before you run it:

#+BEGIN_SRC powershell
Invoke-RestMethod https://sh.lambda-symbolics.com/autolith.ps1 | Invoke-Expression
#+END_SRC

Restart Windows Terminal so that you can use the updated =PATH=. Sandboxed
commands run in an AppContainer without network access. They can write to
the workspace and a private temporary directory.

The SHA-256 of the release archive is verified before extraction on all
platforms. See [[file:release-service.org][Release service]] for how archives are published.

** Update

For a packaged installation, run =autolith update= and then start Autolith
again. Use =autolith update --help= to see the command syntax. To update and
restart from a running session, enter =(update)=. Your original launch
arguments are used for the restart. Automatic update checks run at most once
every 20 hours.

For Nix, update the flake input or upgrade the package in your Nix profile.
For a source installation, update the checkout and run the bootstrap command
again.

** Source checkout

1. Install a compatible SBCL as specified in =sbcl-minimum.version=. Use
   =AUTOLITH_SBCL= to select a specific runtime.
2. Install [[https://www.quicklisp.org/beta/][Quicklisp]] under =~/quicklisp=, along with Rust, CMake, pkg-config,
   and OpenSSL. On Linux, install Bubblewrap as well.
3. From the checkout, run =./script/bootstrap=. Use =./script/check= to check
   the build.
4. Start Autolith with =./bin/autolith=. To run it from other directories, link
   =bin/autolith= into a directory on your =PATH=.

During bootstrap, follow the progress bar for the current build step. Output
from successful steps is hidden. If a step fails, read its captured output and
exit status below the progress bar.

Use =--list= to see test names, =--suite NAME= to select a suite, or
=--test NAME= to select one test. You can repeat the selectors. For example:

#+BEGIN_SRC sh
./script/check --suite workspace-resource --suite fixtures
./script/check --test test-workspace-file-resources --jobs 1
#+END_SRC

Use =--jobs= to set the number of workers and =--timeout= to set the time
limit per worker in seconds. Selected runs skip the recovery checks.

** Windows source checkout

1. Install Git for Windows, Rust with the MSVC toolchain, and Quicklisp under
   =%USERPROFILE%\quicklisp=. Put =clang= on =PATH= for ColorLisp. You can use
   OpenSSL 3 from Git for Windows or set =AUTOLITH_OPENSSL_DIRECTORY= to the
   directory that contains it.
2. From PowerShell in the checkout, run =.\script\bootstrap.ps1=. If there is
   no compatible SBCL, a runtime is downloaded and verified against the
   checksum in =sbcl-windows-releases.sha256=.
3. Use =.\script\check.ps1= to check the build. It accepts the same selectors
   as =./script/check=.
4. In Windows Terminal, start =.\bin\autolith.cmd= or =.\bin\autolith.ps1=.

** Uninstall

1. Stop running sessions.
2. Run =autolith uninstall=. On Windows, delete the folders listed by the
   command. On other platforms, review the paths before confirming or pass
   =--yes= if no terminal is attached.
3. If you used Nix, remove Autolith from the flake or profile. If you built a
   checkout, delete the checkout separately.

The installation, managed runtimes, built images, and caches are removed.
Your conversations, memories, image commits, configuration, and credentials
are kept.

* First session

1. *Connect a model provider.* To use ChatGPT, run =autolith auth chatgpt=
   and follow the prompts. If you use =nix run=, run
   =nix run github:lambda-symbolics/autolith -- auth chatgpt= instead.
   To use a local model, see [[https://lambda-symbolics.com/autolith/docs/configure-autolith#run-a-local-model][Set up local inference]].
2. *Open a channel.* Run =autolith= or =nix run github:lambda-symbolics/autolith=
   in the directory where you want to work. Type a request or Lisp form at the
   startup prompt to create a channel and submit it, or select =inbox= or an
   existing channel in the sidebar. Use =autolith open= to reopen the most recent
   top-level channel in the workspace, or =autolith open ID= to open a specific channel.
3. *Send your first request.* Try /List the files in this workspace and tell
   me where to start./ To see commands, enter =(help)= in the same prompt.

Write requests in plain text and enter Lisp commands as parenthesized forms.
For example, you can inspect the workspace directly:

#+BEGIN_SRC lisp
(resource.read :uri "workspace:.")
#+END_SRC

- Type an opening parenthesis, bracket, or brace to insert a pair. Type the
  closing delimiter to move past it, or press Backspace inside an empty pair
  to delete both delimiters.
- Press Tab to complete a command, option, path, or =@= mention. If you complete
  a mention, press Tab again to cycle through candidates. Use Shift-Tab to
  cycle backward.
- If there is nothing to complete, Tab submits the prompt or queues it during
  a turn. Finish an open Lisp form before submitting it.

** Onboarding

1. Open a channel. At the boot screen, press Space or Enter to start the tour.
   To go straight to the prompt, press Esc or start typing. Typed and pasted
   text is kept in the prompt.
2. Try the exercises on the prompt, =(help)=, background Lisp, and
   =(settings)=. Edit the exercise input and press Enter to submit it.

- Use Page Up and Page Down to scroll.
- Press Shift-Tab to go back or Tab to skip one slide, including an exercise.
- Press Esc to skip the tour. Press Ctrl-C to interrupt it without marking
  unfinished lessons as skipped.

On later launches, you see only new or revised lessons. Enter =(onboard)= to
replay the full tour. To disable the automatic tour, enter
=(settings :onboarding-p nil)= or set =AUTOLITH_ONBOARDING= to =off=. If you
disable the boot screen, you skip the opening animation.

** Boot screen

- To skip /the wait/, use =(setf (config :boot-screen-linger-p) nil)= or set
  =AUTOLITH_BOOT_LINGER= to =off= for one launch.
- To change the direct-session animation from 3.5 seconds, set
  =:boot-screen-seconds= or =AUTOLITH_BOOT_DURATION=. A hosted channel shows
  actual progress and does not replay the animation.
- To skip /the boot screen/, use =(setf (config :boot-screen-p) nil)= or set
  =AUTOLITH_BOOT_SCREEN= to =off=. See =(settings)= for these options.

* Talk to Autolith

** Prose, Lisp, and commands

Type a request in plain text to send it to the current channel. For example,
ask Autolith to review a change and name the file or test you want it to check.
Type =@= to complete a workspace path or a participant handle. A token that
contains a slash is treated as a path.

Start input with =(= to evaluate Common Lisp in the active image. Autolith
passes the form and its result to the model. The form has its normal effects
in that image. To send text from a file, or to attach an image, use
=channel.send=:

#+BEGIN_SRC lisp
(channel.send :text (read-file "request.org"))
(channel.send :channel "@test-review" :text "Run the focused tests.")
(channel.send :text "Review this diagram" :images #("/tmp/diagram.png"))
#+END_SRC

- Run =(help)= for an overview or =(help :commands)= for the command list.
- Use a keyword for a topic, as in =(help :conversations)=. Use a quoted command
  or a tool name for its arguments, as in =(help 'open)= or =(help "lisp.eval")=.
  Browse a namespace with =(help :lisp)= or use =(help :all)= for the full
  reference.
- Press Tab after =(help = to complete a topic or operation. For command
  options, press Tab after a command name and a space. For example, complete
  =(ste t)= to request Simple Technical English and =(ste nil)= to turn it off.

Use =?= followed by whitespace to evaluate one Lisp form in the background.
This also works for a bare variable. Input such as =?text= or =??= is plain text.

#+BEGIN_SRC lisp
? *package*
? (progn (sleep 10) (values :finished 42))
#+END_SRC

Use the printed =exec:N= ID to inspect, wait for, or cancel that job:
=(job.get :id "exec:1")=, =(job.wait :id "exec:1")=, or
=(job.cancel :id "exec:1")=. Replace =exec:1= with the ID you received. Click
the printed cancellation form to insert it at the prompt.
The result and captured output go to the original conversation even if you
switch channels. Background Lisp uses EOF for input and reports errors without
an interactive restart picker. Submitting a form this way does not start a model
turn.

When local Lisp or a command fails and the restart picker opens, choose
*Ask Autolith why this failed* to diagnose it while the operation is suspended.
Review the proposed recovery before choosing a restart or retry. A retry does
not undo effects that happened before the error. Escape during diagnosis
returns to the picker; Escape at the picker aborts the failed operation.

During a model turn, Escape cancels that turn and lets queued steering proceed.
Ctrl-C cancels the turn and pauses queued work until your next submission. A
second Ctrl-C within the force-exit window exits the application. Use =(cwd)= to
see the current workspace. If you submit =(cwd "../other-project")= during a
turn, the relative path is resolved when that input reaches its place in the
steering queue.

** Command arguments

Pass Lisp values directly to commands:

- Use keywords for actions, such as =:refresh= in =(mcp :refresh)=.
- Use =t= to enable a setting and =nil= to disable it. Omit the value to
  inspect the setting.
- Use numbers for quantities and strings for text or identifiers. Pass
  pathnames and quoted Lisp data directly rather than spelling them out in
  strings.

#+BEGIN_SRC lisp
(settings :boot-screen-seconds 2)
(settings :reasoning-traces-p t)
(settings :reasoning-traces-p nil)
#+END_SRC

*** Automatic permissions

Choose a permission mode for the channel:

- =(permissions :ask)= prompts for approval. Choose =once= for one operation
  or =always= to approve the exact operation for future calls.
- =(permissions :auto)= classifies operations without an approval prompt.
  While Autolith classifies the call, look for =judging= in the status bar.
  Read the decision beside the tool call.
- Use =(permissions :sandbox)= for sandboxed execution on supported platforms.
- Use =(permissions :full)= to run with your full user privileges.

The mode is stored locally and restored when you reopen a saved channel. This
includes *full* access, even after a restart.

** Read the transcript

The transcript is above the prompt. Look for =LIVE= in the modeline when
following new output. Otherwise, read the range of rows that are visible.

- Use =PageUp= and =PageDown= to scroll one page, or use the mouse wheel to
  scroll a few rows.
- Use =Ctrl-PageUp= and =Ctrl-PageDown= to jump between user and assistant
  messages. The jump puts the end of the message above the composer, or puts
  the header at the top if the message is taller than the viewport.
- Use =Ctrl-Home= and =Ctrl-End= to jump to the oldest and newest retained
  transcript positions.
- In a hosted channel, press =Ctrl-S= to toggle the sidebar. Press =Ctrl-Space=
  to focus it. See [[#local-sessions][Local sessions]].
- Drag across the transcript to copy selected text on release. Use =Shift=
  and drag to select whole screen rows in the terminal emulator instead.

Transcript history is separate from the scrollback of the terminal emulator. The
viewport keeps about four million characters of recent output in memory. At the
oldest retained row, the modeline shows =(history) loads earlier=. Run
=(history)= to load a page of older output.

When saved memories match your input, a dim =@ N relevant memories exist= line
appears below your message. It shows how many memories were offered to the model
for that request, followed by how many of them are stale or unverified (see the
Memories section). Each input gets one notice across tool calls and provider retries.

Input recall includes every user message, command, and Lisp submission in the
conversation. Automatic messages and assistant output are excluded. On first use,
the complete input-only sidecar is built from the conversation records; later
submissions are appended to it. Resuming reads this sidecar instead of replaying
archived transcript chunks. If cache storage is unavailable, recall streams the
conversation records directly. The editor keeps the newest 500 inputs, up to a
million characters, in memory. Moving past the oldest of them loads the
next older page, and leaving history recall releases it again.

Click a web address in the transcript to open it in your browser. Use
=⧉ copy= below a code block to copy the source. If you connect over SSH,
transcript copies can reach your local clipboard through OSC 52.

Click a tool call header to insert its Lisp form at the cursor. Submit the
form to repeat the call, edit the arguments to change the call, or add a
question to ask the model about it. Arrays are spelled as =(vector ...)= and objects
as =(dict ...)=, and argument names with uppercase letters keep their case as
=:|filePath|= or a string key.

Click a =lisp.eval= input block to expand the complete Lisp source
with syntax highlighting. Click it again to collapse it. The selected view
persists through resizing and tool completion.

Lisp evaluation inputs, returned source, and values use rainbow parentheses:
matching parentheses share a color, and nesting depths cycle through six colors.
Strings, character literals, escaped symbols, and comments do not affect depth.

Tool argument names emitted with underscores are matched to declared hyphenated
names, including nested objects and array items. If both spellings are present,
the declared spelling takes precedence.

A pending tool call starts with =▸=. When it finishes, the
same header shows a green =✓= for success or a red =!= for failure. Errors
appear beneath the original invocation and arguments. Background handoffs keep
=▸= until completion. Thanks to @rgbcube for suggesting these outcome markers.

Autolith reports the session status over the interactive terminal using the
[[https://www.superlogical.com/rex/docs/build/program-status][OSC 7501 Program Status Protocol]] and =app=autolith=:

| Status | When reported |
|--------+---------------|
| =idle= | At startup or after cancellation |
| =working= | During foreground input and resumed model turns |
| =done= or =error= | After success or failure, until the next input or model turn |
| =blocked= | For an input selector (=kind=question=), an approval (=kind=permission=), or authentication (=kind=auth=) |

Reports include the conversation title. Progress from children and background
jobs appears in the transcript. Reports omit prompt text, assignments,
results, credentials, and progress estimates.

*** Terminal diagrams

Ask for a fenced =mermaid= block to see a diagram in the terminal.
[[https://github.com/lambda-symbolics/clermaid][Clermaid]] documents the supported syntax for:

- Flowcharts
- Sequence diagrams
- Flat state diagrams
- Class diagrams
- Entity relationship diagrams

#+BEGIN_SRC markdown
```mermaid
flowchart LR
  A[Read] --> B[Evaluate]
  B --> C[Print]
```
#+END_SRC

While the response streams, read the Mermaid source in the live tail. Use the
*copy* action on the finished diagram to copy the source. If the syntax is
unsupported or the diagram is too wide, read the source block instead.

** Parking and editing queued input

1. Run =(vault-store)= to park queued work and unconsumed steering. Work already
   in progress continues.
2. Run =(vault-contents)= to inspect the parked entries in restoration order.
   Entries are zero-indexed. Use =setf= to publish a change.
3. Run =(vault-restore)= to put the edited entries at the front of the live queue.

#+BEGIN_SRC lisp
(vault-store)
(vault-contents)
(setf (vault-contents 0) '(:message "Run the unit tests first."))
(vault-restore)
#+END_SRC

Use =(vault)= for a summary. To replace the entire list, set =(vault-contents)=
without an index. Its entries may be =(:message INPUT)=, =(:command TEXT)=,
=(:lisp SOURCE)= or, for scheduled wakeups, =(:native-lisp SOURCE)=. Set the list
to =nil= to clear it.

** Managed resources

Use =resource.read= to read a file or another resource. For an edit, pass the
revision from that read as =:base-revision= to =resource.edit=. If the resource
changed, read it again before editing. For a multi-file =cl-resources= change,
Autolith checks every staged revision before publishing. If publication fails
partway through, Autolith restores the earlier files unless an external change
requires manual recovery.

#+BEGIN_SRC lisp
(resource.read :uri "workspace:README.md")
(resource.read :uri "channel:current" :query "unit tests" :max-results 5)
(resource.read :uri "channel:current" :start-sequence 120 :record-count 10)
#+END_SRC

| Resource | Use |
|----------+-----|
| =channel:current= | Read recent history, including records from before compaction. |
| =channel:id/ID= | Read the history of one other channel. |
| =channel:list= | Find channels and their participants. Reading does not subscribe you. |
| =papercut:current= | List active reports about the running Autolith harness or its tools. |
| =papercut:id/ID= | Read one papercut. Percent-encode the stable ID if necessary. |

History searches are limited to one channel and match all the search terms.
Page by sequence number or read a long record on its own. Use =(papercuts)= to
list reports, =(papercut "ID")= to inspect one, or =(papercut-close "ID")= to
close it. Agents can report a harness defect with =papercut.report= or assess
and close a report through its resource where authorized. Put project bugs
and test failures in the plan or agenda rather than the harness reports.

** Memories

Use a *note* for a preference or convention and a *fact* for a value you want to
reuse with its evidence. An agent can edit its own notes through
=memory:personal=. That scope follows the agent across channels and restarts.
When the turn allows =memory:=, agents can read shared workspace and global
memories with =resource.read=. Registered agents can write them with
=resource.edit=. Child agents need the corresponding tool grant.

#+BEGIN_SRC lisp
(memories)
(memories "deploy")
(memory "3afbfa1a")
(forget "3afbfa1a")
#+END_SRC

Open the memory manager with =(memories)=. Press =/= to search, Tab to
choose between All, Notes, and Facts, and Shift-Tab to choose a scope. Press
Enter to read the selected item on a narrow terminal. Use =n= to create a note,
=e= to edit it, =d= to forget it or retract an asserted fact, and =r= to reload.
In the note form, use Tab to move between fields, Space to choose a scope,
Shift-Enter for a newline, and Enter to save. Use a full ID or a unique ID
prefix when you pass an ID to a command.

A note can cite a file, a web page, your words, or another memory as a
/premise/. A note is /stale/ if a cited passage disappears from a file or a
premise changes. Any notes derived from it become stale too. A note whose only
cited files cannot be read is /unverified/. Inspect the evidence with
=(memory "ID")=. Update the source or premise when you update what the note
claims. Retagging a note does not refresh its evidence.

For agent-written notes, the =memory-remember= and =memory-replace= operations
accept =sources= and =premises=. Use =memory:id/ID= to inspect one note. Workspace
file references inside that workspace are relative and can move with an export.

*** Facts and rules

A fact records a typed value and what supports it. For instance, the assertion
=event.start review 2026-10-22T13:00:00Z= can come from your message or a calendar
file. The two sources are kept separately. A derived fact keeps the basis of
its premises: a calculation based on an assumption is still an assumption.

For an example, ask the agent to use the =appointments= recipe:

1. Give it the start time of the review, 30 minutes of travel, and a 10-minute
   buffer.
2. Run =(rules)= to inspect the active departure rule.
3. Change the start from 13:00 to 13:15. The derived departure changes from
   12:20 to 12:35 without another model request to run the rule. Run
   =(what-changed)= to see the change and its cause.

#+BEGIN_SRC lisp
(rules)
(what-changed)
(why "c4dfffae")
(retire-rule "departure")
#+END_SRC

Use =(why "ID")= to inspect the sources, rule and premises of a fact, or the
evidence for a note. Use =(forget "ID")= to retract an asserted fact. If two
facts disagree, both are shown as /conflicted/. A negated premise requires an
explicit negative fact; missing information is unknown. Recheck evidence when
a cited file changes. Web evidence expires after a week and tool output after
a day; observe it again to renew it.

Agents can inspect =memory:facts=, =memory:claim/ID=, =memory:predicates=,
=memory:rules= and =memory:changes=. The =memory:recipes= resource lists
=appointments= and =service-dependencies=. Use =recipe-use= on =memory:facts=
to define the predicates and activate the rules. The same resource accepts
=predicate-define=, =fact-assert=, =fact-retract=, and =rule-propose=.

Set =knowledge-mode= in =(settings)= or through =AUTOLITH_KNOWLEDGE=. Use
=active= to record and recall knowledge, =passive= to record without giving
facts to the model, or =off= to stop recording. The default is =active=. To
inspect how much of the current conversation was spent on structured knowledge,
use:

#+BEGIN_SRC lisp
(knowledge-usage-report (application-conversation *active-application*))
#+END_SRC

*** Plans, methods, gates, and contracts

Use facts when a plan or action depends on something you can check. For the
review example, a plan step can say =Leave at {?leave}= and require
=event.departure review ?leave=. Before the departure is known, the step is
/blocked/. When the time changes, the displayed step follows it. A completed
step is flagged if its recorded facts later stop holding.

- A /method/ describes how to do a task under stated conditions. Ask the agent
  to run =plan.expand= to expand a task into ordered steps. Inspect definitions
  in =memory:methods=.
- A /fact gate/ checks a mission against accepted evidence. By default it
  requires an undisputed observation or a statement from you. For example:

  #+BEGIN_SRC lisp
  (:id "departure-known" :kind :fact :pattern ("event.departure" "review" "?t"))
  #+END_SRC

- A tool /contract/ can require facts before a call and record facts from its
  result. For example, require a verified destination before publishing a
  report. If the prerequisite fails, the tool is not called. A predicted
  effect only counts if the contract explicitly accepts it.

Agents propose methods and contracts with =method-define= and
=contract-define= on =memory:facts=. Inspect contracts in =memory:contracts=.
Review the complete =contract.admit= request before enabling a new version.
Imported contracts also need local approval. A tool result marked
=externalSuccess: true= and =contractRecording: "failed"= means the action
succeeded and only the evidence recording failed. Check the result before
retrying. If damaged contracts block ordinary calls, ask the agent to call
=contracts.reset=. This archives the original log and clears all contracts and
saved diagnoses without clearing facts or notes.

*** Procedures

Procedures are Lisp functions that are stored in the workspace. The agent
defines procedures with =procedure.define= if it expects to repeat some work.
Procedures are =lambda= forms that have keyword parameters and documentation
strings. The bodies call tools as functions, in the same way as Lisp at the
prompt:

#+BEGIN_SRC lisp
(lambda (&key quarter)
  "Return the sales report of QUARTER."
  (resource.read :uri (format nil "workspace:reports/~A.org" quarter)))
#+END_SRC

The agent receives a catalog of active procedures in the request context. The agent runs procedures with =procedure.run=. The tool calls have the approvals of the conversation in which the agent runs the procedure.

#+BEGIN_SRC lisp
(procedures)
(run-procedure "sales-report" :quarter "q3")
(retire-procedure "sales-report")
#+END_SRC

=(procedures)= lists the procedures with their parameters.
=(retire-procedure "NAME")= stops a procedure until it is defined again. The
sources of all procedures are in =memory:procedures=. Procedures require active
structured knowledge.

*** Diagnosis

Ask Autolith to diagnose a failure when more than one cause fits. With
structured knowledge active, the agent can use =diagnosis.run= to compare up to
four hypotheses with existing facts and up to three tool probes. Each probe
needs a contract that records what the result establishes. An observation can
rule out a cause; missing evidence leaves the case open.

For example, if a report fails to reach a service, check whether the service is
reachable and whether the configured endpoint is current. A successful reachability
probe rules out an outage; a stale endpoint gives you a specific setting to fix.
Use =(diagnoses)= to review the evidence and saved diagnoses. Disable probes in
=(settings)= or with =AUTOLITH_DIAGNOSIS=0=.

** Exporting and importing data

Export a workspace from the OS shell, then import it at its new path:

#+BEGIN_SRC sh
autolith data export project.sexp --workspace /home/al/code/project
autolith data import project.sexp --workspace /home/al/src/project
#+END_SRC

Use the same archive format at the Autolith prompt:

#+BEGIN_SRC lisp
(data.export "project.sexp" :workspace "/home/al/code/project")
(data.import "project.sexp" :workspace "/home/al/src/project")
#+END_SRC

Export includes conversations, notes, facts, rules, agendas, plans, papercuts
and related assets. Copy the repository separately. Credentials, configuration,
images and caches are excluded. Omit =--workspace= to export all workspaces and
global data, or pass =--all= explicitly (=:all t= in Lisp).

Pick a new filename for export. Import merges data by stable ID, skips identical
records and stops before publication on an ID conflict. Use =--workspace= on
import to relocate a single-workspace archive. Without it, the original paths
are preserved. Run =autolith data export --help= or =autolith data import --help=
for options. CLI exit codes are 0 for success, 64 for invalid arguments and 1
for a transfer failure.

** Session titles and resume

A channel gets a local title from your first prompt or image. Autolith can ask
the model to refine the title after the third user turn and name the agent after
three user turns or 25 tool calls. Use =(rename "NAME")= to name the current
agent yourself. That name takes precedence over automatic naming. Inspect or
change the setting with =(settings :session-title-generation-p)= or
=(settings :session-title-generation-p nil)=.

- Run =(channel-id)= to find the stable ID of the current channel.
- Run =(open)= to pick a channel or =(open "ID")= to open it directly.
- Run =(delete)= to remove the displayed channel, or =(delete "ID")= to choose
  another. Confirm only if you intend to remove its history and child channels.
  The subtree must be idle and free of other attached clients.

Reopening a live channel gives you its jobs and history. If Autolith needs to
serve the conversation in a new process, the history is available, but old
background jobs and Lisp worker state are gone. Durable child task results can
still be read with =job.get=.

** Usage

Run =(status)= or its alias =(usage)= *at the Autolith prompt* for model usage:

- *Token usage* sums recorded input and output for this conversation. The
  prompt-cache row shows cache usage when reported by the provider.
- *Context* is the current space used in the model window, not the sum of
  tokens sent over the conversation.
- *Cost* covers recorded requests in this process. Review any unpriced request
  count before treating the total as a bill. Subscription rate limits are shown
  when available.

From the OS shell, run =autolith usage= for stored conversation and knowledge
counts, logical disk usage, and resident memory (RSS) of reachable processes.
The disk total counts overlapping roots and hard links only once. RSS can count
shared pages once per process. Run =autolith status= instead to inspect running
channels and the server. Set =NO_COLOR= for plain output in a terminal.

** Local sessions

*** Starting and switching channels

An interactive =autolith= launch starts the background server if needed and
serves the inbox. Use the following shell commands to work on a channel:

#+BEGIN_SRC sh
autolith open
autolith open researcher --read-only
autolith open /researcher/reviewer
autolith new /home/al/code/project
autolith new /home/al/code/project --detached
#+END_SRC

Without a target, =autolith open= opens the last changed top-level channel in
the current workspace or creates one if there is none. Use =autolith new= for
a fresh channel; add =-d= or =--detached= to create it without attaching. To
open it later, use the printed =autolith open ID= command. Only one terminal
can control a channel. Use =--read-only= to observe from another terminal.

Inside Autolith, use =(open "ID")= to switch channels. Use =(exit)= or Ctrl-Z
to disconnect the terminal and leave work running. To stop *all* channels and
their server, use =autolith stop= from the OS shell or =(stop-server)= from
Autolith. Updating or rolling back also stops the shared server.

An idle channel can unload after =(config :channel-idle-minutes)= minutes (30
by default) if nothing is running or queued and no terminal shows it. Open it
again or send its agent a message to serve it again. If you pipe a script into
=autolith= or =autolith open ID=, submissions run in order and the transcript
goes to standard output. A script cannot answer interactive approvals. The
channel closes when input ends.

*** Checkpoints and launch options

Run =(checkpoint)= to save the shared process. Work already in progress finishes
first, across all channels. New turns wait until after the save. Terminals
reconnect automatically, and the requesting channel receives the generation
ID. On Windows, the launcher restarts the server from the saved heap.

If you lose a connection unexpectedly, press =r= or Enter to retry the same
channel, enter an ID to switch, or press =q= to detach. Retrying does not
resubmit your work.

Use =--model=, =--permissions= or =--immutable= when creating a channel. Pair
=--provider= with =--model=. When opening an existing channel, the only launch
override you can pass is =--permissions=, and only when no terminal controls it.
To choose a permission mode in the channel, run =(permissions)=.

*** Channel sidebar

Unfold *home* to find channels grouped by repository or
workspace. Linked worktrees share a group when Autolith can identify their
originating checkout. Independent clones have separate groups. Child channels
are nested under their parent. Home shows the inbox and its unread count.

- Press Ctrl-S to toggle the sidebar. On a narrow terminal it opens as a drawer.
- Click the sidebar or press Ctrl-Space (Ctrl-Tab where supported) to focus it.
  Use the arrows to select or expand an entry, Enter to open it, or Delete to
  remove it after confirmation.
- Type to filter by agent name, ID, title or workspace. Press Escape to clear
  the filter or return focus to the transcript.

| Marker | Meaning |
|--------+---------|
| =▌= | Current channel in this terminal |
| =▸= / =▾= | Closed or open group |
| =●= / =○= | Agent working or hosted but idle |
| =·= / =?= | No running session or unknown status |

A yellow number counts messages received since this terminal last viewed the
channel. =@= counts mentions, and =N pending= counts deliveries waiting for a

*** Session endpoints

Run =autolith status= to list live sessions or =autolith status --sexp= for use

=:observer-client-pids= for read-only clients and =:pid= for the host.

#+BEGIN_SRC sh
autolith start

autolith tell /researcher/reviewer '(channel-id)'

Use =start= to launch the server in the background, =tell= to submit input,

started without a terminal.

** Channels

A channel has its own history and workspace. Each agent resides in one channel
and can subscribe to others. You reside in =/inbox=, also shown as *home* in the
sidebar. Viewing or controlling another channel does not move you there.
Typing ordinary text in the inbox starts no agent turn.

#+BEGIN_SRC lisp
(open "inbox")
(tell "@researcher" "Check the release notes.")
(open "/researcher/reviewer")
(rename "/researcher/reviewer" "critic")
#+END_SRC

Address a channel by agent handle, exact path, full ID or unique ID fragment.
For =autolith open=, a bare agent name works too. Use a full ID in a bookmark
or script if the names may change. A path follows channel ancestry and can
change when an agent is renamed. Copy the displayed path, including case and
percent escapes. Find paths with =(open)= or =channel:list=. Use =(tell)= to
pick a recipient and prepare a message. Use =(rename "WHO" "NAME")= to rename
a participant. Handles accept letters, digits, hyphens and underscores and
are matched without regard to case.

Use a mention such as =@researcher please check this= to send a copy to a
participant from your current conversation. A mention starts a word, so the
=@= inside a mail address does not count. To send directly, use =(tell "ID"
"text")=. Agents use =channel.send= and can follow other channels through
=channel.subscribe= and =channel.unsubscribe=. Subscribers receive copies of messages and replies.
An agent can use =@parent= to
reach its nearest active ancestor or, if there is none, you.

An idle agent starts work when it receives a message. A working agent receives
it as steering. Messages for you go to the inbox. Open it with =(open "inbox")=
and use the =open= form at the end of a notice to jump to its source. Read a
child agent transcript at =channel:id/ID=, where =ID= is its execution ID. Child
channels nest under the parent; =AUTOLITH_TASK_MAX_DEPTH= defaults to three levels
below a top-level agent.

* Configure Autolith

Put personal configuration in
=${XDG_CONFIG_HOME:-~/.config}/autolith/init.lisp=. This file runs as
Common Lisp in the =AUTOLITH= package with your privileges. Use
=--pristine= to skip private replay and executable initialization.

After the tracked code and selected private image have loaded, Autolith
loads these files in order:

1. The site =init.lisp=, if a site root is configured.
2. Trusted =.autolith/init.lisp= files, from the outermost directory to the
   nearest one.
3. Your personal =init.lisp=.

This order also applies to =autolith models= and =autolith auth=. Your
personal file reloads if you reconnect to a retained generation. Startup or
reload reports the pathname if a configuration file cannot be read or evaluated.

Packagers can set a read-only site root with =--site-config-root DIRECTORY=
or =AUTOLITH_SITE_CONFIG_ROOT=. Use an existing absolute directory. It can
contain =init.lisp=, =mcp.sexp=, =skills/= and =agents/=. A site
=init.lisp= runs with the same privileges as personal configuration. Use an
explicit site root in place of =XDG_CONFIG_DIRS=.

Packagers that ship Autolith under another name can set three environment
variables before the launcher starts:

- Set =AUTOLITH_DIRECTORY_NAME= to replace =autolith= in the per-user roots.
  Data is kept in =~/.local/share/NAME/= instead of =~/.local/share/autolith/=.
  The name must match the ASCII pattern =^[A-Za-z0-9][A-Za-z0-9._-]*$=.
- Use =AUTOLITH_PRODUCT_NAME= for the product name in these messages:
  - Startup messages.
  - Update messages.
  - Recovery messages.
- Set =AUTOLITH_COMMAND_NAME= for the command name in help and suggested commands.

Processes started by Autolith inherit these variables.

Nix packagers can include defaults for these variables. Import
=nix/package.nix= with any of these arguments:

- =directoryName=
- =productName=
- =commandName=
- =siteConfigRoot=

The packaged launcher sets the matching variables if they are unset or
empty. The launcher is installed as =bin/COMMAND= instead of =bin/autolith=.

** Project instructions and adaptation notes

Put repository instructions in =AGENTS.md=.
Autolith reads these files from the project root down to the current working directory.
Rules in deeper directories refine the rules above them.
In Git projects, the project root is the nearest ancestor directory with a =.git= entry.
Outside Git projects, the current working directory is the project root.

Use the optional =AUTOLITH.org= at the project root to document project-specific
Autolith adaptations. Include the problem and the change.
Record the verification results and the conditions for removing the adaptation.
Autolith includes these notes in model requests.
Instructions in =AGENTS.md= take precedence.

** Folder blacklist

Set =*tool-path-blacklist*= in trusted =init.lisp= to deny native tool path
arguments beneath selected folders, including in full-access sessions:

#+begin_src lisp
(setf *tool-path-blacklist*
      '("~/.ssh/" "/srv/private/"))
#+end_src

Entries are absolute directory pathnames or strings. A leading =~/= expands
to your home directory. The default is =nil=. The check precedes permission
approval and covers the folder itself, missing descendants, and current
symlink targets. Retained resource observations and prepared edits are
rechecked before access or publication. Recursive parenthesis checks reject
an entire requested tree if it contains a denied folder. A refusal has code
=path-blacklisted=.

This policy governs native tool path arguments, such as workspace resources,
images, explicit ASDF files and command working directories. It does not
confine arbitrary shell commands, Lisp forms, indexed-search queries or
external MCP servers. Use OS-level restrictions when those also need confinement.

** Settings

Use =(settings)= to open the settings picker. Select a setting to see the
current value, where it came from, and the available choices. In a script,
=(settings)= prints the settings by area.

You can use the same command without the picker:

- =(settings :boot-screen-seconds)= describes the setting.
- =(settings :boot-screen-seconds 2)= sets the value.
- Use =t= or =nil= for switches. Omit the value if you only want to inspect
  the setting. An explicit =nil= counts as a value.

Settings have four scopes:

- *Durable.* Your model, reasoning effort, reasoning traces, timestamps and
  saved permission mode belong to this scope. Changes are saved immediately
  in =preferences.sexp= under the configuration directory.
- *Session.* Settings such as hurry-up mode last until exit.
- *Process.* Startup sets the configuration roots and management endpoint.
- *Derived.* The provider endpoint and context window depend on the model.
  For the context window, Autolith tries the declared value first, then the
  catalog value, then the default.

For durable settings, the first available source wins:

1. An explicit command-line option.
2. The environment variable for the setting.
3. The saved value in =preferences.sexp=.

If a saved provider or model is unavailable, Autolith uses a registered choice
and shows a notice. Register the provider again to recover the saved choice at
next startup. Invalid command-line or environment choices produce an error.
Use =--model= or =AUTOLITH_MODEL= to select a model served by the provider.

In Lisp, read settings with =(config :model)= or pass an explicit configuration
with =(config :model configuration)=. Change the current value with
=(setf (config :reasoning-traces-p) t)=. Use =configuration-copy= to make a
separate configuration.

*Upgrading from preferences versions 1 through 7:* Run Autolith 0.53 once
to write version 8 before you upgrade to 0.54 or later.

** Language servers

1. Install a language server that you trust. It runs with your privileges and
   inherits your environment.
2. Create =lsp.sexp= in your user configuration directory, beside =init.lisp=.
   Here is a configuration for =clangd=:

#+BEGIN_SRC lisp
(:version 1
 :servers ((:name "clangd"
            :command "clangd"
            :arguments ("--background-index")
            :extensions (".c" ".h")
            :language-id "c"
            :root-markers ("compile_commands.json" ".git")
            :timeout-seconds 30)))
#+END_SRC

For each server, provide a unique =:name=, a =:command= on =PATH=, a nonempty
=:extensions= list and a =:language-id=. Use literal strings for arguments.

- Use JSON object strings for =:initialization-options= and =:settings=.
- Set =:disabled-p t= to disable an entry.
- The request timeout defaults to 30 seconds. You can set it to an integer from
  1 through 120.

Autolith reads LSP configuration from your user configuration directory.

Configure at least one enabled server to use the =lsp= tools. If the file is
malformed, run =lsp.status= to inspect the configuration error.

Ask Autolith to use these tools:

- =lsp.status=: inspect configuration and running project/server pairs.
- =lsp.query=: request =definition=, =references=, =hover=, =implementation=,
  =type-definition=, =document-symbols=, or =workspace-symbols= for a workspace
  file. Position queries require one-based =line= and =character= coordinates,
  with columns measured in UTF-16 code units. For workspace symbols, supply
  =query=; the file selects the project and server.
- =lsp.diagnostics=: synchronize a file and retrieve diagnostics.
- =lsp.restart=: stop servers and reload the configuration after changing it.

Use =lsp.semantic= for revisioned transformations:

- =prepare-rename=: inspect the symbol at =path=, =line= and =character=.
- =rename=: propose a symbol rename with those coordinates and =new-name=.
- =code-actions=: discover choices for a range, using =line=, =character=,
  =end-line= and =end-character=. Optionally filter =only= action kinds or
  supply =diagnostics=.
- =resolve=: retrieve a complete action using its returned =choice= ID.
- =propose=: retain an action's edit as an applicable proposal using =choice=.
- =move=: propose server preparatory edits followed by moving =path= to
  =new-path=. Both paths must identify regular files or a missing destination.
- =inspect=: review a retained =proposal= ID.
- =apply=: apply a retained =proposal=. Obtain explicit approval for annotations
  with =needsConfirmation=, then include their IDs in =approved-annotations=.
  Confirm each synthetic =lsp.semantic-confirmation= request through the ordinary
  command-permission prompt. Without a permission callback, confirmation is denied.

Use local =file:///= URIs for regular files. Before you apply a proposal,
Autolith checks permissions, file revisions and synchronized versions. Request
a new proposal after a conflicting edit or server restart. Server commands
are returned as data for separate approval and execution.

Autolith starts servers on demand. It uses the nearest configured root marker
inside the workspace, or the workspace itself if no marker matches. All enabled
servers that match the file suffix receive the request. Open files are refreshed
from disk first.

*Diagnostics.* Ranges are zero-based and measured in UTF-16 code units. The
=sources= field gives the freshness of push and pull results. The diagnostic
state means:

- =received=: The report is versioned.
- =unversioned=: The snapshot of the file could not be confirmed.
- =pending=: No report arrived.

The automatic check after =resource.edit= shares a one-second deadline across
all matching servers. If it times out, use =lsp.diagnostics= to allow two seconds
for push reports and the configured timeout for pull requests. Use =lsp.restart=
to release the servers.

** Active-image management endpoint

The management REPL is an always-enabled endpoint for evaluating Common Lisp
in the running =AUTOLITH= image. Use =eval-connect= and =eval-call= from
=image-daemon= to connect from Lisp.

Put a nonempty token in a regular file owned by your user with mode =0600=.
Connections use HMAC-SHA-256 and a fresh nonce. The token itself is read from
the file during authentication and is not sent over the connection.

The following environment variables configure newly created applications:

| Variable | Default | Meaning |
|-
| =AUTOLITH_MANAGEMENT_REPL_TRANSPORT= | =unix=, or =tcp= on Windows | =unix= or =tcp=. |
| =AUTOLITH_MANAGEMENT_REPL_UNIX_SOCKET= | =${XDG_STATE_HOME:-~/.local/state}/autolith/management/repl.sock= | Unix socket pathname. |
| =AUTOLITH_MANAGEMENT_REPL_TCP_ADDRESS= | =127.0.0.1= | IPv4 loopback listener address. |
| =AUTOLITH_MANAGEMENT_REPL_TCP_PORT= | =4141= | TCP listener port. |
| =AUTOLITH_MANAGEMENT_REPL_TOKEN_FILE= | =${XDG_CONFIG_HOME:-~/.config}/autolith/management-repl.token= | Mode-0600 token file. |

Evaluation and authentication deadlines are 10 seconds. Frames are bounded to
1 MiB, source and output to 256 KiB, and queued evaluations and clients to 64.

*Trust boundary.* TCP is restricted to IPv4 loopback and uses no TLS. Use
trusted local clients. Evaluation results can contain secrets.

On Unix, Autolith uses a mode-0700 directory and a mode-0600 socket. Startup
can replace a stale socket owned by the current user. On Windows, use TCP.

*** Wire protocol

Each message is a four-octet unsigned big-endian length followed by exactly that
many UTF-8 octets containing one readable S-expression. Length zero, oversized
or truncated frames, invalid UTF-8, malformed syntax, and trailing forms are
rejected. Readers use standard I/O syntax, a fresh standard readtable, and
=*read-eval*= =nil=.

The server starts each connection with:

#+BEGIN_SRC lisp
(:challenge :version 1 :algorithm :hmac-sha-256 :nonce HEX)
#+END_SRC

=HEX= encodes 32 random nonce octets as 64 lowercase hexadecimal characters.
The client reads its token file, computes =HMAC-SHA-256(token, nonce)=, and
replies:

#+BEGIN_SRC lisp
(:authenticate :proof HEX)
#+END_SRC

A valid proof receives =(:authenticated :version 1)=. A proof is valid only for
that connection's nonce. Authentication failure closes the connection without
a reusable credential or detailed oracle response.

After authentication, send one request at a time:

#+BEGIN_SRC lisp
(:evaluate :source "(values (+ 20 22) *package*)")
#+END_SRC

Send one form per request. Autolith evaluates it in the =AUTOLITH= package
and captures output. A successful response looks like this:

#+BEGIN_SRC lisp
(:evaluation-result
 :status :ok
 :values ("42" "#<PACKAGE \"AUTOLITH\">")
 :values-truncated-p nil
 :output ""
 :output-truncated-p nil)
#+END_SRC

The =:values= list contains one string per return value. A condition response
includes =:condition-type= and =:report=. A deadline returns =:status :timeout=.
The connection can accept another request. The deadline is best effort because
trusted forms can suppress interrupts.

Autolith stops the endpoint before a checkpoint and restarts it afterward.
If the evaluator cannot stop within two seconds, the checkpoint fails with
=management-repl-error= and operation =:quiesce=.

** Context

Use *ephemeral notes* to add temporary information to provider requests without
adding conversation messages. For example, register advice for release requests:

#+BEGIN_SRC lisp
(define-context-contributor release-advice (request)
  "Add advice for release requests."
  (when (search "release" (or (request-context-latest-user-text request) "")
                :test #'char-equal)
    (make-context-contribution
     :identifier  "release-check"
     :instruction "Verify release artifacts before publishing."
     :lifetime    ':turn
     :priority    40)))
#+END_SRC

- A contributor receives a read-only request snapshot.
- It can return zero, one, or many contributions.
- Notes stack unless they deduplicate, supersede, or conflict.
- Priority matters only when the advice budget is full.

Inspect contributions with =(context)=. They apply only to provider requests;
they do not count as conversation turns or attach to your messages.

Register selective project or user advice as a declarative rule:

#+BEGIN_SRC lisp
(register-context-rule
 '(:id "lisp-edits"
   :when (:paths ("src/") :languages ("common-lisp")
          :events ("tool-success"))
   :instruction "Check the changed declarations before committing."
   :priority 30 :lifetime :while-relevant))
#+END_SRC

Use =:paths=, =:languages=, =:tools=, =:namespaces=,
=:diagnostics=, =:events= and =:output-contains= in =:when=. Fields are
conjunctive; values within a field are alternatives. Paths match prefixes;
=:output-contains= matches literal case-insensitive substrings of recent
completed assistant text and generated tool arguments. Other values match
exactly. Add an absolute =:workspace= directory for project scope. Authorized
tool operations and structured LSP severities supply bounded current-turn
metadata. Asynchronous completions use their originating turn identity.
Rules share the ordinary advice budget, priority, lifetime and deduplication
policy. Inspect delivery with =context-status=; remove a registered rule with
=unregister-context-rule= and its original ID.

The status line keeps a context meter visible while idle. It shows used tokens
and the full model window. =|= marks the automatic compaction point. The
ChatGPT subscription catalog currently reports a 272K-token window for the
GPT-6.1, GPT-6, and GPT-5.6 models, which compact at about 218K tokens by default:

#+BEGIN_EXAMPLE
ctx [==========|..] 218K / 272K used
#+END_EXAMPLE

Before provider usage is available, the count uses four characters per token
from the known system prompt, request-local guidance, retained conversation,
and tool schemas. After compaction it estimates the replacement context until
next provider report. Compaction request usage is recorded separately as work
spent on the checkpoint.

If you switch Responses models, the new model receives the conversation and
tool exchanges. Encrypted reasoning is available again if you return to the
model that produced it.

*** Compaction

Use =(compact)= to make a checkpoint now. If a turn is active, compaction
waits in the idle queue. Automatic compaction uses the same typed checkpoint
format. Models from different providers can read the checkpoint. Earlier
provider-native windows can still be read by the providers that made them.

A checkpoint records the current goal, decisions, constraints, completed and
open work, uncertainties, and the next step. Recent turns are kept verbatim,
normally up to two user turns and 32,768 characters. The latest user message
and required tool or reasoning groups can exceed that bound. Live job state,
mission policy and the current plan are read separately from their stores.

*Evidence.* Checkpoint notes can cite messages, tool results, plan steps,
mission gates, symbolic facts and unfinished jobs. A completed note without
a citation is marked =(unsubstantiated)=. Use the =channel:id/<id>= address and
record sequence to find a message or result. Use =memory:claim/<id>= to inspect
a fact. After compaction, the next turn reports changes to cited steps, gates
and facts. For example, a gate can become stale after an input changes.

If the model submits an invalid checkpoint, Autolith asks for a correction.
After four unsuccessful attempts, it keeps the earlier checkpoint notes and
recent turns. It records the range of history that was not summarized. If the
provider is unreachable or refuses, or a permission check fails, the
conversation is left unchanged.

A failed checkpoint writes a private report under =compaction-reports/= in
the state directory. It contains the error and last completed response, with
active credentials redacted. In the terminal, use =(copy bug report to clipboard)=
to copy the report.

*** Output limits and admission

- =(settings :max-output-tokens 4096)= caps ordinary model replies. You can
  also set =AUTOLITH_MAX_OUTPUT_TOKENS=. Use =nil=, or the text =none=, =off=
  or =unset=, to use the provider limit.
- =(settings :context-output-reserve 8192)= reserves at least 8,192 tokens for
  the reply. You can also set =AUTOLITH_CONTEXT_OUTPUT_RESERVE=. A larger
  explicit generation cap takes precedence.

Before sending a request, Autolith checks that the encoded prompt, tools and
reply reserve fit within the model window. Cached input counts in full. The
most recent compatible provider measurement is used if available. Otherwise
Autolith estimates the input size locally.

Set =ANALYTICS_EVENTS_FILE= to export completed streaming calls as UTF-8 JSONL
usage events. =ANALYTICS_ACTOR= overrides the operating-system username. Each
schema-v1 =llm-usage= event contains the UTC timestamp, actor, model, request
count, elapsed seconds, and known input, output, and cached token counts.
Unknown token counts are omitted. Export is disabled without a destination.
Appends are synchronous and serialized across processes; export errors do not
abort a completed provider call.

Mechanical precompaction bounds oversized old tool output before a request,
but only after an explicitly declared cache lifetime expires or the
provider/model changes. A retention estimate alone never permits rewriting
served history.

Excerpts include the head and tail, failure status, uncertainty about external
effects, and a retrievable conversation/call reference. Calls, reasoning, and
failed attempts are retained. Full outputs are available in the durable
transcript; the latest user turn is untouched. Each precompaction is recorded
and replayed on resume.

A same-provider/model resume preserves its prefix unless a known lifetime has
elapsed. If a conversation has no recorded response identity, it is prepared
once on resume. Manual, context-threshold, and scheduled idle compaction can
still replace history with a summary, including when its cache lifetime is unknown.

Idle cache compaction is enabled by default. After a completed request with at
least 32,768 prompt tokens and 131,072 characters of summarizable history, an
idle session can compact two minutes before its estimated cache expiry. The
timer starts when the request starts, not when its response finishes. User
input, drafts, active work and shutdown take priority. Each opportunity is used
once, including after failure. Resumed sessions need a new completed request
before scheduling one.

Use =(settings :idle-compaction-p nil)= to disable it. The ChatGPT subscription
route uses a conservative five-minute inactivity estimate. For Anthropic and
OpenRouter Claude, the requested cache lifetime supplies the estimate. Other
providers need an explicit estimate for idle compaction, for example
=(settings :prompt-cache-retention-seconds 1800)= for thirty minutes. A positive
value also declares a lifetime for precompaction; this is a user declaration,
not evidence from the provider. Set it to zero to use the provider policy.
Both settings persist across restarts. The ChatGPT estimate alone never
permits idle precompaction; that route has no declared lifetime by default.

=(settings :prompt-cache-ttl :1h)= asks the Anthropic API and OpenRouter
Claude models to keep cache entries for one hour instead of five minutes. A
one-hour cache write costs twice the base input price, against 1.25 times for
five minutes. The longer lifetime can avoid rewrites after pauses of five
minutes to an hour; whether it saves money depends on reuse. Other routes
ignore the setting. The requested lifetime supplies both the declared lifetime
for precompaction and the estimate for idle compaction. An explicit
=:prompt-cache-retention-seconds= setting takes precedence for both local
policies. OpenRouter requests carry the conversation's cache key as their
session identifier for upstream routing affinity from the first request.

Use =(status)= to inspect this process's model-request costs. Autolith uses
reported charges when available, as with OpenRouter. Otherwise it uses a
model-price snapshot: the built-in Anthropic API list prices, or
=(settings :model-prices "{\"model\": {\"input\": 2, \"cache_read\": 0.2, \"output\": 10}}")=
in US dollars per million tokens, keyed by the model name from =(model)=. A
missing cache_write rate charges cache writes as input. Requests without a
price, such as subscription routes, are counted as unpriced, not free.
=(settings :cost-limit 5)= refuses new model requests, compaction and
inference frames included, once reported and estimated spending reaches five
dollars; zero disables the limit. Unpriced requests do not count toward it.

Cache retention depends on the provider, model, routing and account policy.
The [[https://developers.openai.com/api/docs/guides/prompt-caching][OpenAI API cache documentation]] describes a thirty-minute default for
GPT-5.6 and later; it does not establish a retention contract for the ChatGPT
subscription route. Idle compaction uses the ordinary paid checkpoint path. It
can reduce the context sent after a long pause, but neither a cache hit nor a
net saving is guaranteed.

Use =(settings :cache-miss-notices-p t)= to enable notices when cached reads fall
by at least 128 tokens, including accumulated smaller losses. Notices also appear when
cached reads remain flat while shared request history grows by at least
16,384 characters and at least one sixteenth of its reference size. Temporary
context and newly offered history are excluded from shared growth.

A cache miss reports measured lost reads. A stall reports shared-history growth
in characters because its token count is unknown. Both show cached and total
input tokens and start with a red =!=. Model changes, idle intervals and
smaller prompts are local observations, not proof of eviction or routing failure.

Each notice also identifies changes in the request as sent, compared with the
previous request: top-level fields such as =tools= or =system=, the first item
in the previous request's reusable prefix that the new request changes or
omits, and moved cache markers.

The reusable prefix stops before temporary context and one-response exchanges,
so appended history does not count as a change. If a request repeats the whole
prefix, the notice reads =prefix intact=: the provider did not extend its
cache. These comparisons use digests of the final request, not provider
counters, and retain no prompt text.

The first request after resuming or compacting establishes a fresh baseline.
Without comparable read counters or prefix measurements, no loss is inferred
from total input. The setting is off by default and persists across restarts.

In Responses requests, skill catalogs and selected skill instructions keep their
first surviving history position instead of moving after each new message.
Autolith reads the current skill contents and checks activation on every request.
Selected instructions expire with the logical turn; only the small selection
call and result enter durable history. Mutable session state and other ordinary
request context follow history. After compaction or removed history boundaries,
Autolith places active skill context after the new history. Use =(context)= to
inspect contribution sizes. Provider cache hits and savings depend on the
provider and are not guaranteed.

** Providers

*** Run a local model

Register local inference servers through the *OpenAI-compatible Chat
Completions* API. The server must support streaming and the model must support
tool calls to use Autolith tools. For an Ollama server on the same machine:

1. If Ollama is not already running, start it with =ollama serve=. In another
   terminal, download a model that supports tools:

   #+begin_src sh
   ollama pull qwen3:8b
   #+end_src

2. Add this form to
   =${XDG_CONFIG_HOME:-~/.config}/autolith/init.lisp=:

   #+begin_src lisp
   (register-openai-compatible-provider
    :name                         "local-ollama"
    :endpoint                     "http://127.0.0.1:11434/v1/chat/completions"
    :models                       '("qwen3:8b")
    :api-key-environment-variable "AUTOLITH_OLLAMA_KEY"
    :stream-usage-p               nil)
   #+end_src

3. Set a nonempty key value and start Autolith. Autolith sends it as a bearer
   key. Local Ollama ignores it, so =ollama= is a placeholder, not a secret.

   #+begin_src sh
   export AUTOLITH_OLLAMA_KEY=ollama
   autolith models | grep -Fx 'local-ollama/qwen3:8b'
   autolith --provider local-ollama --model qwen3:8b
   #+end_src

4. Send a short prompt to check that replies stream. Ask Autolith to list
   the files in the current directory to check tool calls.

If Ollama runs on another host, =127.0.0.1= still refers to the machine that
runs Autolith. To keep the remote server private, forward the port over SSH:
=ssh -N -L 11434:127.0.0.1:11434 HOST=. Use a different local port if 11434 is
already in use and change =:endpoint= to match.

*Troubleshooting.* If the model is unknown, check the exact ID with
=ollama list=. If the server rejects =stream_options=, use =:stream-usage-p nil=
as shown above. If the server runs out of context, increase the context limit
on the server first. Then set =:models= to a list of model property lists, for
example ='((:name "qwen3:8b" :context-window 32768))= for a server configured
with a 32,768-token window. The registration does not change the server limit.
See the [[https://docs.ollama.com/api/openai-compatibility][Ollama API reference]] for supported endpoints.

*** Add another OpenAI-compatible provider

Use the same registration form for a local or hosted service. Change these
fields in =init.lisp= and restart Autolith:

- *Provider name:* Set =:name= to a unique name for Autolith.
- *Endpoint:* Set =:endpoint= to the full streaming Chat Completions URL,
  typically ending in =/v1/chat/completions=.
- *Models:* Set =:models= to the IDs you want to use, =:models-endpoint= to the
  full model-list URL, or both. Use static IDs if you want to select a model on
  the first launch. Inside Autolith, use =(models :provider "my-provider")=
  to refresh the model list from the service.
- *Credentials:* Set =:api-key-environment-variable= to the name of a variable
  that contains the service key, or run =autolith auth my-provider= to store
  the key privately. A nonempty environment value takes precedence. Replace
  =my-provider= with your registration name.

Optional =:headers= adds non-secret HTTP headers. For headers that depend on the
conversation, set =:request-headers= to a function of one conversation argument.
Return an alist of non-secret header names and string values. For example, add
this option to the registration to route each conversation to the same backend:

#+begin_src lisp
:request-headers
(lambda (conversation)
  (list (cons "X-Session-Id" (conversation-identifier conversation))))
#+end_src

The conversation identifier is durable across resume and compaction. The function
is called before each completion request, including retries. Its headers replace
static headers with the same name, ignoring case. Model discovery uses only static
headers. Authentication, content type, accepted response type and user agent are
set by Autolith.

If the server supports the streaming usage chunk, you can omit =:stream-usage-p=
to request it.

For a different wire protocol, use the Lisp extension point =register-provider=
with a factory that returns a =model-provider=. The Chat Completions helper
always uses Chat Completions.

Select a model with =(model "glm-5.3-flash" :provider "neuralwatt")= or
=(model "neuralwatt/glm-5.3-flash")=. Use =(models :provider "neuralwatt")=
to refresh and list one provider, or =(model nil :provider "neuralwatt")=
to filter the interactive picker. The picker and listings show the provider
with each model, including identical IDs offered by different providers.

Bare model IDs use the existing registration precedence. Only a registered
provider name introduces a provider prefix; catalog IDs containing slashes,
such as =hf:zai-org/GLM-5.3-Flash=, are matched intact. If a catalog ID also
looks like another provider's full ID, specify =:provider= to select its exact
catalog ID. An explicit provider and a conflicting qualified prefix signal a
selection error. The selected provider is saved with the model in preferences
and conversation history, so reopening a session uses the same registration.

Select a model for one launch with =--model MODEL=. Use a provider-qualified
ID, or pass =--provider PROVIDER= together with =--model= for an exact catalog
ID. These options work before or after =run-job= and =open=:

#+begin_src sh
autolith --model my-provider/my-model
autolith --provider my-provider --model hf:custom/model
autolith open --model my-provider/my-model
autolith run-job --model my-provider/my-model --input job.sexp --output result.sexp
#+end_src

The launch selection takes precedence over environment variables, saved
preferences, and a resumed conversation's model. It does not save a new default;
use =(model ...)= to save a selection. Autolith loads executable initialization
and the local provider catalog before validating the requested model, so providers
registered in =init.lisp= are available. Startup does not fetch a remote catalog;
use =autolith models= to list locally known IDs and =(models)= to refresh them.

new user input and request-local context changes. New input and changed context
follow the dispatched prefix. Requests use at most four cache breakpoints across
system instructions, tools and messages. Changed headers, rewritten history,
compaction and ephemeral exchanges start a fresh projection. For a specifically
identified thinking prefix-binding HTTP 400, Autolith retries once with Anthropic's
binding control.
The conversation log stores up to 32 rejected signature digests. Later requests
use the control only while a rejected block is present and the effective thinking
mode supports it. See Anthropic's [[https://platform.claude.com/docs/en/build-with-claude/preserved-thinking/prefix-checks][prefix checks]]
and [[https://platform.claude.com/docs/en/build-with-claude/effort][effort guide]].

ChatGPT models use Codex's default context windows, currently 272,000 tokens,

ChatGPT Codex Fast mode sends =service_tier=priority= when the active Codex model

If a request fails before model generation begins, Autolith retries it up to
six times with jittered delays.

Once reasoning or output has streamed, or the provider reports token exhaustion
(=length=, =max_output_tokens=, or =max_tokens=), Autolith makes at most two
retries: three generation attempts including the original. Token exhaustion
before visible text uses the same limit.

Set =autolith::*provider-maximum-streaming-retries*= in =init.lisp= to change
this retry count; zero disables these retries.

Every failed attempt is recorded next to its request number with the attempt
count, elapsed seconds, whether output was received, and provider identifiers.

ChatGPT Codex uses standard Responses requests and native Responses compaction.
Normal requests enable provider parallel tool calls. Autolith executes independent
calls concurrently, then records their results in provider wire order. Calls
requiring a provider round trip, exclusive tools, and calls sharing one mutable
runtime execute in separate ordered waves.

GPT-5.4 and later Codex models use native Responses tool search. Autolith sends
stable namespace names and descriptions up front, marks each function
=defer_loading=true=, and declares a client-executed =tool_search=.

When the model searches, Autolith searches its own registry within the
namespaces advertised in that request. It scores namespace names, tool names,
and description words, then appends the =tool_search_output= as a durable
provider item.

The expansion replays intact in every later request. This keeps those tools
loaded and the prompt prefix cacheable. Other models and providers receive the
complete eager tool array.

** Commands

Put commands in =${XDG_CONFIG_HOME:-~/.config}/autolith/init.lisp= or load a
Lisp file from there. Autolith loads user initialization after tracked code on
ordinary startup, including after updates. Use =define-application-command= to
register the command and set its help, completion and dispatch policies.

#+BEGIN_SRC lisp
(define-application-command my-version-command
    (:name              "my-version"
     :aliases           ("local-version")
     :argument          "[LABEL]"
     :description       "show a labeled local integration version"
     :tip               "shows the version supplied by init.lisp."
     :busy-behavior     :execute
     :terminal-behavior :shared
     :callable          t)
    (application &optional (label "integration"))
  (application-present application (format nil "~A 3" label))
  :continue)
#+END_SRC

- *Arguments:* Callable handlers take ordinary Lisp lambda lists, including
  =&key= and supplied-p parameters. Missing interactive arguments open the
  restart debugger. Use =supply-arguments= to pass replacement Lisp values.
  Autolith rejects excess arguments before dispatch.
- *Busy behavior:* Choose =:inspect=, =:execute=, =:apply=, =:hold= or =:cancel=.
  Use =:execute= to run immediately, =:apply= to change state at the next safe
  provider boundary, or =:hold= to wait for idle. Argument-free =:inspect= and
  =:apply= invocations can show state immediately.
- *Terminal behavior:* Choose =:shared=, =:exclusive= or
  =:exclusive-without-arguments= to specify which calls need exclusive input.
  A modal picker that changes state under =:inspect= or =:apply= waits for
  idle. A picker under =:execute= can open during inference.
- *Fixed options:* Use =:static-options= instead of =:argument= for one
  positional choice. Supply strings, keywords or =(t nil)= for a boolean
  choice. Autolith uses these values in help and completion.

** Live definitions

Use =self.define= to add or replace a loaded Lisp definition. Qualify the
symbol or set =package= to choose the reader package. Use qualified symbols
with =self.set= when changing global bindings in other packages. Autolith
restores package locks after installation, discard or replay.

Use =self.eval= to evaluate in the active image. In a world, that is the server
image. Set =target= to =client= to evaluate in the controlling terminal or, if
there is no eligible terminal, the most recently attached eligible structured
client. The client must advertise Lisp evaluation. Client evaluations are not
journaled and do not survive the client process.

*Tracked source takes precedence.* On startup, Autolith skips a private
definition if the tracked definition changed, appeared or disappeared, or if
ownership moved to another library. A startup notice groups skips by reason.
The next =self.commit= omits skipped definitions. For older commits without
this metadata, tracked overrides replay only on the source revision used to
publish the lineage.

Reapply a skipped definition against the current source to keep it. Or run
=(fix-skipped-definitions)= to give the model the private, old tracked and
current tracked versions. By default it rebuilds overrides that are still
needed and publishes the result with =self.commit=. An optional comment takes
precedence over that policy. If a turn is active, the command waits for idle.

#+BEGIN_SRC lisp
(fix-skipped-definitions "Drop all of these. They were temporary development experiments.")
#+END_SRC

** Refinement

Use =(refine)= to inspect proposals. Record a local task assessment before
promotion:

#+BEGIN_SRC lisp
(refine :assess "PROPOSAL-ID" :revision 3 :verdict :passed
        :evidence "Evidence from a separate task")
#+END_SRC

Promote from session to project to global scope. Each step requires renewed
evaluation and checks for intervening owner changes. If an operation was
interrupted, use the recorded evidence to recover it explicitly. Replay does
not repeat the operation.

** Executable Skills

Use =skill.load= with the exact catalog name to load instructions for the
current turn. Use =resource.read= on =skill:NAME= if you need the full catalog
description.

1. Put a data-only =EXECUTABLE.sexp= beside =SKILL.md= or =SKILL.sexp=.
   Declare the Skill and ASDF system versions, entrypoint, contracts,
   capabilities and exact host tool names.

   #+BEGIN_SRC lisp
   (:skill-executable :format-version 1 :skill-version "1.0.0"
    :system "my-workflow" :system-version "1.0.0"
    :entrypoint ("MY-WORKFLOW" "RUN")
    :self-test ("MY-WORKFLOW" "SELF-TEST")
    :verify ("MY-WORKFLOW" "VERIFY")
    :capabilities ("workspace-read") :tools ("resource.read")
    :input (:type :object) :output (:type :object))
   #+END_SRC

2. Define the entrypoint with =input &key context=. Use =&key context= for
   self-test and verification functions. Use portable JSON values such as
   =(:object ("status" "ready"))= for input and output.
3. Install the ASDF system in the worker environment or pass an authorized
   =asd= pathname. Call =skill.invoke= with contract-valid =input=:

   #+BEGIN_SRC json
   {"name":"my-workflow","input":{},
    "asd":".autolith/skills/my-workflow/my-workflow.asd","async":true}
   #+END_SRC

Use =skill.verify= with =name= to run the self-test. Set =entrypoint= to
=verify= to run the verification function instead. Both tools require
explicit full-access code authorization and run in a fresh worker. A worker
can call only the declared host tools that the originating agent may use.
Autolith rechecks source, manifest and ASDF version before execution.

Use =async: true= for a managed job. Autolith validates the result against the
output contract and retains up to 1 MiB of data with the executable identity.

** Local text redaction

** Worker tool calls

(autolith:worker-tool-context)

Read =:success-p=, =:content=, =:code= and =:details= from the result. The
originating conversation, permissions and mission admission apply to every
callback. Use a different REPL for nested worker calls. Omit =host-tools= if
no callbacks are needed.

For example, pass these arguments to =lisp.eval= to return the content on
success and the error code on failure:

#+BEGIN_SRC json
{"host-tools":["resource.read"],
 "forms":["(let ((result (autolith:worker-tool-call \"resource.read\" \"{\\\"uri\\\":\\\"workspace:README.org\\\"}\"))) (if (getf result :success-p) (getf result :content) (getf result :code)))"]}
#+END_SRC

An interrupted callback is recorded as =unknown-outcome=. Inspect the effects
before repeating a call that can change state.

** Structural code edits

Load the optional system and configure =ast-grep= before creating the registry:

#+BEGIN_SRC lisp
(asdf:load-system "autolith/structural")
(setf autolith:*structural-program* "/path/to/ast-grep")
#+END_SRC

1. Call =structural.query= with a workspace URI and revision you have read.
2. Call =structural.rewrite= and inspect the preview.
3. Publish with =structural.apply=. Proposals are single-use, owned by the
   conversation and subject to the same revision checks as resource edits.

For an existing registry, call =structural-register-tools= with =:program=.
Ordinary executable and file authorization apply. To test the backend, set
=CLASTED_AST_GREP= to the backend path and run
=(asdf:test-system "autolith/structural/tests")=.

** Debug adapter sessions

Load =autolith/debug= before creating the registry. Configure an adapter in
user initialization or pass it directly to =debug.launch= or =debug.attach=:

#+BEGIN_SRC lisp
(asdf:load-system "autolith/debug")
(setf autolith:*debug-adapter-program* "/path/to/debug-adapter"
      autolith:*debug-adapter-arguments* nil)
#+END_SRC

For an existing registry, call =debug-register-tools= with =:program= and
literal =:arguments=. Adapter execution, launch, attach and evaluation require
exact full-access command approval. Authorize source and program paths as
usual.

Use the returned session ID in the conversation that created it:

- Set breakpoints with =debug.breakpoints= and drive execution with
  =debug.continue=, =debug.pause= and =debug.step=.
- Inspect state with =debug.threads=, =debug.stack=, =debug.scopes=,
  =debug.variables= and =debug.evaluate=. Read queued events with

** Child agents

Use =child.spawn= to start a child with a self-contained assignment and an
optional name and context. Children use the parent's model, medium reasoning
effort, and the configured child-safe tools. Codex Fast mode is not inherited.

Reuse a child by sending work to its channel. An agent can have up to 32
children. Read =channel:current= to see which are busy. Use =child.rename=
to rename one, =child.compact= to summarize an idle child's history, or
=child.remove= to delete an idle child and its descendants. When you open a
child's channel, its recorded tool grants apply.

Channel deletion validates the whole selection first. If storage cleanup
fails after deletion, use the =retry-cleanup= restart or let the next server
start or deletion retry the intent in =channel-removals/=. Deleted identities
cannot be reopened from leftover history.

** Completion-driven turns

Set =completion-policy= on asynchronous tools or =child.spawn=. The same
policy applies if a synchronous call outlasts the blocking grace period.
Batch items inherit the outer policy unless they specify their own.

- =continue= is the default. In a primary terminal or ACP session, idle
  completions in a one-second window share one automatic turn. If a turn is
  busy, results arrive at the next safe request boundary.
- With =notify=, results arrive on the next ordinary turn. Interfaces without
  an input controller also deliver results on ordinary turns.

Continue independent work while jobs run. Yield the turn if all you need is
the results. An empty reply shows a yield notice that counts the unfinished
jobs eligible to wake the conversation. Use =job.get= to inspect a result or
=job.wait= if you need to wait explicitly.

A goal or mission waits for eligible job results before resuming automatic
continuations. Only the conversation that owns the work gets a wakeup.
Delivery receipts survive restart and compaction, so a notification can be
restored without repeating the job. Cancellation, paused or terminal
missions, and spent budgets can prevent automatic turns.

** Task inspection and continuity

Use =(tell "CHILD" "text")= to steer a running child at its next safe
boundary. Use =job.continuity= with =action= set to =list= or =get= to see
which retained jobs are live, complete, recoverable or need a decision.
Lists default to 20 records (maximum 100). Pass =offset= to page and read
=:total=, =:next-offset= and =:more-p= from the result.

To recover interrupted work:

1. Inspect the retained job and its effects. Use a visible job ID or durable
   execution ID in =id=.
2. To permit a restart, the primary owner calls =allow-restart= with a
   =safety= rationale about repeating external effects and =authorize: true=.
   For a saved worker, use =checkpoint= with a compatible =image=, target
   =repl= and =authorize: true=.
3. Use =revive= or =abandon= with the ID and =authorize: true=. Revival can
   reattach live work, start the saved worker or dispatch a new child from a
   retained safe shared-workspace task specification.

Autolith records the decision before dispatch and links the executions. If
revival fails or is interrupted, inspect the uncertain outcome before trying
again. Resuming a conversation shows the inventory without replaying work.

** Isolated modifying tasks

Pass an =isolation= object to =child.spawn= to give the child a detached Git
checkout. Omit it for a shared workspace. Use these fields:

- =baseline= resolves to a commit. The default is =HEAD=.
- =dirtyPolicy= defaults to =reject=. Use =ignore= to start from the committed
  baseline and exclude staged, unstaged and untracked source changes.
- =artifactKind= defaults to =patch=. A patch includes committed and
  uncommitted tracked changes. Use =commit-range= for a clean checkout whose
  history descends from the baseline.

*Stage new files* before yielding. The terminal result identifies the artifact
for integration, including on abort. If extraction fails, Autolith retains
the checkout and reports =:worktree-error=.

Use =child.worktree= with an explicit =action=:

- =inspect= reports provenance, touched paths and the artifact path. Use
  =extract= to retry extraction after repairing a checkout. Pass the terminal
  job or durable execution ID as =id=.
- =check= checks patch applicability. Use =apply= to patch the clean target
  or =commits= to cherry-pick the range. Pass =id= and an explicit =target=.
- =conflicts= shows unmerged paths. Use =abort= to abort an interrupted
  cherry-pick. Pass the target repository.
- =cleanup= removes the owned checkout. Pass =discardDirty: true= to discard
  local changes. The secured artifact is separate from the checkout.
- =discover= lists owned worktrees. Pass =source= to recover registration
  from Git markers. Use =cleanup-orphan= with the discovered worktree =id=
  and =source= to clean up after failed task publication.

The sandbox can write the isolated checkout and its Git administrative
directories. Integration requires authorization for the target. Worktree
isolation prevents accidental overlap. It does not confine hostile code.

The default pool admits eight concurrent children. Set
=AUTOLITH_TASK_MAX_CONCURRENCY= to raise this up to 32. Set
=AUTOLITH_TASK_MAX_DEPTH= to change the default depth of three below a
primary agent. Child jobs have a one-hour wall-clock deadline by default.
Set =AUTOLITH_TASK_MAX_RUNTIME_MS= to change it in milliseconds or use zero
to disable it.

** Reusable shell sessions

Pass =session= to =shell.run= to reuse a POSIX shell. Commands in one shell
run serially and share variables, functions and the current directory. Pass
=directory= to change the directory first. Autolith authorizes each command
in its observed directory and captures separate logs for each invocation.
Use =description= to label the live row. Shell commands have no execution deadline.

- Use =shell.sessions= to inspect live and dead shells.
- Use =shell.close= to stop and forget a shell.
- Use =shell.reset= to replace a shell after exit or cancellation,
  or after permissions, workspace or writable scopes change.

The runtime stops its shells and descendants on shutdown. Reset does not
replay commands. Keep temporary storage outside writable workspace roots for
sandboxed sessions. On Windows, or for an independent POSIX command, omit
=session=. Use native PowerShell on Windows.

On Windows, add existing read-only tool directories with
=*win32-sandbox-read-roots*=. Sandboxed commands run serially while the
helper applies temporary access rules. Use local directories without
reparse points or hard-linked files. Unsupported scopes or a missing
helper cause the command to fail.

** Retained command output

=shell.run= returns the exit status and capture details with a short preview.
Pass =separate-output: true= to capture stdout and stderr separately. Read
the =shell-log:= references from the result or from job inspection after a
restart or compaction. You do not need to rerun the command.

Use =resource.read= with zero-based =byte-offset= and =byte-count= (default
and maximum 4096 bytes). For a literal search, use =query= and optionally
=max-results=. Continue at the returned offset. A search scans up to 1 MiB
per page. The default is 20 excerpts and the maximum is 50. Text display
replaces invalid UTF-8. The retained capture preserves the original bytes.

Share the exact reference with another agent to give it access to range reads
and searches, including across tasks or sessions.

The defaults are 64 MiB per stream and 1 GiB overall. If a stream exceeds
its limit, the result marks the capture incomplete. Eligible captures can be
pruned after seven days or if the overall limit is reached. Live captures,
pending results and captures that support active structured facts receive
pruning protection.

For a new command, capacity is normally reserved without reading retained logs.
Age-based retention and receipt backfill run in bounded background batches.
A new process or a missing or interrupted accounting checkpoint requires a
validated scan before new storage can be reserved.

Adjust =*shell-log-capture-byte-limit*=, =*shell-log-retention-byte-limit*=
and =*shell-log-retention-age*= in trusted configuration. Session export
collects task metadata independently of local log storage.

* Goals and verified missions

Use a *goal* for work that can continue between messages without a turn, token,
or wall-clock budget. A goal runs as a mission and verifies when the assistant
includes =[GOAL-COMPLETE]= in its final message and no mission work is outstanding.

- Set a goal with =(goal "OBJECTIVE")=. A string such as ="pause"= is an objective,
  not an action.
- Inspect it with =(goal)= or =(goal :status)=. Change the objective with
  =(goal :update "NEW-OBJECTIVE")=.
- Pause, resume, or clear it with =(goal :pause)=, =(goal :resume)=, or
  =(goal :clear)=. To resume a standalone goal from an older channel, run
  =(goal :resume)= explicitly.

To set acceptance criteria, checks, or budgets before starting work, set up
and run a mission:

1. Install the objective, limits, and acceptance criteria with
   =(mission :start specification)=. This example requires both a passing build
   and your review:

   #+BEGIN_SRC lisp
   (mission :start
    '(:objective "Deliver the accepted build"
      :turn-limit 40 :token-limit 100000 :wall-seconds 3600
      :criteria ((:id "build" :description "The build passes" :gates ("build"))
                 (:id "review" :description "The user accepts the result"))
      :gates ((:id "build" :kind :command :command "make check"
               :inputs ("Makefile" "src/main.lisp") :deterministic-p t
               :attempt-limit 3 :timeout-seconds 300))))
   #+END_SRC

2. Run =(mission :run)= and inspect the saved state with =(mission :status)=.
3. Give explicit evidence for each criterion without a gate. If the mission is
   blocked on your review, accept the result and resume:

   #+BEGIN_SRC lisp
   (mission :accept "review" "I inspected the artifact and accept the result")
   (mission :resume)
   #+END_SRC

4. Request verification with =(mission :verify)=. The model can also request it
   with its completion marker. A mission is verified only if every gate passes
   and every criterion is satisfied.

Give each criterion a unique =:id= and a =:description=. Use =:gates= to list the
checks that count as evidence for that criterion. The model cannot weaken the
criteria or accept results on your behalf. Only the primary agent can use the
=mission.status=, =mission.verify=, =mission.stop=, and =mission.invalidate= tools.

*Mission budgets* cover parallel work as well as the primary agent:

- *Turns.* Each provider call uses a turn, including calls from children,
  compaction, recursive inference, and independent review. Admissions and
  settlements are serialized within a mission. Provider calls can run in
  parallel.
- *Tokens.* Each admitted call reserves tokens from the unspent and unreserved
  budget. The default allocation divides them among the remaining turns. An
  explicit provider output cap replaces that allocation. On settlement,
  Autolith releases the reservation and charges reported input and output usage.
  Provider normalization excludes known prompt-cache reads. Measured usage can
  exhaust the budget.
- *Wall time.* The deadline includes gates, tools, pauses, and time away.

If a child call reports no usage, Autolith charges the full finite reservation
once if it can identify the exact child and reservation. It records the
failure and the unknown usage. The charge is already included in =:tokens-used=.
Use =:reservation-charged-tokens= for the total and
=:reservation-charges-by-child= for the breakdown. The child result lists
=:unknown-usage=, =:reservation-charged-tokens=, and
=:reservation-charge-requests=. The =:usage= field contains only measured usage.

A reservation charge is an accounting rule, not a provider billing or output
limit. Input and repeated generations can cost more. At the current library
pin, Codex does not enforce an output ceiling on the wire. A successful retry
charges the final reported usage without reconciling unreported attempts.

The default =:block= policy blocks new inference if missing usage cannot be
settled, including missing primary usage or uncertain child ownership. Already
reserved requests and continuations that spend no tokens can finish. Restoring
the session cannot recover per-request bounds from aggregate reservations or
reclassify unresolved usage.

To proceed despite missing usage, select =:unknown-usage-policy :record= when you
start the mission:

#+BEGIN_SRC lisp
(mission :start
 '(:objective "Run the periodic checks"
   :turn-limit 10000 :token-limit 10000000 :wall-seconds 86400
   :unknown-usage-policy :record
   :criteria ((:id "checks" :description "The user accepts the checks"))))
#+END_SRC

Under =:record=, Autolith records failed or interrupted calls whose usage cannot
be settled and can continue without that measurement. It still charges exact
child reservations if possible. Turn and wall-clock limits apply, and independent
reviewers still need reported usage. To change the policy for existing work,
start a new mission with the criteria and budgets and add the policy key.
Large integer limits are finite.

- Pause with =(mission :pause)= and resume with =(mission :resume)=. These
  commands do not reset the budget.
- Cancel with =(mission :cancel "REASON")=.
- Inspect a blocked mission with =(mission :status)=. Resolve the blocker
  before resuming. The terminal states are =verified=, =exhausted=,
  =cancelled=, and =failed=.

Autolith saves gate attempts, fingerprints, and evidence with the conversation
so you can inspect them after a restore or compaction.

Gates run in order and stop at the first failure:

- *Command gates* use the normal shell authorization and sandbox boundary.
- *Artifact gates* require =:path=. Set =:sha256= to check an expected hash.
- *Lisp gates* require a =:predicate= string. The assertion runs in the existing
  isolated Lisp worker.

Every gate supports =:timeout-seconds= and a separate =:attempt-limit=. The
defaults are 60 seconds and three executions. Each gate keeps bounded evidence.

For deterministic gates, declare all relevant file paths in =:inputs= and set
=:deterministic-p t=. File contents and missing-file states form the fingerprint;
directory paths are rejected. Unchanged passing gates supply current proof, and
unchanged failed gates are withheld while the model works on their relevant
inputs. For remote state, omit deterministic policy or invalidate a particular
gate explicitly:

#+BEGIN_SRC lisp
(mission :invalidate "build" "The remote build configuration changed")
#+END_SRC

Invalidation permits another execution without replenishing its attempt budget.
Before acceptance, every gate fingerprint is checked again under the workspace
mutation lock. Changes from a later gate invalidate earlier passing evidence.
Collect terminal results and outstanding inference usage before verifying.

** Independent review checkpoints

Attach a reviewer to an active mission with =mission-review.configure=, or evaluate:

#+BEGIN_SRC lisp
(application-mission-review-configure
 *active-application*
 '(:id "release-review" :phase :final-acceptance
   :inputs ("src/main.lisp" "tests/main-tests.lisp")
   :context "Review the changed behavior and test coverage. Report concrete findings."
   :turn-limit 4 :token-limit 16000 :run-limit 3))
#+END_SRC

Declare all relevant files. The reviewer receives an independent snapshot and
background and returns findings in the required form. The reviewer has no tools
or spawning permission. Reviewer calls and tokens count against both the
cumulative reviewer allowances and the mission allowances, including reviews of
changed snapshots. =:run-limit= bounds the number of distinct snapshots reviewed.

Use =mission-review.trigger= with =id= to review a checkpoint and
=mission-review.inspect= to read its durable findings, decisions and usage.
Unchanged snapshots reuse completed, failed or interrupted runs. Resolve or reject
each finding through =mission-review.decide= with =id=, =finding=, =decision=
(=resolve= or =reject=) and an evidence-bearing =reason=. Only the primary agent
or local user may configure, trigger and adjudicate reviews.

Final verification runs configured =final-acceptance= checkpoints. Pending
findings and failed or interrupted reviews block acceptance. For
=before-integration= and =after-edit-set= checkpoints, trigger the named review
explicitly at the chosen boundary. Reviewer findings are advisory; mission gates
and user acceptance supply harness evidence.

** Scheduled mission continuations

Attach explicit wakeups to the current mission with =mission-schedule.add=.
Supply an immutable =id=, continuation =content=, and one time policy. =at= is an
absolute Common Lisp universal time. =interval= is a positive number of seconds.
=event= names an external event instead. For example:

#+BEGIN_SRC lisp
(application-mission-schedule-add
 *active-application* :id "build-followup"
 :content "Check the pending build and continue the mission."
 :at (+ (get-universal-time) 300) :missed-policy :latest)
#+END_SRC

For recurring wakeups, choose =missed-policy= =latest= (the default), =all=, or
=skip=. These select the newest missed occurrence, every missed occurrence, or
only an occurrence due at exactly the current time. Use =mission-schedule.event=
with an event name and stable external event =id=; repeated delivery of that ID
is deduplicated. The local daemon listener hosts time wakeups. Due work is
persisted in the ordinary primary command queue as =(mission-wakeup ticket)=,
where =ticket= is structured data. The command runs as a mission continuation
under the existing turn, token, and wall-clock budgets.

While a hosted time wakeup of the current mission version is due later or
already admitted, automatic goal continuations stop and the mission stays
active. The model is not prompted again between occurrences. Within an
occurrence, work continues through the turn's own tool calls and through job
completions. Event schedules, cancelled schedules, and a finished one-shot
wakeup leave ordinary continuations in place. A user message or =(goal :resume)=
still runs its own turn.

Only the primary agent may use the =mission-schedule= tools. Each wakeup keeps
its exact mission identity and version. Both are checked at admission and
execution.

While the mission is paused or blocked, the missed policy skips due occurrences
without running them. The interval advances. After a resume, the next due
occurrence arrives without recreating the schedule. Skipped occurrences are not
replayed, including one-shot wakeups and deduplicated events. With the default
=:block= policy, unknown usage prevents mission resume. =:record= does not prevent
an independent pause or blocker from resuming.

The schedule is cancelled when the mission is replaced, its version changes,
or it reaches a terminal state (verified, exhausted, cancelled, failed or legacy
complete). Skips and automatic cancellations produce persisted user notices. Use
=mission-schedule.inspect= to read schedules, occurrence IDs, claim tokens and
outcomes: skipped occurrences have =state= =cancelled= with
=result= =(:skipped <mission-status>)=; obsolete mission work has
=result= =:stale-mission= and a cancelled schedule. Use =mission-schedule.cancel=
with the schedule =id= to cancel future and pending work.

Interrupted admissions and executions restore as uncertain outcomes. Inspect the
external effects before calling =mission-schedule.resolve= with the readable
=occurrence= ID, current =token= and =action= =completed=, =failed= or =retry=.
Retry is an explicit decision and is refused while the occurrence is executing.
Cancellation retains claim and duplicate history.

* Editor sessions over ACP

To open an ACP editor session:

1. Authenticate the selected provider with =autolith auth=.
2. Configure your ACP-compatible editor to launch:

   #+BEGIN_SRC sh
   autolith acp
   #+END_SRC

3. Open a session in the editor. ACP uses UTF-8 JSON-RPC on stdin and stdout.
   Diagnostics go to stderr.

Autolith starts the world server if needed. A new session opens a channel in the
absolute working directory supplied by the editor. The session ID is the
conversation ID. Load that ID to replay messages, visible reasoning, tool calls,
and results, then follow the channel. You can view the same channel in a
terminal. ACP accepts text prompts, resource links, and embedded text resources.
File and process operations use the native Autolith tools.

The world server does not run in pristine mode. For a pristine rescue session,
use =autolith resume --pristine= in a terminal.

- *Approvals.* In =ask= mode, the editor receives the channel's choices. The
  first answer from the editor or terminal counts. Select =auto=, =sandboxed=,
  or =full-access= in the editor, or use =--permissions auto|sandbox|full= at
  launch. Changing the mode in the editor changes it for the channel.
- *MCP.* You can supply stdio and HTTP MCP servers when the server starts a
  channel for the session. An existing channel refuses new servers and returns
  the reason. Literal environment values and headers are kept temporarily and
  redacted from server output.
- *Closing.* Cancel a prompt to stop the current turn. A prompt returns after
  the turn ends. Closing the session stops following the channel. Autolith
  closes a channel it started for that session if nothing else follows it.
  =Ctrl-C= leaves all channels and exits the ACP process with status 130.

** Remote clients

- Use =autolith acp --http= for Streamable HTTP (HTTP/1.1 or cleartext HTTP/2)
  and WebSocket at =/acp=.
- Use =autolith acp --websocket= for WebSocket alone.

Both listen on =127.0.0.1:8737= by default. Supply a port or a host and port to
change the listener:

#+BEGIN_SRC sh
autolith acp --websocket 9000
autolith acp --http 0.0.0.0:8737 --token "$ACP_TOKEN"
autolith acp --http [::1]:8737
#+END_SRC

Autolith prints the endpoint URL on stderr and serves until Ctrl-C. Each client
gets its own sessions, each a channel of the world server.

*For remote access*, put a TLS reverse proxy in front of the listener and require
a token. ACP does not encrypt the traffic itself. A non-loopback bind can make
the agent reachable from other machines. Other local users can read a token
passed on the command line.

With =--token=, send =Authorization: Bearer TOKEN= or add =?token=TOKEN= to
the URL. Autolith rejects requests that carry an =Origin= header.

** Typed client extensions

Request =_autolith/capabilities= to discover installed methods and schema version.
Include =sessionId= in every other extension request. Responses contain =outcome=
(=ok=, =condition=, =busy=, =unsupported=, or =cancelled=), with =value= on success
and a bounded =report= on failure. Unknown measurements are JSON null.

| Method suffix | Value or action |
|---------------+-----------------|
| =state= | Session, turn, model, permission, usage, plan and health snapshot |
| =settings=, =models=, =operations= | Typed catalog =items= |
| =set-setting= | Set =name= to =value=; return the updated setting row |
| =invoke= | Invoke =operation= with JSON =arguments=; return presented =text= |
| =steer=, =queue= | Durably admit primary =text=; return =accepted= and =delivery= |
| =conversations= | Page durable conversations using =limit= and =cursor=; optionally filter =cwd= |
| =jobs=, =job= | Page owned jobs or inspect one =jobId= |
| =job-transcript= | Read =jobId= with =offset=, =limit= and =output= (=text= or =structured=) |
| =job-send=, =job-cancel= | Send =text= to or cancel an owned =jobId= |
| =resource= | Read bounded =workspace:= lines or =shell-log:= bytes from =uri= |

Prefix these suffixes with =_autolith/=. Catalog operations expose admission and
availability; tools use their native decoders and ACP approval callbacks.
Terminal-only operations return an explicit unsupported outcome. Workspace resource
windows use =startLine= and =lineCount= and include the observed revision. Shell-log
windows use =byteOffset= and =byteCount= with the exact retained reference.

For a command, send =arguments= as a JSON array in Lisp argument order. For
example, =(settings :turn-timestamps-p t)= takes
=[{"keyword":"turn-timestamps-p"}, true]=. A keyword is an object with exactly one
=keyword= member whose value is a nonempty string. For a tool, send =arguments=
as an object keyed by parameter name. Operations with =terminalWithoutArguments=
require an argument to avoid a terminal picker. During an active turn,
boundary-applied commands return =delivery: "scheduled"= and present their
results as ACP updates.

=steer= delivers text at the next safe boundary, including submissions made while
an approval is pending. Late steering is promoted ahead of ordinary queued
follow-ups. =queue= appends a follow-up for the next available primary turn.
Both accept up to 262144 characters and return =delivery: "steering"= or ="queued"=.
Display accepted input separately until its durable =user_message_chunk= arrives.
Cancellation pauses pending input; a new submission resumes it. Accepted input
survives session close and reload. ACP has no per-item withdrawal operation.

For structured child transcripts, =value.updates= contains ordinary ACP
SessionUpdate bodies, with messages, reasoning, tool calls and result content.
Offsets count updates from zero; the default limit is 100 and the maximum is 200.
The typed response envelope is bounded to 262144 UTF-8 bytes. A single update over
that bound returns a condition instead of advancing the cursor. =nextOffset= is
JSON null when =complete= is true, meaning the current snapshot is exhausted.
For a running child, poll again from =total= to read later updates. Text output
uses character offsets and retains its existing numeric end cursor.

Treat =_autolith/event= state and catalog notifications as invalidation hints.
Refetch the affected snapshot after a sequence gap. Events with kind =turn= are
ordered lifecycle boundaries: =data= contains =state= (=running= or =idle=), an
integer =epoch=, =source= (=prompt=, =queue=, =completion=, or =invoke=), and a terminal
=outcome= (=end-turn=, =cancelled=, or =condition=; null while running). Match the
epoch when handling approvals, cancellation and transcript boundaries.

Automatic job continuations stream through ordinary ACP updates. Cancellation or
an inference failure pauses continuation; submit an explicit prompt to resume.

* Emacs and sly

Use =emacs/autolith.el= from the source tree to edit code, work in a sly REPL,
and talk to Autolith in one Emacs frame. The REPL connects to the same Lisp
image as Autolith. The REPL spans the bottom quarter of the frame. Above it,
code is on the left and the agent-shell conversation is in the right third.

1. Install sly and agent-shell.
2. Load the integration file:

   #+BEGIN_SRC emacs-lisp
   (load "/path/to/autolith/emacs/autolith.el")
   #+END_SRC

3. In the buffer you want to edit, run =M-x autolith-ide=. The command starts
   the Emacs server if needed, launches the agent, and connects sly.

Optional Sly contribs need their Lisp dependencies in Autolith's image. For
=sly-stepper=, install =agnostic-lizard= in a persistent ASDF source registry
visible to the Autolith process before Slynk starts.

=autolith-ide= starts the Emacs server if needed and launches =autolith acp=
through agent-shell with three environment variables:

- =AUTOLITH_SLYNK_DIRECTORY= is your sly's own =slynk/= directory, so the server
  speaks exactly your client's protocol. Autolith loads that =slynk.asd= by path
  and compiles it into the ASDF cache on first use.
- =AUTOLITH_SLYNK_PORT_FILE= receives the loopback port once Slynk listens, or
  =error: REASON= when it cannot start. =autolith-ide= waits for it, up to
  =autolith-slynk-timeout= seconds, and connects sly.
- =AUTOLITH_EMACS_SERVER= is this Emacs's server socket and enables the
  =emacs:= resources and =emacs.*= tools.

=M-x autolith-agent-shell= starts only the conversation, with Emacs access and
without Slynk. The same variables, or the =:slynk-directory=,
=:slynk-port-file= and =:emacs-server-socket= settings, work outside Emacs. In
the terminal, =(slynk)= starts Slynk and shows the port for =M-x sly-connect=,
and =(slynk :stop)= closes it.

The agent reaches your definitions with =lisp.describe=, =lisp.source= and
=lisp.apropos= using target =self=, or with =self.eval=. While Slynk serves, a
context note tells it so. Your Emacs appears to the agent only while the
configured server socket exists:

- =emacs:current=, read with =resource.read=, lists authorized visible windows
  with point, the active region and open file buffers, each by its
  =emacs:buffer/NAME= URI. Outside-root files and non-file buffers require
  full-access approval; denied buffers are omitted from this snapshot.
- =emacs:buffer/NAME= is a live buffer's text, unsaved edits included, with the
  buffer name percent-encoded. =resource.edit= applies line operations to the
  buffer itself: the change stays unsaved and undoable, and is refused as stale
  if you have edited the buffer since the agent read it. A buffer visiting a file
  outside the workspace and source roots asks the same permission as that path.
- =emacs.visit= shows a file position in a file window of the selected frame.
- =emacs.eval= evaluates Emacs Lisp. It asks command authorization for
  =emacs.eval -- FORM= and runs only with full access.

Slynk listens on =127.0.0.1= only. Like ordinary sly, it has no authentication
beyond the optional =~/.sly-secret=. Anyone who can reach loopback on this machine
can evaluate in the image. Your code shares the agent's heap: a fatal error or
=(sb-ext:exit)= ends the session, which recovers like any crash.

Slynk's debugger and output hooks stay off for Autolith's own threads, so your
REPL sees only your evaluations. A checkpoint stops Slynk and closes sly
connections, then restarts Slynk on the same port. Reconnect with
=M-x autolith-ide-reconnect=. A checkpoint waits for in-flight sly evaluations
and fails if they exceed the shutdown timeout.

* Non-interactive jobs

Use =run-job= to run one assignment from a script or CI with the configured
providers and MCP servers. Read the result from =--output=.
Choose exactly one input form: =--input FILE= or =--prompt TEXT=.

#+BEGIN_SRC sh
autolith --permissions auto run-job \
  --input /path/to/job.sexp \
  --output /path/to/result.sexp
#+END_SRC

The input file contains one data-only form:

#+BEGIN_SRC lisp
(:autolith-job
 :version 1
 :id "job-identifier"
 :prompt "Perform the assigned work."
 :input (:caller-owned "opaque data"))
#+END_SRC

For an inline assignment, pass =--prompt TEXT= or use =--prompt -= to read
standard input. Autolith generates an ID unless you supply =--id=.

#+BEGIN_SRC sh
autolith --permissions auto run-job \
  --prompt "Review the current change and report the result." \
  --id review-change \
  --output /path/to/result.sexp
#+END_SRC

Autolith atomically publishes an =(:autolith-job-result :version 1 ...)=
artifact. Read =:result= for the response on =:succeeded=. Other terminal
statuses are =:failed=, =:cancelled= and =:timed-out=. The result includes
failure categories and any available trace and usage fields. Prompt read
errors and oversized prompts produce a failure artifact too.

*Headless jobs cannot ask for approval.* =auto= denies decisions that require
a prompt. =sandbox= permits only sandboxed shell commands. =full= permits
full command execution and external tools that otherwise require a prompt.

** Live S-expression events

Add =--events sexp= to observe progress on stdout. Send diagnostics to a
separate stream, and use the artifact for the authoritative result:

#+BEGIN_SRC sh
autolith --permissions auto run-job \
  --input /path/to/job.sexp --output /path/to/result.sexp \
  --events sexp >events.sexp 2>diagnostics.log
#+END_SRC

Read consecutive top-level forms. /Strings can contain newlines./

#+BEGIN_SRC lisp
(:autolith-event :version 1
 :run-id "a-generated-run-uuid" :seq 1 :time "2026-10-08T09:00:00Z"
 :kind :run-started :data nil)
#+END_SRC

- Sequence numbers increase within one run. A new run starts at one with a
  new run ID. There is no replay or reconnect cursor.
- Event kinds are =:run-started=, =:job-started=, =:tool-started=, =:progress=,
  =:tool-finished=, =:job-finished=, =:usage=, =:warning=, =:progress-omitted=
  and =:run-finished=. Ignore unknown kinds. Events report registered tool
  names and bounded metadata, without prompts, tool payloads or output.
- Root =:job-finished= and final =:run-finished= follow result publication.
  Published job events carry =:result-uri=. The final event reports
  =:status= and =:published-p=. It includes =:output-path= on publication.
  A write failure reports =:category :result-publication-failed= and exits
  nonzero.
- A slow reader can miss events. =:progress-omitted= counts omitted progress,
  and a =:warning= with =:code :queue-full= reports lifecycle overflow.
  Execution and result publication continue even if the stream disconnects.

From Lisp, pass =:events :sexp= and =:event-output STREAM= to =run-job-run=.
Read records with =run-job-event-read-stream=, which returns =nil= at EOF.
The reader accepts bounded data forms of up to 16 KiB of UTF-8 per record.
Use UTF-8 for character streams. Binary streams receive UTF-8 octets.

* Generations and recovery

Use =(checkpoint)= to save the live image as a retained generation. The
source checkout must be clean and pass =./script/check= on POSIX or
=script\check.ps1= on Windows. To allow local changes, use
=(checkpoint :allow-dirty t)=. Autolith marks the generation dirty because
the recorded revision does not describe all of the source.

- *POSIX:* You can keep using the active session while the image is saved.
- *Windows:* Autolith saves the live heap and restarts through the stable
  launcher. It resumes the conversation after the saved image passes its probe.
- *World server:* A checkpoint waits for running work and holds new turns.
  Use =(checkpoint-cancel)= to cancel a waiting checkpoint and release turns.

Run =(generations)= to list retained images. Run =(rollback "GENERATION-ID")=
to select a compatible image and exit through recovery. In the terminal,
=(rollback)= opens the picker. From the command line:

#+BEGIN_SRC sh
autolith --recovery --list
autolith --recovery --generation GENERATION-ID
#+END_SRC

Pristine and retained-image sessions use separate world endpoints from the
ordinary active image. A retained core must support world startup.

*Automatic recovery* uses a private clean checkout of the current committed
source with =--pristine=. It uses a separate recovery core if valid and can
fall back to source. Use explicit generation selection to return to an older
compatible core.

After a fatal active failure, Autolith restores the terminal and writes a
private crash capsule. Recovery resumes the conversation without duplicating
scrollback. With a valid capsule, it queues one read-only diagnosis before
ordinary input. The turn can inspect bounded crash context, workspace and
tracked source, indexed source and active state. It cannot use shell, MCP,
hosted-provider or image tools. It asks before applying a repair.

To start a rescue session yourself, use:

#+BEGIN_SRC sh
autolith open --pristine --permissions full
#+END_SRC

A manual pristine session skips private image replay, mutation journal
reconstruction and executable user initialization. Autolith enables
=--immutable= and leaves mutation and conversation data on disk. Crash
diagnosis requires a valid crash capsule from a supervised recovery.

Saved cores require the recorded SBCL version, OS build and architecture.
To reconstruct without a core:

1. Check out the revision in the generation manifest.
2. Run =./script/bootstrap=.
3. Load Autolith in Lisp, then load the ordered =reconstruct.lisp= from the
   manifest in package =AUTOLITH=:

   #+BEGIN_SRC lisp
   (asdf:load-asd (truename "autolith.asd"))
   (asdf:load-system :autolith)
   (load #P"/path/from/generation/manifest/reconstruct.lisp")
   #+END_SRC
