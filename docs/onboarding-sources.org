* Welcome to Autolith
:PROPERTIES:
:ID: welcome
:VERSION: 3
:END:
[[https://autolith.rocks][@@brand:Autolith@@]] is an agent you can inspect and change while it runs.

I'm [[https://twitter.com/LukasHozda][*Lukáš Hozda*]]. I made this tour to help you get started.

We will explore what you can do with Autolith.

@@dim:Press Space to continue, or Esc to skip. Start the onboarding again anytime with (onboard).@@

* Adapt the system while it runs
:PROPERTIES:
:ID: live-image
:VERSION: 4
:END:
Autolith runs inside a *Common Lisp image*. You and the agent can inspect, define, test, and revise behavior without a rebuild.

@@brand:inspect -> redefine -> test -> private commit@@

Autolith records persistent self-modifications in a journal and replays them from private image commits.

Run =autolith --immutable= to prevent self-modification during a session.

* Connect your first provider
:PROPERTIES:
:ID: first-provider
:VERSION: 2
:EXERCISE: authentication
:END:
Choose a provider and sign in before your first conversation.

For a *ChatGPT subscription*, choose *chatgpt*. Use *browser* for OAuth with a local callback, or *device-code* to enter the displayed code in your browser.

For an *OpenAI API key*, choose *openai-api* and paste your key into the hidden prompt. Autolith saves it in its private credential store and discovers your available models.

Follow the login or API-key prompts for other providers.

Don't want to sign in yet? Type =continue=.

Press *Escape* in the method picker to return to providers, or in the provider picker to return here.

@@brand:PRACTICE  Type (auth) to sign in, or continue to skip.@@

* Start with a conversation
:PROPERTIES:
:ID: ordinary-prompt
:VERSION: 3
:EXERCISE: continue
:END:
Ask a question, describe a task, or paste some code.

=Explain this project=
=Fix the failing tests and verify the change=

Use familiar terminal editing shortcuts:
*Ctrl-A / Ctrl-E*  go to the beginning / end
*Ctrl-W / Ctrl-U*  erase a word / erase to the beginning
*Up / Down*        recall input history

@@brand:PRACTICE  Type  continue  and press Enter.@@

* Your prompt is also a Lisp REPL
:PROPERTIES:
:ID: lisp-listener
:VERSION: 4
:EXERCISE: help
:END:
The prompt accepts ordinary text, but you can also start with a parenthesis to evaluate Common Lisp forms.

=(help)=      basic help
=(settings)=  settings

When you start a Lisp form, you'll see @@lisp-prompt:*@@ at the start of the prompt. Go on, try it.

*Use Common Lisp syntax for forms and arguments.*

@@brand:PRACTICE  Type  (help)  to get some pointers, then continue.@@

* Run Lisp in the background
:PROPERTIES:
:ID: asynchronous-lisp
:VERSION: 3
:EXERCISE: async
:END:
Type *? followed by a space* before a Lisp form to run it in the background.

=? (+ 1 2)=

Press Enter to run it.

This is also useful if a Lisp form you want to evaluate does not start with a parenthesis:

=? *my-var*=

@@brand:(form)    local evaluation
? (form)  background local evaluation@@

*PRACTICE  Try ? (+ 1 2).*

* Compose requests with Lisp
:PROPERTIES:
:ID: prompt-function
:VERSION: 4
:END:
Use =(prompt ...)= to send a prompt programmatically.

E.g. you can compute the text or read it from a file.

This is actually what your plain text evaluates to when you type it into the prompt.

=(prompt "Review this change")=

Use =:to= to send a request to a named child that is already running:
=(prompt :to 'test-review
        "Run focused tests and report failures.")=

Omit =:to= to address the primary Autolith.

* Steering and follow-ups
:PROPERTIES:
:ID: steering
:VERSION: 3
:END:
@@brand:NOW   Enter  -> steer the active turn
NEXT  Tab    -> queue a follow-up@@

*Press Enter to steer the current work.* Autolith reads all pending steers together at the earliest opportunity.

*Press Tab to queue a follow-up.* Autolith handles follow-ups one at a time, in order, whenever it becomes idle.

=Focus on the parser first=
=After that, review the documentation=

* Park input for later
:PROPERTIES:
:ID: input-vault
:VERSION: 4
:END:
Store drafts and pending requests in the *input vault* to return to them later.

=(vault-store)=    park input
=(vault)=          view and edit
=(vault-restore)=  return input to the queue

You can use =(vault-contents)= to edit the stored data or to compute a series of follow-ups.

@@brand:draft -> vault -> restore@@

* Searching and other tools
:PROPERTIES:
:ID: indexed-search
:VERSION: 4
:END:
The agent uses *fff* indexed search to find files, identifiers, or path patterns:

=(search.files :query "parser")=           fuzzy file paths
=(search.content :query "parse-request")=  exact identifiers
=(search.glob :pattern "**/*.lisp")=         matching paths

*In the prompt: type @ and part of a path, then press Tab.* Choose a fuzzy match to insert its path.

You and the model can call these tools.
In fullscreen mode, you can click a tool call to paste it into your prompt, then repeat or modify the call.

* Detached sessions
:PROPERTIES:
:ID: detached-sessions
:VERSION: 5
:END:
Use =(detach)= to disconnect your terminal while Autolith keeps working.

*From another terminal:*
=autolith localgroup status=
=autolith localgroup attach [SESSION-ID]=
=autolith localgroup tell   [SESSION-ID] "message"=
=autolith localgroup pause  [SESSION-ID]=
=autolith localgroup detach [SESSION-ID]=
=autolith localgroup kill   [SESSION-ID]=

Use =attach --read-only= to watch a session. To watch and control the session (full re-attachment), use =attach --take-over=.

You can use =autolith lg= as a shorthand for =autolith localgroup=.
With one active session, you can omit =SESSION-ID=. Otherwise, use a uniquely identifying prefix.

* Give Autolith an objective
:PROPERTIES:
:ID: goals
:VERSION: 3
:END:
Use a *(goal)* for longer autonomous work.

=(goal "Make the project ready for release")=
=(goal :pause)=   pause autonomous work
=(goal :resume)=  resume it
=(goal :clear)=   remove the objective

For more elaborate acceptance criteria, verification gates, and budgets, use =(mission ...)=.

* Missions
:PROPERTIES:
:ID: missions
:VERSION: 1
:END:
Use a *mission* when you need explicit acceptance criteria and limits on turns, tokens, and time.

=(mission :start
 '(:objective "Prepare a release summary"
   :turn-limit 20 :token-limit 50000 :wall-seconds 1800
   :criteria ((:id "review" :description "I accept the summary"))))=

=(mission :run)=     begin work
=(mission :status)=  inspect progress, budgets, and evidence
=(mission :resume)=  continue after a pause or resolved blocker

To finish this example, inspect the result, then record your acceptance:
=(mission :accept "review" "I checked and accept the summary")=
=(mission :verify)=

For automated checks, link criteria to verification gates.

To finish a mission, pass all criteria and gates.
Use =(mission :cancel "Reason")= to stop instead.

Missions are very popular with our enterprise users that try to have predictable LLM execution
bounds.

* Keep evidence with what you remember
:PROPERTIES:
:ID: symbolic-evidence
:VERSION: 1
:END:
Autolith keeps *prose memories* and *structured facts* with their sources.
A fact can have several independent supports.

=(memories)=           browse memories and facts
=(memories "deploy")=  filter by topic
=(why "ID")=           inspect sources and dependencies

Autolith checks stale or invalid entries before relying on them. May it reduce the amount of hallucinations
your models have.

@@brand:read the evidence -> record it -> recheck when it changes@@

* Follow facts through rules
:PROPERTIES:
:ID: symbolic-rules
:VERSION: 1
:END:
An admitted *rule* derives facts locally. Move a meeting and its calculated departure time changes without a model request.

=(rules)=                   inspect versions and admission
=(admit-rule "departure")=  approve a proposed rule
=(what-changed)=            inspect changes and their causes

Use =(why "ID")= to inspect a conclusion's premises.

* Check plans and calls against facts
:PROPERTIES:
:ID: symbolic-actions
:VERSION: 1
:END:
*Plan steps* can require facts and use their values in step text.
Unsatisfied requirements appear as blocked.

*Mission fact gates* check accepted evidence.
*Action contracts* check requirements before a tool call, describing its predicted effects and observed results.

=(mission :status)=  inspect gates and evidence

* Reuse a learned sequence
:PROPERTIES:
:ID: symbolic-procedures
:VERSION: 1
:END:
Autolith can learn a *parameterized procedure* locally after repeating the same tool-call sequence in three successful turns.

=(procedures)=  inspect calls, admission, runs, and measured savings

Automatic reuse requires successful runs of the *exact admitted version* with measured savings in both model requests and tokens.

Use =(retire-procedure "NAME")= to stop using and learning that procedure.

* Diagnose before repairing
:PROPERTIES:
:ID: symbolic-diagnosis
:VERSION: 2
:END:
When several causes could explain a failure, Autolith can check known facts
and run *diagnostic probes* before choosing a repair.

Probes are on by default. Turn them off in =(settings)=.

=(diagnoses)=  inspect saved diagnoses and recent cases

* Large inputs via RLM (recursive inference)
:PROPERTIES:
:ID: recursive-inference
:VERSION: 3
:END:
Autolith can use *recursive language models (RLM)* to process very large inputs piecemeal.

@@brand:large input
      -> selected views
      -> focused analyses
      -> combined result@@

You can request it specifically if you like, but generally, Autolith knows when to use it.
